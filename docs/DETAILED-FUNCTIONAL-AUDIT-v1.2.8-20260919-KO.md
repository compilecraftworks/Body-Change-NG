# Body Change NG 1.2.8 상세 기능 재점검

검사일: 2026-09-19. 제품 기준: `3aab08a359a55e0180ebed7ca454ec03e712aba9`.

후속 상태: 아래는 수정 전 진단 기록입니다. 확인된 세 경로의 1.2.9 수정 및 정상 기대값 회귀 검사는 [1.2.9 검증 기록](RELEASE-VERIFICATION-v1.2.9-KO.md)에 정리했습니다.

## 결론

기존 자동 검사에서는 실패가 없었지만, **기능 사이의 호출 연결에서 수정이 필요한 3개 경로를 추가 확인했다.** 따라서 “전체 기능 문제 없음”으로 판정하지 않는다.

이번 작업은 진단이다. 제품 코드·DLL·배포 ZIP·MO2·GitHub는 변경하지 않았다. 게임 실행, 게임 메모리 접근, 세이브 조작도 하지 않았다. 이 보고서와 무시되는 `build/audits/detailed-functional/` 진단 파일만 추가했다.

확인 수준을 구분한다.

- **코드상 확인 및 오프라인 재현:** 아래 3개 항목. 제품 함수 본문을 수정 없이 추출하고, 엔진 경계만 가짜 구현으로 대체해 분기와 후속 처리를 실행했다. 반대 조건의 대조군도 함께 실행했다.
- **기존 회귀 검사 재통과:** 개별 정책·직렬화·입력·UI·할당 실패 경로. 아래 추가 결함이 없다는 의미는 아니다.
- **실게임 미검증:** 실제 얼굴/몸 경계, TNG 크기 변경 후 보라색, RaceMenu의 실제 co-save·비동기 VM·엔진/GPU 메모리. 이번 검사로 제보 증상의 단일 원인을 확정하지 않는다.

## 1. 미로드 NPC의 스킨 미리보기 취소가 실제 복원을 건너뜀 — P2

관련 위치:

- `src/BodyChangeNG/UI.cpp:1632` — `RollbackSingleCatalogPreview`
- `src/BodyChangeNG/SkinApplication.cpp:403` — `QueueClear`
- `src/BodyChangeNG/NativeSkinBackend.cpp:1381` — 미로드 `QueueApply`의 확정 의도 수락
- `src/BodyChangeNG/SkinApplication.cpp:675` — 언로드 시 지우는 상태의 범위

발생 조건과 흐름:

1. 원래 기본 스킨이던 NPC에게 사용자 스킨을 한 번 클릭해 미리본다. 바디 미리보기는 private Skin Armor/TXST에 실제로 반영된다.
2. 확정하지 않은 상태에서 NPC의 3D가 언로드된다.
3. 창을 닫거나 다른 액터로 전환하면 UI는 원래 스킨을 되돌리기 위해 `QueueClear(actor)`를 호출한다.
4. 이 함수는 미로드이고 삭제 준비 모드가 아니면 `queued`를 반환하지만, native 복원이나 지연 복원 기록을 만들지 않는다.
5. UI는 `g_pendingSkin`을 지운다. 일반 언로드 처리도 얼굴 요청·애드온·선택 캐시는 지우지만, 이미 변경된 native body graph는 되돌리지 않는다.

**영향:** 미리보기 취소 후에도 바디의 임시 스킨이 남을 수 있다. 해당 액터에 별도 확정 스킨 선택/규칙이 없으면, 재등장 시 원래 스킨으로 되돌릴 선택도 없다. 이는 미로드 액터의 *새로운 수동 선택을 저장하는 기능*과 *이미 반영된 미리보기를 취소하는 기능*을 같은 반환 경로로 처리한 문제다.

오프라인 검사에서는 미로드 일반 모드 `QueueClear`가 native backend를 0회 호출했고, 대조군인 삭제 준비 모드에서는 1회 호출했다. UI의 취소 호출과 임시 상태 삭제는 별도로 원문을 확인했다. 실제 NPC 이동/언로드 화면은 재현하지 않았다.

권장 수정: 확정 의도 수락과 미리보기 복원을 구분하고, 언로드되어도 수행 가능한 private form 복원 및 남은 얼굴 복원을 보존해야 한다. 강제 3D 로드나 원치 않는 수동 Default 선택 기록으로 우회하지 않는 것이 적절하다.

## 2. 확정 이력이 없는 NPC의 오버레이 미리보기 정리가 언로드 때 누락됨 — P2

관련 위치:

- `src/BodyChangeNG/RaceMenuOverlay.cpp:1447` — `ForgetActorState`
- `src/BodyChangeNG/RaceMenuOverlay.cpp:1466` — registry가 없으면 정리 작업 종료
- `src/BodyChangeNG/ActorEvents.cpp:253` — 미리보기 정리 예약 후 transient registry 제거
- `src/BodyChangeNG/ActorRegistry.cpp:807` — `ForgetTransient`
- `src/BodyChangeNG/ActorState.h` — `CompleteOverlayTransaction`, `HasPersistentAppearance`

발생 조건과 흐름:

1. BCNG의 확정된 바디·스킨·후타·오버레이 기록이 없는 NPC에서 오버레이를 미리본다. NPC 배포 체크박스 미리보기도 해당한다.
2. 미리보기는 RaceMenu 노드에 적용되지만, 확정된 선택으로 기록하지 않는다. 이는 정상 정책이다.
3. NPC 언로드 시 `ForgetActorState`가 임시 슬롯 소유권을 캡처하여 actor-0 정리 작업을 예약하고, 미리보기 맵에서 제거한다.
4. 같은 언로드 처리에서 `ForgetTransient`가 확정 외형 없는 registry 항목을 제거한다.
5. 나중에 정리 작업이 실행되면 `!ActorRegistry::Get().Snapshot(actor)` 검사에 걸려, 캡처해 둔 오버레이 삭제를 수행하지 않는다.

**영향:** 임시 오버레이 등록이 남고 BCNG의 미리보기 추적은 사라질 수 있다. 재등장 시 원치 않는 표시/슬롯 점유로 이어질 여지가 있다. UI 적용 카운트는 확정 선택 기반이므로 남은 임시 등록을 제대로 설명하지 못할 수도 있다. 실제 화면·RaceMenu 저장 파일에 남는 양상은 인게임 확인하지 않았다.

오프라인 재현은 제품의 `ForgetActorState`와 `ForgetTransient`, 실제 상태 정책 헤더를 사용했다.

| 조건 | 정리 작업 뒤 임시 등록 |
| --- | --- |
| 미리보기만 한 NPC | 남음: 결함 재현 |
| 확정 바디 선택도 있는 NPC | 제거됨: 대조군 |

권장 수정: 이미 캡처한 임시 슬롯 소유권으로 정리하고, 별도 확정 registry의 존재를 필수 조건으로 삼지 않아야 한다. 재등장 후 새로운 미리보기를 시작한 경우까지 고려해 요청 세대와 실제 슬롯 소유권 검증은 유지해야 한다.

## 3. 기본 스킨 복원 실패가 성공 상태로 기록될 수 있음 — P2

관련 위치:

- `src/BodyChangeNG/NativeSkinBackend.cpp:947` — `RestoreOwnedPointers`의 성공/실패 반환
- `src/BodyChangeNG/NativeSkinBackend.cpp:1285` — `ClearNow`에서 반환값 무시
- `src/BodyChangeNG/NativeSkinBackend.cpp:1054` — 얼굴 성공 뒤 `MarkSkinApplied`
- `src/BodyChangeNG/NativeSkinBackend.cpp:1046` — 실패 복구 분기의 유사한 반환값 무시

`RestoreOwnedPointers`는 private TXST 중 일부라도 원본 경로로 쓰기/읽기 검증에 실패하면 `false`를 반환한다. 그러나 `ClearNow`는 그 결과를 무시하고 적용 ID를 비우며 `appliedDefault=true`로 바꾼다. 이어 얼굴 정리가 성공하면 전체 스킨 Default 적용 완료로 기록될 수 있다.

**영향:** 일반 Default 복원에서 몸 쪽 실패를 감춘다. 특히 외부 제공자가 과거 private ARMA/TXST를 참조하고 있다면 아직 사용자 DDS가 남은 복제물을 재사용할 위험이 있다. 다만 이는 **복원 쓰기 실패가 실제로 발생한 경우의 결함**이지, 정상 Default가 매번 실패한다는 뜻은 아니다. TNG 제보의 원인으로 확정하지 않는다.

오프라인 실패 주입에서 제품 `ClearNow`를 그대로 실행했다. private 복원이 실패하고 얼굴은 성공하도록 설정했을 때, private 사용자 텍스처가 남아 있는데도 Default 상태와 성공 완료가 함께 관측됐다. 복원 성공 대조군에서는 이 불일치가 없었다.

**삭제 준비 완료 판정과는 구분:** 삭제 준비는 별도의 `PrivateTexturesRestored()`로 실제 경로를 검사한다. 이 결함만으로 삭제 준비가 무조건 잘못된 완료를 표시한다고 판정하지 않는다.

권장 수정: 몸 복원 결과와 얼굴 복원 결과를 각각 보존하고 모두 성공했을 때만 완료로 기록해야 한다. 실패 시 재시도에 필요한 원본 정보와 상태를 유지하고, 동일 반환값을 무시하는 다른 호출부도 함께 점검해야 한다.

## 재실행 결과와 메모리·성능 범위

- 고정 xmake 3.1.0으로 `xmake build -a` 성공. 의존성 변경 없음, VR 비활성 설정 유지.
- `build/v1.2.8/tests/*Tests.exe` **31개 모두 exit 0**. 빌드에서 다시 생성된 FailurePathTests도 재실행하여 통과.
- `tools/test-addon-audits.py` **19개 통과**.
- 배포 메타데이터 Address Library 주소 **12개 런타임 × 11개 통과**. 주소 존재 검사지 모든 후킹 코드/엔진 행동의 검증은 아니다.
- 오프라인 할당 검사: 6그룹×100회, 2,977,400회 호스트 C++ 할당. 그룹 종료 시 잔여 바이트/블록 증가 0. 4,096바이트 양성 대조군 정상 검출.
- 이 메모리 검사는 가짜 VM/엔진 경계이며 성공한 장기 유지 그래프는 검사기가 직접 정리한다. 실제 엔진 메모리·VRAM의 누수량을 의미하지 않는다.
- 실제 제품은 TNG 등의 raw pointer 참조 가능성 때문에 공개한 그래프 일부를 프로세스 수명 동안 보존한다. 원본 제공자/종족 변경 반복 시 누적 가능성이 남는다. 일반 동일 원본의 스킨 팩 변경은 그래프를 재사용한다.
- 합성 1,000팩 카탈로그 검사: 스킨 메타데이터 복사+집계 중앙값 약 **14.6869 ms**, 공유 카탈로그의 캐시된 집계 순회 약 **0.0004 ms**. 게임 FPS 측정은 아니다.
- DLL SHA-256은 배포 기준과 동일: `26392044CF7EB914FC993C833EE9EE20AF6F86ACB7E20DB19081AF44222C6FA3`.

## 추가 재현 방법

진단 스크립트: `build/audits/detailed-functional/Run.ps1`.

스크립트는 4개 제품 함수 본문을 진단 디렉터리의 include 파일로 기계적으로 추출하고, `Probe.cpp`와 함께 컴파일한다. 액터/노드/복원 성공 여부만 가짜 경계로 대체한다. 게임을 실행하거나 조작하지 않는다.

관측 결과:

```text
overlay detached preview-only remains=1 control committed actor remains=0
native Default reports success after restore failure=1 control success misreported=0
unloaded ordinary skin rollback skips backend=1 control removal calls backend=1
```

이 진단 실행 파일은 **현재 결함과 대조군이 예상대로 관측되면 exit 0**을 반환한다. 제품의 올바른 동작을 승인하는 회귀 테스트가 아니다. 수정 후에는 정상 기대값을 사용하는 회귀 검사로 바꿔야 한다.

이번에는 위 3개 제품 수정은 하지 않았다. 특히 미리보기 언로드 정리는 바디/오버레이/얼굴의 서로 다른 소유권을 구분해 고치는 것이 다음 우선 작업이다.
