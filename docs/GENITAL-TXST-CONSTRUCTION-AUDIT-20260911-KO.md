# SOS/TNG TXST 전환: SE 및 AE 실행 코드 조사

후속 진행: 수명 조사와 시험 구현 결과는
[Native TXST 시험 기록](GENITAL-NATIVE-TXST-TRIAL-20260911-KO.md)에 정리했다.
아래의 미구현/미확인 표기는 각 조사 시점의 기록이며 실기 완료를 뜻하지 않는다.

## 상태

2026-09-11 사용자 요청으로 실행 중인 툴레드 메인 메뉴에서 읽기 전용 조사했다.
이 문서는 **전환 완료 또는 게임 기능 테스트 통과 보고서가 아니다**.
현재 성기 적용은 기존 LiveAddonSkinBackend 그대로이며, 게임 메모리 쓰기·DLL 교체·
세이브 변경·공개 Release 갱신은 하지 않았다.

**추가 조사로 정정:** AE 1.6.1170의 `DoReset3D(false)`가 설정하는 갱신 플래그를
끝까지 추적했다. 지오메트리를 재사용한 뒤에도 선택 TXST를 다시 읽히는 네이티브
경로가 있다. 따라서 아래 초기 조사의 “재사용 무효화가 필요하다”는 결론은 철회한다.
현재 우선 설계는 **TXST 공급 + 기존 정상 갱신 경로**이며, 성기 강제 제거·재생성이나
private model 포인터 교체를 추가하지 않는다. 세부 근거는 마지막 추가 조사 절에 있다.

같은 ActorBase를 공유하는 NPC의 동일 스킨 사용은 사용자가 허용했다.
하지만 서로 다른 ActorBase가 같은 SOS ARMO/ARMA를 사용하는 경우까지 함께 바꾸는
것은 허용된 것이 아니다. 원본 공유 TXST를 수정하는 방식은 여전히 제외한다.

## 확인 환경과 재현 자료

- 프로세스: TuLED SkyrimSE.exe, PID 9528, SE 1.5.97.
- 실제 경로: `D:\TuLED13E\STOCK GAME\Skyrim Special Edition\SkyrimSE.exe`.
- 원본 EXE SHA-256은 `build/audits/addon-txst/se-full/addon-code.json`에 기록.
- `OpenProcess(0x410)`만 사용: query/read 권한. actor 객체/heap/세이브는 읽지 않는다.
- Address Library와 설치 EXE 버전 일치를 확인하고, PE 실행 섹션 및 unwind 정보로
  범위를 제한했다. chained unwind 조각도 합쳐 함수 본문 누락을 방지했다.
- 호출자 검색은 실행 섹션 32 MiB 이하에서 수행하고 전체 섹션 데이터는 보관하지
  않는다. E8 바이트 검색 후보는 저장한 디스어셈블리에서 호출 명령인지 다시 확인한다.
- 도구: `tools/audit-addon-txst-code.py`. CommonLib의
  `TESObjectARMA::InitWornArmorAddon` relocation ID는 SE 17361, AE 17759다.

## 확인된 실제 경로

| SE RVA | 확인 내용 |
|---|---|
| `0x227070` | InitWornArmorAddon. 성별/1인칭 모델을 선택하고 ARMA의 skinTextures 및 swap list에서 TXST 선택 |
| `0x227222` | 선택 TXST를 5번째 인자로 Biped 구성 함수 `0x1C6C50`에 전달하는 CALL |
| `0x1C6EA5` | 선택된 BIPOBJECT의 skinTexture 필드에 그 포인터를 저장. ARMO/ARMA 자체를 고치는 명령은 아님 |
| `0x1C6F90` | 이전 bufferedObjects와 현재 objects를 비교하는 3D 구성 루틴 |
| `0x1C7127`, `0x1C713A` | 기존 모델 포인터와 장비 포인터 비교 후 재사용 여부 분기 |
| `0x1C7140..0x1C7145` | 재사용 경로에서 새 skinTexture 포인터를 이전 buffered object로 복사 |
| `0x1C717A` | 재사용 경로의 방문은 `0x1CB8A0` → `0x1CB980`; 읽은 본문은 피부 TXST 로드가 아니라 skin partition 표시 처리 |
| `0x1CAFB0` | 새 부착 경로. 현재 설치 모드에 의한 분기 패치가 이미 존재함 |
| `0x1CCD50` | 새 부착에서 사용하는 피부 셰이더 방문자. BIPOBJECT.skinTexture를 읽어 재질의 텍스처 로딩 함수로 전달 |

`0x227222` 호출 인자는 현재 SE 본문에서 다음 순서다.

1. BipedAnim*
2. 원본 ARMO*
3. 원본 ARMA*
4. 선택된 TESModelTextureSwap*
5. 선택된 BGSTextureSet*

원본 함수는 이 연결에서 장비 구성 데이터를 만들고, 이후 별도 부착 단계가 재질에
TXST를 읽힌다. 따라서 **TXST 공급 인자만 대체하는 후보 지점**은 확보했다.
단, 이것을 아직 설치 가능한 안전한 완성 후킹이라고 판정하지 않는다.

## 초기 조사: TXST 인자 교체와 재사용 분기 (아래 추가 조사로 보완)

현재 확인한 재사용 분기는 장비와 모델 포인터를 비교하지만 TXST 차이만으로 새 부착을
요청하지 않는다. 새 TXST 포인터를 복사해도 이전 지오메트리를 그대로 사용하는
분기가 존재한다. 하지만 이 사실만으로 반복 선택의 표시가 갱신되지 않는다고
판정할 수 없다. 뒤쪽의 갱신 플래그 분기도 확인해야 한다(아래 추가 조사 참고).

새 부착 방문자는 shader flag `0x200000`(FaceGenRGBTint), `0x400`(FaceGen) 분기를
사용한다. 임의의 조명 셰이더 전부에 skinTexture가 자동 적용된다고 일반화할 수 없다.
애드온 NIF의 해당 셰이더/부위 구성을 적용 승인 조건과 대조해야 한다.

이 기록은 이전 오버레이 실패 원인을 새로 확정한 것이 아니다. **새 성기 TXST
구현에서 같은 형태의 실패를 만들 수 있는 경로를 발견한 것**이다.

## 구현 전 남은 검증

- AE 1.6.1170의 인자/필드/재사용 조건 대조는 아래 추가 조사에서 완료했다.
  다른 AE 버전의 검증까지 완료한 것은 아니다. SE 오프셋을 AE에 복사하지 않는다.
- 슬롯 52의 TXST만 교체하고 모델/ARMA의 다른 부위를 건드리지 않는 대상 판별.
- 재사용 무효화/private model 방식은 보류한다. 기존 정상 갱신 플래그를 통한
  네이티브 TXST 재로드를 우선 사용하고, 새로 공급하는 TXST의 수명을 검증한다.
- BIPOBJECT가 TXST의 raw pointer를 보관하므로 함수 복귀 직후나 선택 변경 직후에
  복제 TXST를 파기하면 안 된다. buffered object와 진행 중인 로딩도 포함한 수명 설계 필요.
- 누락 DDS는 선택/공급 원칙에 맞게 원본 채널을 유지하고, NIF-only 애드온 및 alternate
  texture의 실제 기본값 확보 방법 검증. 빈 TXST를 주어 보라색으로 만드는 것 금지.
- TNG 재조합 뒤에도 새 애드온을 다시 판정해야 한다. TNG 캐시/표식을 BCNG가 위조하거나
  TNG 전용 함수의 미확인 주소를 호출하지 않는다.
- 현재 3D 부착 함수에 설치된 다른 모드의 후킹을 덮어쓰지 않는다.

## 수행한 검사

- 새 읽기 전용 조사 도구 `py_compile` 통과.
- SE 실행 코드 10개 바이트/상대 CALL 대상 검사 통과: ARMA TXST 읽기, 5번째 인자 전달,
  BIPOBJECT 필드 저장, 기존 3D 재사용 시 포인터 전달, 최종 피부 방문자의 채널 읽기와
  두 shader flag 분기.
- 게임 내 선택/반복 선택/저장·로드/탈착/두 NPC 격리는 **아직 테스트하지 않았다**.
- 이번 변경은 조사 도구와 문서뿐이다. 따라서 새 성기 TXST DLL의 Release 빌드나
  전환 후 전체 회귀 테스트 결과는 아직 없다.

## AE 1.6.1170 추가 조사

사용자가 떼껄룩을 일반 권한으로 메인 메뉴까지 실행한 뒤 PID 21500에서 동일한
query/read 권한으로 코드만 읽었다. 경로는 `C:\TAKEALOOK\Stock Game\SkyrimSE.exe`.
실행 파일과 Address Library 버전은 모두 1.6.1170.0이다. 최종 캡처와 파일 해시는
`build/audits/addon-txst/ae-full/addon-code.json`에 기록했다.

| AE RVA | 확인 내용 |
|---|---|
| `0x2775D0` | InitWornArmorAddon, Address Library ID 17759 |
| `0x277692` | 성별 ARMA TXST를 `+0x130`에서 읽음 |
| `0x277782`, `0x277791` | TXST를 5번째 인자로 `0x213210`에 전달 |
| `0x2134F4` | BIPOBJECT.skinTexture에 raw pointer 저장 |
| `0x213580` | 기존/현재 BIPOBJECT를 비교하는 3D 구성 루틴 |
| `0x21370F`, `0x213725` | 모델 및 장비 포인터 비교 |
| `0x213730`, `0x213735` | 재사용 분기에서 새 TXST를 buffered object로 복사 |
| `0x21376A` | 재사용 분기의 `0x218120` 호출; 하위 `0x218200`은 partition 처리 경로 |
| `0x217550` → `0x217890` | 새 부착 처리 경로; 앞 함수의 진입점은 이미 후킹되어 있음 |
| `0x217DC8`, `0x217E06` | 피부 방문자 직접 호출 및 재귀 방문 호출 |
| `0x219510` | 피부 방문자; 두 shader flag 분기에서 BIPOBJECT TXST 읽음 |
| `0x219620`, `0x219630` | TXST를 텍스처 로딩 데이터로 전달한 뒤 재질 가상 함수 호출 |

이때 확인한 것은 재사용 분기의 앞부분이며, 이것만으로 반복 선택의 즉시 표시
불가를 확정한 것은 잘못이었다. BIPOBJECT의 stride는 0x78, objects는 +0x10,
bufferedObjects는 +0x13C0, actorRef는 +0x2770으로 해당 본문 및 CommonLib 선언과
일치한다. 이 확인을 전체 Actor 레이아웃이나 다른 런타임으로 확대하지 않는다.

또한 `0x217550` 진입에 간접 JMP, `0x217160` 진입에 직접 JMP가 설치되어 있다.
패치 뒤 남아 있는 원래 본문을 읽었다고 해서 해당 모드의 전체 후킹 체인까지 검증한
것은 아니다. 어느 모드 소유인지 이번 범위에서는 확정하지 않았으며 덮어쓰지 않는다.

기존 코드 재사용 분기는 CommonLib의 RemoveAllParts(AE ID 15659, `0x212560`)의
실제 CALL 호출자를 찾아 확인했다. 근접 주소나 SE와의 일정한 오프셋을 추측해
대응시킨 것이 아니다. 조사 도구에 알려진 함수의 호출자 검색 옵션을 추가했으며,
기존 실행 섹션 제한·최대 64개 함수·읽기 전용 권한 제한은 유지했다.

추가 검사:

- `tools/check-addon-txst-ae-capture.py`: 저장된 AE 코드의 명령/분기 대상 16개 검사 통과.
- 조사/검사 도구 두 파일 `py_compile` 통과.
- 게임 메모리 쓰기, 함수 실행, 세이브 로드, DLL 교체 없음.
- 성기 TXST 전환 구현, 반복 선택 실기 테스트, 새 DLL 빌드는 아직 수행하지 않음.

이 단계에서 재사용 무효화를 검토했지만, 후속 조사에서는 정상 갱신 분기를 찾았다.
남은 핵심은 공급 TXST의 참조 수명과 애드온 NIF의 피부 셰이더 적합성이다.
현재 캡처는 이 설계를 진행할 근거이며, 전환 완료나 누수·CTD 부재의 증명은 아니다.

## AE 정상 갱신 경로 추가 조사 및 정정

사용자가 메인 메뉴를 켜둔 TAKEALOOK PID 14892, 1.6.1170.0에서 코드만 읽었다.
최종 묶음은 `build/audits/addon-txst/ae-native-txst-refresh/addon-code.json`이다.
`tools/check-addon-native-refresh-capture.py`의 명령·분기·RIP 상대 전역 변수 연결
27개 검사를 통과했다. 이는 실행 코드의 연결 검사이며 인게임 기능 테스트가 아니다.

1. CommonLib `Actor::DoReset3D` AE ID 40255는 `0x726F10`이다.
   `false`인 경우 `0x726F3C`에서 RemoveAllParts 블록을 건너뛴다.
   일반 경로 `0x72708C`에서 설정하는 갱신 플래그는 `0x17`로 `0x2`를 포함한다.
2. AIProcess 갱신 AE ID 39395, `0x6E3B70`은 `0x6E3E3D`에서 `0x2`를 검사한다.
   `0x6E3E4C`에서 네이티브 갱신 제어 바이트를 켜고, 액터의 바디 구성을 갱신한 뒤
   `0x6E3E6C`에서 이전 상태에 맞게 되돌린다. BCNG가 이 전역 바이트를 쓰면 안 된다.
3. `0x2E8510` → `0x3BDD00` → `0x213580`이 동기 호출로 연결된다.
   마지막 호출은 `0x3BE272`이다. 엔진 코드에는 플레이어/일반 액터 분기가 함께 있다.
4. 기존 지오메트리를 재사용할 때 새 TXST를 복사한 후, partition 방문에서 끝나지 않는다.
   `0x21377B`에서 **위와 동일한 전역 바이트**를 검사하고, 켜져 있으면 `0x213794`에서
   `0x2180E0`을 호출한다. 이전 조사에서 이 후속 분기를 빠뜨렸다.
5. `0x2180E0`은 현재 BIPOBJECT 배열·슬롯·지오메트리로 방문 문맥을 구성한다.
   `0x218107` → `0x218EC0` → `0x219510`으로 연결되며, 최종 방문자는 해당 슬롯의
   TXST를 읽어 엔진의 텍스처 로딩 함수를 호출한다.

따라서 **이 코드 경로에서는 재사용 자체가 새 TXST 반영을 막는 것이 아니다.**
원본 장비를 유지하면서 새 TXST를 공급하고 정상 갱신을 요청하는 설계를 우선한다.
이는 별도 Live Material 적용을 추가하거나 성기 모델을 강제로 제거하는 설계가 아니다.
다만 실제 다른 모드의 후킹 체인과 BCNG 공급 코드까지 실행 검증한 것은 아니다.
이 시점에는 SE 기존 캡처의 대응 플래그만 확인했으며, 이후 아래 SE 추가 조사에서
남은 하위 함수까지 읽었다. 다른 AE 버전도 별도 확인이 필요하다.

### 수명 조사

`ae-part-lifetime` 및 `ae-refresh-lifetime` 캡처에서 확인했다.

- BIPOBJECT 복사 `0x212180`: TXST `+0x18`은 참조 카운트 증가 없이 raw pointer 복사.
  지오메트리 `+0x20`은 별도로 참조 카운트를 조정한다.
- 초기화 `0x212000`: TXST 포인터는 0으로 지우지만 TXST 자체를 해제하지 않는다.
- 부위 제거 `0x212730`: 지오메트리 관련 정리, 참조 해제 및 작업 큐 경로가 존재한다.
  `0x655160`은 지오메트리 참조를 증가시켜 정리 작업을 전달한다.
- 제거 함수의 네 번째 인자는 코드상 `r9d`를 읽고 sign-extend한다. bool 인자로
  추측하여 직접 호출하지 않는다. 정리 하위 함수 진입에 이미 다른 후킹도 관찰됐다.

BCNG 공급 TXST를 선택 변경 즉시 파기하거나, 모든 과거 선택 TXST를 무한 보관하는
방식 둘 다 채택하지 않는다. 공급 데이터의 소유권·안전한 해제 경계 검증은 아직 남았다.

### 설치 NIF 표본

읽기 전용 `tools/audit-addon-nif-shaders.py`로 정확한 NIF 블록 표를 파싱했다.
두 표본 모두 shader type 5, flags1 `82601303`, flags2 `02008001`이며, 네이티브
Skin TXST 방문자가 사용하는 플래그 조건에 해당한다.

- TAKEALOOK LDD Altmer `malegenitals_1.nif`:
  SHA-256 `05ba8d9e155fafbedb1c92ff2f5ef3cb16bcf2358a5c2a369a03a6545563eeb2`.
- TuLED ERF CBBE `futanari_schlong_cbbe_1.nif`:
  SHA-256 `0c65bfb07a222ed4041a31ce4b2a5be9471ad2b31529d1ec17718bf1a736c685`.

이것은 표본 파일의 셰이더 확인이다. 모든 애드온, MO2 우선순위의 실제 승자 파일,
LDD와 다른 팩의 UV 호환성까지 증명하는 것은 아니다.

현재 상태: 성기 TXST 런타임 전환 코드/DLL은 아직 작성·배포하지 않았다.
기존 몸·손·발·얼굴·오버레이 코드는 이번 조사에서 변경하지 않았다.

추가 검증 결과:

- 기존 AE 캡처 검사 16개 통과.
- 정상 TXST 갱신 연결 검사 27개 통과.
- `tools/test-addon-audits.py` 10개 테스트 통과. NIF 절단/잘못된 참조 거부,

  서로 다른 전역 플래그로의 연결 변조가 검사 실패로 검출되는지 포함한다.
- 플러그인 전체 테스트/Release 빌드/실기 테스트를 대신하는 결과는 아니다.

## SE 1.5.97 / TuLED SOS 환경의 후속 연결 확인

사용자가 툴레드를 메인 메뉴로 실행한 PID 23176에서 query/read 권한만 사용했다.
EXE/Address Library 버전은 1.5.97.0이며 경로는 앞서 기록한 TuLED 경로와 같다.
캡처는 `build/audits/addon-txst/se-native-txst-refresh/addon-code.json`에 저장했다.
게임 메모리 쓰기, 함수 호출, 세이브 로드 및 DLL 교체는 하지 않았다.

| SE RVA | 이번 캡처에서 확인한 연결 |
|---|---|
| `0x69313C` → `0x693264` | DoReset3D(false)는 RemoveAllParts 블록을 건너뜀 |
| `0x69327E` | 일반 갱신 플래그 `0x17` 설정 |
| `0x6510BB`, `0x6510CA`, `0x6510EA` | `0x2` 검사, 텍스처 갱신 제어 바이트 설정/복원 |
| `0x6510D7` → `0x2943B0` → `0x364FF0` | 액터 바디 구성 갱신 |
| `0x36533C` → `0x1C6F90` | 동일 호출 안에서 Biped 구성 처리 |
| `0x1C7140`, `0x1C7145` | 재사용할 부위에 새 TXST 포인터 전달 |
| `0x1C718B`, `0x1C71A4` | 재사용 후 동일 제어 바이트 검사, 켜져 있으면 `0x1CB860` 호출 |
| `0x1CB887` → `0x1CC700` | 현재 BIPOBJECT 배열/슬롯/지오메트리로 재귀 방문 |
| `0x1CC735` → `0x1CCD50` | 최종 네이티브 피부 텍스처 방문자 |
| `0x1CCE27`, `0x1CCECB` | 해당 슬롯 `skinTexture` 읽기, 두 피부 셰이더 분기 |
| `0x1CCE5E` → `0x2D1980`, `0x1CCE6E` | TXST 텍스처 로딩 데이터 생성 및 재질 로딩 호출 |

갱신 제어 바이트는 생산자와 소비자 모두 RVA `0x1EC4498`을 가리킨다.
RIP 상대 주소를 계산해 비교했으며 ASLR 절대 주소나 AE 상대 오프셋을 재사용하지 않았다.
이것으로 앞서 미확인으로 남긴 SE `0x1CB860` 이후의 연결도 확인했다.

결론: 툴레드의 SOS 환경에서도 **원본 장비 유지 → 액터별 선택 TXST 공급 → 정상
게임 갱신**을 우선 설계로 사용할 코드상 근거가 있다. 이미 장착된 성기의 텍스처를
갱신하기 위해 BCNG가 SOS를 대신 Equip/Unequip하거나 모델을 강제로 지울 근거는 없다.
이는 SOS의 모든 애드온/셰이더가 적합하다는 뜻이나 완성 DLL의 작동 보증은 아니다.
TXST 공급 훅, 복제 TXST의 수명/해제 및 기본값 복원은 아직 구현 검증이 남아 있다.

검증:

- `check-addon-native-refresh-capture.py --runtime se`: 27개 코드 연결 검사 통과.
- 같은 도구 `--runtime ae`: 기존 27개 검사도 통과.
- `test-addon-audits.py`: 14개 테스트 통과. SE/AE 런타임을 서로 잘못 표기한 캡처,
  누락 함수, 변경된 후속 CALL/전역 변수/플래그 값이 검사에 걸리는지 포함한다.
- 도구와 조사 기록만 변경. 런타임 전환 DLL, 전체 플러그인 회귀 테스트 또는
  SOS/TNG 선택·저장/로드 실기 테스트 완료를 보고하는 것이 아니다.
