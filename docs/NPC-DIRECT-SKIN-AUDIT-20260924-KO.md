# NPC 직접 스킨 선택 점검 — 2026-09-24, 미배포

이하 내용은 버전업 전 개발 점검 기록입니다. 최종 1.3.2 빌드·검증 결과는 [배포 검증 기록](RELEASE-VERIFICATION-v1.3.2-KO.md)을 참고하세요.

기준: `main`의 1.3.1 소스 `7a3c92b87613d0a61f7d48822fa62262e9f2d0bc`와 `v1.1.4` 태그 비교.

## 제보와 확인 범위

- 1.3.1에서 팔로워 스킨을 바꾸려면 규칙이 필요한 것처럼 보이고, 1.1.4보다 적용이 어렵다는 제보.
- 플레이어는 바디프리셋·스킨 모두 되지만 NPC는 바디프리셋만 적용된다는 추가 제보.
- 직접 스킨 적용 함수에 NPC 배포 규칙을 요구하는 조건은 없었다. 배포의 커스텀 팔로워·노인 제외는 일반 액터 드롭다운이나 직접 스킨 선택의 필터가 아니다.
- 제보자의 팔로워/스킨팩/로그가 없으므로 아래 코드상 실패 조건이 실제 제보자의 원인이라고 확정하지 않는다. 인게임 테스트나 세이브 수정은 하지 않았다.

## 확인한 차이와 수정

### 1. 판별되지 않은 바디 계열의 직접 선택

1.1.4는 액터 바디 계열이 0(미확인)이면 스킨 후보를 숨기지 않았다. 1.3.1은 `EvaluateSkinCompatibility`에서 계열이 하나로 결정되지 않으면 목록과 실행 모두 거부했다. 바디프리셋 목록의 미확인 계열 허용 동작과도 달랐다. 독립형 팔로워의 전용 메시·DDS 경로, 여러 바디 프레임워크가 공존하는 환경에서 이러한 차이가 드러날 수 있다.

직접 선택과 자동 배포의 의도를 분리했다. 직접 선택은 미확인 액터에게 성별·종족이 맞고 레이아웃을 아는 스킨팩을 표시한다. 알려진 UBE/일반 계열 불일치, 성별·종족 불일치, 미분류 팩은 여전히 거부한다. UI에는 미확인 안내와 규칙 없이 클릭 미리보기·더블클릭 적용할 수 있다는 안내를 표시한다. 사용자가 실제 액터에 맞는 일반/UBE 팩을 선택해야 하며 이 변경이 UV 자동 판별을 보장하는 것은 아니다.

일반 스킨의 정확한 CBBE/UNP 계열을 모르면 몸·손·발의 원래 ARMA/TXST 및 NIF 타깃으로 처리하고, 계열에 종속된 성기·항문 보조 아틀라스는 추측하여 적용하지 않는다. 미확인 상태를 BCNG 내부 DDS 이름으로 재분류하지 않는다.

자동 배포 후보 선택과 자동 재적용은 기본 엄격 정책을 유지한다. 수동 선택 저장의 기존 manual 표시로 재로드 시 직접 선택 정책을 이어가므로 별도 세이브 스키마 변경은 없다. 미리보기 취소와 플레이어 RaceMenu 후 복원에도 직접 선택 의도를 전달한다.

### 2. NPC 얼굴 메시 이름

1.1.4는 실제 FaceGen 하위 메시를 찾았지만, 1.3.1은 HeadPart EditorID와 실제 geometry 이름의 일치를 전제로 재생성 대기·적용·검증을 처리했다. 이 이름이 다른 내보낸 얼굴이나 일반 HeadPart를 찾지 못하는 얼굴 구조에서는 유효한 얼굴이 있어도 적용 대상이 없을 수 있다.

이제 실제 `GetFaceNodeSkinned()` 영역만 읽어 정확한 HeadPart 이름을 우선한다. 일치하는 이름이 없으면 유효한 얼굴 피부 재질이며 명확히 하나인 후보만 사용한다. 눈·입·머리카락·몸·손·발을 대체 대상으로 사용하지 않는다. RaceMenu가 액터 루트에서 같은 이름의 다른 객체를 찾는 경우에는 쓰지 않는다. 찾은 이름만 복사하고 geometry/material 포인터는 비동기 작업이나 세이브에 보관하지 않는다.

두부의 Heejung/Erienne FaceGen NIF도 읽기 전용으로 확인했다. 전용 텍스처 경로와 얼굴·입 등의 별도 geometry가 존재한다. 확인한 Heejung 얼굴 이름은 해당 HDPT와 일치하므로 이 팔로워가 이름 불일치로 실패했다고 주장하지 않는다. 이름 불일치 경계는 실제 제품 resolver를 가짜 엔진 객체에 연결한 테스트로 검증했다.

### 3. 몸 전용 팩의 얼굴 대기

기존 재생성 확인은 얼굴 DDS 유무와 관계없이 선택 요청이면 얼굴 준비를 요구했다. 이제 얼굴 채널도 없고 복원할 이전 얼굴 baseline도 없으면 얼굴 타깃 검색/Override 연결을 생략한다. 몸의 재생성 완료 확인은 그대로 수행한다. 이전 얼굴 변경을 지워야 하거나 얼굴 채널이 하나라도 있으면 기존 얼굴 복원·검증 절차를 유지한다.
