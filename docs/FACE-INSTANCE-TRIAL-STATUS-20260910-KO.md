# 부착 전 얼굴 인스턴스 시험 — 진행 상태

후속 구현: [2026-09-11 시험 DLL 및 검증 기록](FACE-ATTACHMENT-TRIAL-20260911-KO.md).
아래 “미구현” 표기는 조사 당시의 기록이며, 최신 구현 상태는 후속 문서를 따른다.

2026-09-11 추가 코드 캡처와 확인 사항은
[얼굴 부착 경계 추가 조사](FACE-ATTACHMENT-BOUNDARY-AUDIT-20260911-KO.md)에 기록했다.
아래의 게임 종료/미캡처 상태는 9월 10일 당시 기록이다.

**9월 11일 메인 메뉴 재확인으로 설계 조건을 정정했다.** TESNPC 얼굴 등록표는
장비 슬롯의 얼굴 partition 표시를 갱신하는 데 사용되므로, 실제 붙인 얼굴을
등록해야 한다. 공용 모델 DB만 원본으로 보존하고, 현재 얼굴 등록표의 원래
삽입·조회·제거는 건드리지 않는다. 아래의 “원본이 아닌 얼굴을 등록하지 않는다”는
과거 조건은 더 이상 채택하지 않는다. 상세 증거는 위 조사 기록의 메인 메뉴
재확인 절을 따른다. 런타임 어댑터 미구현 상태는 그대로다.

## 아직 구현 완료가 아니다

사용자가 동의한 방향은 원래 FaceGen 로딩이 끝난 뒤, 액터에 부착하기 전에
액터 전용 얼굴 인스턴스에 선택 TXST를 바인딩하는 것이다. 기존 몸·손·발
Native Skin Armor 경로, 원본 HeadPart/NIF, RaceMenu 오버레이 경로는 바꾸지 않는다.

**이번 단계에서는 런타임 후킹을 넣지 않았다. 새 얼굴 적용 시험 DLL도 아직
준비되지 않았다.** 아래 캐시와 수명 경계를 해결하지 않고 미완성 어댑터를
비활성 코드로 생산 소스에 남기거나, 작동하는 시험판으로 포장하지 않는다.

## 연결 전에 확인할 위험

SE 1.5.97의 `0x363F20`은 얼굴을 액터에 붙이고, 그 얼굴 포인터를 TESNPC 키의
등록표에도 보관한다. 원래 모델 DB 등록은 앞선 FaceGen 로더 내부에서 끝난다.
따라서 이 지점에서 얼굴을 새로 복제하는 것은 모델 DB 격리의 후보일 뿐,
모든 공유 상태와의 격리를 자동으로 보장하지 않는다.

특히 TESNPC 등록표를 모델 DB와 같은 성격의 단순 캐시로 간주하면 안 된다.

- `0x3641A0`은 등록된 얼굴 참조를 조회한다.
- `0x361AE0`은 등록표에서 얼굴을 제거한 뒤, 꺼낸 노드를 `0xC61CE0`에 전달한다.
- 마지막 함수의 정확한 정리 동작과 조회 결과의 전체 사용처는 미확인이다.
- 월드에는 복제 얼굴을 붙이고 등록표에는 원본을 넣는 우회는, 두 경로가 같은
  얼굴을 가리켜야 하는 엔진 계약을 깨뜨릴 수 있다. 안전하다고 확정하지 않는다.

원본이 아닌 얼굴을 등록하지 않겠다는 설계 조건을 지키려면, 등록/조회/제거의
역할과 부착된 인스턴스의 수명까지 함께 검증해야 한다. 이를 확인하지 않고
삽입 함수 인자만 바꾸는 후킹을 구현하지 않는다.

다음 실행 코드 확인 대상은 삽입 함수 `0x36A880`, 제거된 노드 소비 함수,
`BSFaceGenNiNode::CreateClone`, FaceGen 재질의 텍스처 로드/해제 및 셰이더
설정 함수다. 복제 얼굴의 animation data, 재질, TextureSet이 공유되는지도
이 결과와 대조해야 한다. 모든 주소는 SE 1.5.97 전용이며 AE 재사용은 금지한다.

## 이번 수정

- `SkinArchitectureTests.cpp`: 얼굴 helper 호출을 모의 구현하면서 Diffuse를
  선택 경로로 바꿔 놓던 잘못된 테스트 가정을 제거했다. helper dispatch와 실제
  얼굴 DDS 변경 성공을 구분한다.
- `NativeSkinBackend.cpp/.h`: QueueNiNodeUpdate가 몸만 재구축한다는 부정확한
  주석을 고쳤다. 보조 shader helper 로그도 얼굴 Diffuse 성공을 주장하지 않는다.
  실제 적용/복원/저장 동작은 바꾸지 않았다.
- `tools/audit-native-face-code.py`: 읽기 전용 `--attachment-boundary` 조사 모드를
  추가했다. 기존 조사 결과와 분리된 `build/audits/face-attachment-boundary/`에
  출력하며 프로세스 쓰기·함수 호출·후킹·세이브 조작을 하지 않는다.

## 검증 결과와 한계

- 고정된 XMake 3.1.0, 기존 SE/AE-flat Release 구성으로 빌드 통과.
- XMake에 등록된 기존 테스트 실행 파일 17개를 빌드하고 실행, 모두 통과.
- 새 조사 모드의 대상 주소/가상 슬롯을 설치된 1.5.97 EXE의 예외 테이블 및
  고정 Address Library와 오프라인 대조했다. 이는 실행 코드/ABI 검증이 아니다.
- 조사 도구 문법 검사 및 수정한 추적 파일의 whitespace 검사 통과.
- 게임이 꺼져 있어 새 대상의 실행 코드 캡처는 아직 실행하지 못했다.
- 툴레드 MO2, 공개 Release, 세이브 파일은 변경하지 않았다.

이 빌드와 테스트 통과는 얼굴 적용 문제 해결, NPC 간 격리, 세이브/로드 또는
AE의 해당 후킹 경로가 검증됐다는 뜻이 아니다. 새 어댑터 연결 후에는 각각
별도의 검증이 필요하다.
