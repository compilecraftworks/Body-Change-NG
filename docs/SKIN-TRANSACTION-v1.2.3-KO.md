# 1.2.3 바디스킨 반복 전환 점검

## 확인된 코드 문제

1. 일반 목록과 NPC 배포 목록의 미리보기가 확정과 동일한 QueueApply를 사용하여, 성공 시 ActorRegistry의 적용 기록 및 플레이어의 영구 얼굴 키까지 변경했습니다. UI의 수동 선택 저장 여부만으로는 이를 분리할 수 없었습니다.
2. 얼굴 DDS를 순서대로 바꾸다 실패했을 때 이미 바뀐 채널을 되돌리지 않았습니다. 네이티브 몸 그래프도 이미 수정된 상태일 수 있었습니다.
3. 동일 팩의 미리보기와 확정, 동일 ID의 DDS 내용 새로고침을 요청 세대에서 충분히 구분하지 않았습니다.

이는 코드에서 확인한 결함입니다. 사용자가 전한 검은색/이상 텍스처의 모든 원인이나 세이브 자체 손상, GPU 메모리 누수를 인게임에서 확정한 것은 아닙니다. 이전 버전 게임 로그를 이번 빌드의 검증 증거로 사용하지 않았습니다.

## 변경 범위

- skin_transaction::Mode를 UI → SkinApplication → NativeSkinBackend → 얼굴 작업까지 전달합니다. 기본은 확정이므로 기존 NPC 배포와 로드 재적용 호출은 유지됩니다.
- 미리보기는 ActorRegistry의 적용 ID를 갱신하지 않고 플레이어 얼굴 키를 영구 저장하지 않습니다. 기본 스킨 미리보기도 확정 키와 복원 기준을 지우지 않습니다. FCNI에는 원래 경로/기존 소유권이 남아도 미리보기 DDS가 새 영구 소유 키로 들어가지는 않습니다.
- 확정으로 승격할 때는 같은 팩이라도 얼굴 작업의 모드를 확인합니다. DDS 내용이 변경되면 이전 내용의 늦은 완료를 새 적용으로 인정하지 않습니다.
- 얼굴 작업은 변경 전 경로 문자열을 보관합니다. 실패 시 바뀐 채널만 순서대로 복원하며, 복원 실패도 나머지 채널을 막지 않습니다. 외부 모드가 새 키를 쓴 경우 그 키를 덮어쓰지 않습니다. 빈 DDS 경로는 로드하지 않으며, 원래 비어 있던 맵은 재생성 경로에 맡깁니다.
- 네이티브 그래프 쓰기 실패 시 변경 직전 TXST 경로를 복원합니다. 얼굴 완료와 짝을 이루는 몸 스냅샷을 보관하고, 최신 얼굴 작업 실패 시 해당 몸 상태를 복원합니다. 사용할 수 없으면 아직 BCNG가 소유한 포인터만 원래 Skin Armor로 돌립니다.
- 새 클릭이 와도 시작된 얼굴 채널 작업은 끝까지 처리합니다. 늦은 작업은 새 요청의 적용 기록을 확정하거나 새 몸 상태를 롤백하지 않습니다. 성공한 이전 작업의 스냅샷만 다음 복원 기준으로 사용할 수 있습니다.
- 완료 콜백은 비우고 로드 시 복원 스냅샷은 해제합니다. 얼굴 스냅샷은 문자열만 보관하고 지오메트리·텍스처 포인터는 유지하지 않습니다. 몸 스냅샷은 기존 백엔드가 관리하는 폼의 식별 포인터와 경로만 보관하며 새 복제 폼을 만들지 않습니다.
- 정상 상태 재확인에는 새 복원 스냅샷을 만들지 않습니다. 새 타이머, 디스크 전수 검사, 대량 진단 로그 또는 DDS 누락에 대한 추가 전체 차단은 없습니다.

명시적으로 확정한 사용자 선택은 기존 정책대로 저장되어 이후 재적용 대상이 됩니다. 실패한 확정 선택 자체를 삭제하거나 다른 모드의 저장 키를 일괄 삭제하지는 않습니다. ASTR v6 / FCNI v1 형식도 바꾸지 않았습니다.

## RaceMenu 근거

공식 고정 소스의 AddNodeOverride는 persist가 참일 때만 저장 맵에 등록하고, 거짓이어도 현재 외형에 적용합니다. 따라서 기존 Papyrus 대체 경로에서도 미리보기를 비영구로 처리할 수 있습니다.

## 자동 검증과 남은 인게임 확인

- 기존 24개 테스트 대상: 카탈로그, 부분 스킨/UV 라우팅, 얼굴/오버레이, NPC 상태 및 후타 저장, 비동기 작업, 런타임 레이아웃, 모프/의상 보정 등.
- 플레이어/NPC 각각 200회 × 얼굴 5채널 = 2,000개 미리보기 저장 경계에서 실제 FCNI 코덱을 왕복하여 영구 소유/복원 경로가 미리보기 값으로 바뀌지 않는지 확인.
- 네이티브 3행 × 8채널에서 각 쓰기 위치 실패 및 정상 실행을 주입하여 모든 복원 채널을 방문하는지 확인.
- 외부 제공자 키 변경, 미리보기→확정 승격 및 로드 시 작업 세대 차단에 대한 정책/소스 연결 확인.

이 테스트는 게임 렌더러나 Papyrus 지연을 실제 실행하지 않습니다. 인게임에서는 CBBE/BHUNP/UBE의 반복 전환, 기본 스킨 미리보기 후 취소, 확정 후 저장/재로드, NPC 배포 체크박스 미리보기, 남성의 별도 애드온 텍스처 경로를 확인해야 합니다.
