## 게임 버전

명시적으로 허용하는 런타임은 SE **1.5.97**, AE **1.6.317 / 1.6.318 / 1.6.323 / 1.6.342 / 1.6.353 / 1.6.629 / 1.6.640 / 1.6.659 / 1.6.1130 / 1.6.1170 / 1.6.1179**이다. VR, Epic 1.6.678, 목록 밖 게임 버전은 추가하지 않았다. `EXCLUSIVE_SKYRIM_FLAT`과 기존 고정 의존성을 유지했다.

몸·손·발은 기존 TXST/ARMA/Skin Armor 경로를 유지한다. 얼굴은 NiOverride 피부 DDS 채널 방식이다. 피부를 일반 문신 오버레이로 바꾸거나 구 얼굴 HeadPart/TXST 교체 방식을 되살리지 않았다.

### SOS/TNG 성기 TXST의 2개 버전 한정 조건 정리

- 기존 고정 SE/AE 두 버전의 RVA·해시 검사 대신, 위 12개 버전에서 실제 로드된 게임의 Address Library ID를 사용한다.
- 참조 함수 7개씩의 명령어 패턴은 보관된 SE 1.5.97 / AE 1.6.1170 코드에서 생성한다. 외부 상대주소만 같은 ID의 실제 주소로 비교하고, opcode·멤버 오프셋·상수·가상 함수 슬롯·함수 내부 분기는 그대로 검증한다.
- GOG 1.6.659에는 AE Steam의 `Sleep` IAT 데이터 ID 175091이 없다. 이 항목을 무조건 조회하면 CommonLib가 실행을 종료할 수 있었다. OS 호출은 게임 IAT 안의 실제 `kernel32!Sleep` 항목으로 식별한다. 나머지 필요한 32개 ID는 12개 Address Library 모두에서 존재함을 확인했다.
- 호출 지점은 Address Library로 식별한 함수의 unwind 범위 안에서, 전후 명령과 원래 호출 대상이 유일하게 맞는 경우만 연결한다. 전체 EXE 검색이나 첫 번째 CALL 임의 선택은 하지 않는다.
- 보관된 두 런타임의 실제 호출 지점 4개 및 원본 소유권 코드 14개, 기존 복제 TXST 참조·해제 계약을 재검사했다. 재배치·변조·누락·중복 호출·IAT 경계는 C++ 정책 테스트로 실행했다.
- 검사와 IAT 조회는 설치 시 수행한다. 스킨 선택 때마다 EXE나 Address Library를 재검색하지 않는다.

**남은 한계:** 나머지 10개 런타임은 실제 명령어 캡처가 없다. 주소 항목 존재만으로 명령어 일치를 보장하지 않는다. 그 게임에서 검증된 패턴과 일치해야 성기 TXST 후킹이 설치되며, 다르면 해당 백엔드는 중단된다. 따라서 이 10개까지 성기 표시가 완전히 해결·검증됐다고 말할 수 없다. 해당 런타임의 합법적으로 확보한 실행 코드 검증이 추가로 필요하다.

## RaceMenu 버전

공식 저장소의 SE 1.5.97용 RM 0.4.11부터 고정 커밋 `9ebcb733e17be695f994cd2e9cc383043446bc02`까지 확인했다. 사용 인터페이스 헤더가 바뀐 모든 중간 커밋과 주요 릴리스·초기화 변경을 포함한 14개 시점에서 가상 함수 순서와 실제 호출의 인자·반환형, v2 visitor 계약 검사를 통과했다. 제품 파일 버전으로 기능을 막지 않는다.

| 실제 인터페이스 | BCNG 경로 |
| --- | --- |
| BodyMorph v4 | v4의 확인된 공통 호출 |
| BodyMorph v5 이상 | v5 공통 부분; 알 수 없는 추가 함수 호출 안 함 |
| Overlay/Override v1/v1 | 구형 전용 가상 함수·문자열·variant ABI |
| Overlay/Override v2 이상/v2 이상 | 공개 v2 wrapper의 확인된 공통 부분 |
| 얼굴 Override v1 또는 v2 이상 | 대응하는 동기 node-texture adapter; 직접 연결 불가 시 Papyrus 대안 |

v1과 v2 객체를 서로의 레이아웃으로 캐스팅하지 않는다. 미확인 상위 인터페이스는 기존 공통 부분을 유지한다는 전제하에 하위 계약을 사용한다. 계약 자체를 깨는 미래 버전·비공식 포크까지 무조건 호환된다고 보장하지 않는다. RaceMenu DLL 자체도 해당 Skyrim/SKSE 런타임용이어야 한다.

공식 근거: [RM 0.4.11 런타임 및 Scaleform 등록](https://github.com/expired6978/SKSE64Plugins/blob/8f58265b7019c162dec7a6199a20721e66398214/skee/main.cpp), [초기 AE/GOG 설정](https://github.com/expired6978/SKSE64Plugins/blob/8adc4b635ef2c6eef5befef3578ecabfb059a5ee/skee64/main.cpp), [고정 공개 인터페이스](https://github.com/expired6978/SKSE64Plugins/blob/9ebcb733e17be695f994cd2e9cc383043446bc02/skee64/IPluginInterface.h).

### 구형 오버레이 슬롯 수

구형 코드가 `skee64_custom.ini`를 누락하고 얼굴 활성화 항목의 옛 섹션만 읽던 문제를 수정했다. 소스 기본 몸 슬롯은 6이 아니라 3이며, normal 슬롯 상한은 127이다. 가능한 시점부터 HUD의 `_global.skse.plugins.NiOverride`에서 RaceMenu가 실제 공개한 얼굴/몸/손/발의 normal 슬롯 수를 읽고 값만 캐시한다. GFx 객체나 영화 포인터는 보관하지 않는다. 초기 HUD 이전에는 두 INI를 반영한 캐시를 사용하고, 실제 provider 값이 준비되면 갱신한다. v2는 자체 공개 count API를 계속 사용한다.

## NPC 배포 조건 편집

- 바디프리셋·바디스킨·후타스킨·오버레이 공통으로 팝업 편집은 임시 상태다. 틴트마스크에는 배포를 추가하지 않는다.
- 닫기·X·Esc 및 본체 UI 닫기에서는 조건 추가/편집/삭제/순서 변경을 저장하지 않는다. 기존 자동 저장 함수와 더 이상 호출되지 않는 활성 규칙 저장/조회 API를 제거했다.
- ‘로드된 NPC 즉시 배포’는 파일 저장 성공 후 활성 규칙을 바꾸고 배포한다. 파일 저장 실패 시 활성 규칙도 그대로다.
- ‘다음 게임 실행 시 배포’는 저장 규칙만 갱신하며 현재 세션의 활성 규칙을 바꾸지 않는다. 팝업을 다시 열면 마지막으로 명시 저장한 값이 보인다. 저장 이후 추가 편집을 취소해도 이미 저장한 부분은 남는다.
- 취소 때문에 종족·팩션·키워드 목록을 다시 스캔하지 않는다. 팝업의 선택 항목 스냅샷은 규칙 추가에 쓰고, 닫으면 비운다.

## 오버레이 숫자

`적용 2/14`에서 **2는 BCNG 확정 선택**, **14는 RaceMenu 해당 부위 normal 슬롯 총수에서 다른 모드가 차지한 슬롯을 뺀 수**다. 별도 `BCNG 숫자`는 삭제했다. 일반 미리보기와 기본값 복원 미리보기는 두 숫자를 바꾸지 않는다.

다른 모드가 등록한 색상·투명도만 있는 슬롯이나 투명한 문양도 BCNG가 임의로 덮어쓰면 안 되므로, 실제로 새로 사용할 수 없는 예약 슬롯은 분모에서 제외한다. 그 때문에 기본 상태의 분모가 RaceMenu 설정의 총수보다 작을 수 있지만, 다른 모드 슬롯이 BCNG 적용 숫자로 나타나지는 않는다. 사용자 사진에 보인 외부 슬롯의 구체적인 작성 모드까지 확인한 것은 아니다.
