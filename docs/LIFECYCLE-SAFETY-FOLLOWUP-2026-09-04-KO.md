## 1. 실제 업데이트 경계와 처리 예산

`FrameTaskQueue.h`는 엔진과 분리된 정책이고, `FrameTasks.cpp`가 이를 SKSE 게임 태스크에 연결한다.

- 기존 검증된 입력 poll 훅의 원본 호출 뒤에서 업데이트 tick을 알린다. 새 relocation/가상함수 슬롯/렌더 훅은 추가하지 않았다.
- 메뉴가 닫혀 있어도 입력 poll 경계가 들어오므로 자동 NPC 작업이 UI 표시 여부에 의존하지 않는다.
- 입력 훅 안에서 액터나 지오메트리를 변경하지 않는다. 실제 작업은 SKSE 게임 태스크에서 실행한다.
- 같은 SKSE FIFO 내부 재예약으로 tick을 전진시키지 않는다. Pump는 자기 자신을 재예약하지 않는다.
- 일반 모드: 한 배치 최대 액터 작업 4개, 2ms 예산. 성능 모드: 2개, 1ms 예산. 가벼운 후속 콜백을 포함해 최대 64개이며 시간 예산을 함께 적용한다.
- 시간 측정에는 실제 BCNG 콜백/native 호출 비용이 포함된다. **RaceMenu의 한 번의 큰 호출은 중간에 끊을 수 없으므로 1ms/2ms는 최대 프레임 시간 보장이 아니다.**
- 초기 배포, init/attach, 의상 이벤트, RaceMenu 복원, 바디·스킨·틴트 적용/복원, 구형 스킨 선택 경로, 전체 바디 초기화를 연결했다.
- 전체 초기화도 소유 키를 수집한 다음 액터별 작업으로 나눴다. 원래의 BCNG 소유 키 제거 범위를 유지했다.
- camera update 작업은 기존 경로를 유지했다. 카메라 수치·회전·pause 플래그/카운터를 스케줄러에서 조작하지 않는다.

우선순위는 오래 기다린 작업 보호 → 새로 나타난 액터/사용자 작업 → 해당 액터의 실제 적용 → 일반 bulk 평가 순서로 동작한다. 같은 액터의 작업 순서는 우선순위로 뒤집지 않는다. 연속된 같은 채널 요청은 최신 요청으로 병합하면서 다른 채널과의 시간 순서를 보존한다.

## 2. 액터별 비동기 수명과 취소

- 바디/의상/스킨/틴트가 같은 액터에서 겹치지 않도록 공유 작업권(lease)을 사용한다. 다른 액터까지 전역으로 막지는 않는다.
- RaceMenu Override v1의 조회 → 소유 오버라이드 삭제 → 새 적용 → 노드 갱신 콜백까지 같은 lease를 전달한다.
- 진행 중인 작업을 취소했다고 완료로 취급하지 않는다. 예약 작업은 제거하고, 실행 중 lease는 무효 표시하되 콜백이 해제될 때까지 유지한다.
- 콜백 완료/소멸의 중복 완료 방지는 이전 체크포인트의 CompleteOnce를 유지한다.
- 로드/취소된 콜백은 후속 native 호출을 하지 않으며, 불필요한 재예약도 생략한다.
- lease 해제 관측 뒤 추가 업데이트 경계를 둔다. 이는 **외부 OverlayFix 작업 완료 확인이 아닌 BCNG의 조용한 간격**이다.
- 새 의상 변경 번호는 단조 증가하므로 detach/재등록으로 같은 번호가 재사용되는 ABA 문제를 막았다.
- 3D 대기는 bounded retry로 바꿨다. 자동 NPC는 최대 100회 × 6 tick, 의상 갱신은 최대 60회 × 2 tick 재시도한다. detach/새 세션에서 제거하며 나중 attach 시 다시 시작할 수 있다.
- 저장된 선택값은 재시도 만료 때문에 삭제하지 않는다.

VM이 이미 받은 native 호출이나 다른 플러그인이 보유한 작업 자체를 취소할 수는 없다. VM이 콜백을 영원히 보유하는 비정상 상황을 임의 타임아웃으로 강제 해제하면 중복 실행을 재허용하므로 그렇게 하지 않았다. 새 세션에서는 이전 세션 작업을 무효화한다.

## 3. 로드·RaceMenu·미리보기

- PreLoadGame 및 serialization Revert에서 큐를 차단/무효화한다. PostLoadGame/NewGame에서 새 epoch를 시작한다.
- UI에도 epoch 검사와 생명주기 잠금을 추가했다. load는 사용자 확정이 아니므로 이전 UI의 pending 선택을 새 세이브에 확정하지 않는다.
- 로드 시작에 기존 presentation을 복원하고 창 닫기를 요청한다. 기존 카메라 값/우클릭 회전 코드는 변경하지 않았다.
- 정상 창 닫기·액터 변경의 확정 동작은 유지했다.
- 자동 배포와 의상 처리가 같은 액터의 활성 바디 미리보기를 덮지 않게 했다.
- 기본 바디/기본 스킨 요청을 빈 desired 항목으로 기록해, 비동기 삭제 중에 이전 applied ID가 다시 선택되는 문제를 막았다.
- default body 삭제에도 최신 작업 번호를 검사한다.
- RaceMenu가 열려 있는 동안 플레이어 지오메트리 작업을 실행하지 않는다.
- RaceMenu 닫기 후 복원/재검증은 이전 액터 작업이 끝나기를 기다린다. 복원 재검증이 진행 중인 스킨 배치를 스스로 취소하지 않게 했다. 대기는 실제 tick 기반이며 횟수 제한이 있다.
- 틴트 연속 입력도 최신 작업으로 병합한다.
- 없는 미리보기 키를 지우는 요청에서는 불필요한 전체 바디 모프 재계산을 하지 않는다.

## 4. 같은 ID의 파일 변경과 평가 비용

- BodySlide 프리셋의 내용 서명은 XML에서 읽은 family/set/성별/refit 여부/slider 이름·저/고체중 값으로 계산해 카탈로그 새로고침 때 캐시한다.
- DDS 내용은 카탈로그 등록/새로고침 때 물리 파일당 한 번 읽어 해시한다. 파일 크기·수정 시각이 같은 교체도 감지한다.
- 스킨 서명에는 부위/채널별 경로, DDS 내용, UBE·3BA·UNP·SOS·노인·종족·얼굴 detail 변형 목록을 포함한다.
- NPC 조건 평가에서는 캐시된 서명만 조회한다. XML/DDS 전체를 다시 읽거나 전체 프리셋 목록을 복제하지 않는다.
- 동일 DDS 경로의 내용이 바뀌면 새로운 texture cache alias를 사용한다. 기존 엔진 텍스처 캐시 때문에 이전 파일이 남는 문제를 피한다.
- MO2의 현재 승자뿐 아니라 스캔한 다른 provider의 내용 캐시도 해당 prefix 새로고침 시 무효화한다.
- 적용 예약 뒤 새로고침된 경우 오래된 내용이 최신 완료 기록으로 저장되지 않도록 확인한다.
- 배포/의상 규칙은 읽기 전용 snapshot을 재사용하고, UI 편집용 복사 기능은 유지한다.
- 강제 의상 이름/FormID 목록이 둘 다 비었을 때 **강제 적용용 전체 인벤토리 탐색만** 생략한다. 일반 착용 의상 판정·제외·의상별 전용 프리셋은 유지했다.
- 시작 카탈로그 스캔은 DataLoaded로 통일해 같은 DDS를 두 번 읽지 않는다.
- 자동 스킨 적용 뒤의 비싼 부위·DDS별 지오메트리 검증은 debug 모드에서만 한다. 적용 라우팅과 부분 팩 동작은 그대로다.

내용 서명 추가로 기존 완료 기록은 한 번 재평가/재적용될 수 있다. 이후 내용/규칙이 그대로면 완료 기록을 재사용한다. 64비트 저장 필드를 그대로 사용하므로 코세이브 스키마 변경은 없다.

**비용 경계:** 큰 DDS 팩의 명시적 새로고침/첫 카탈로그 스캔에는 파일 읽기 비용이 있다. 이를 일반 NPC 이벤트에 옮기지는 않았다. 새 캐시 파일은 바뀐 내용별로 생기며, 이미 세이브/엔진이 참조할 수 있는 이전 캐시를 임의로 삭제하지 않는다.

## 6. 확인되지 않은 사항과 배포 상태

- 제보자 크래시 로그·정확한 OverlayFix 바이너리·동일 환경 재현은 없다.
- OverlayFix 내부 raw node 수명 문제인지, 다른 원인인지 확정하지 않았다.
- OverlayFix 비공개 설정/메모리 패치/임의 DLL 버전 분기는 넣지 않았다. 공개 완료 API 없이 고정 tick을 외부 작업 완료 보장으로 표현하지 않는다.

- 따라서 “스터터 0”, “회귀 0”, “OverlayFix CTD 완치”를 보장하지 않는다. 확인된 BCNG 내부 문제를 수정하고 자동 검증을 통과한 상태다.
- MO2 복사, Nexus/GitHub 업로드, 배포/소스 ZIP 재생성은 아직 하지 않았다.
