## 확인한 증거

- 단일 DLL 정리 뒤 사용자는 몸·손·발 및 스킨 목록 소실이 재현되지 않는다고 보고했다.
- 01:52:30 이후 플레이어 `00000014`의 Native TXST 변경 로그가 반복되지만
  `Actor.QueueNiNodeUpdate` 호출 로그는 없다.
- 기존 `RefreshLoadedActors`는 `ProcessLists::ForAllActors`의 NPC 목록만 순회했다.
  선택한 플레이어가 그 목록에 없으면 변경 콜백을 전혀 호출하지 않는다.
- 오버레이 교체는 이전 값을 제거할 때 RaceMenu의 비동기 RevertOverlay를 예약하고,
  새 값은 즉시 적용했다. 구버전 RaceMenu의 AddOverlays도 비동기로 노드를 생성한다.
  이 순서는 새 페인트가 초기화되거나 노드 생성 전에 적용을 시도할 수 있다.
- RaceMenu 원본 `87a5cad:skee/OverrideInterface.cpp`, `OverlayInterface.cpp`의
  해당 함수와 `OverrideInterface.h`의 ApplyNodeOverrides 가상 함수 순서를 대조했다.

## 변경

- 선택 액터를 먼저 갱신하고, 같은 ActorBase의 로드된 다른 액터를 중복 없이 갱신한다.
  플레이어/NPC 모두 기존 Native TXST → 단일 QueueNiNodeUpdate 경로를 사용한다.
- 오버레이는 저장할 값을 먼저 등록하고, 다음 입력 틱에서 정확한 페인트 노드를
  다시 찾아 RaceMenu ApplyNodeOverrides로 텍스처·색·투명도를 함께 적용한다.
  v1/v2 각각의 인터페이스로 호출한다. 일반 바디스킨 경로에는 영향을 주지 않는다.
- 지연 작업은 액터 핸들과 노드 이름만 보관한다. Geometry 포인터를 보관하지 않으며,
  세션 및 선택 교체 시 기존 작업 lease가 취소된다.
- 같은 저장값이라도 실제 노드의 텍스처/투명도가 다르면 적용을 생략하지 않는다.
- 후속 로그는 저장값 일치, Geometry 존재, 라이브 텍스처 일치, alpha와 diffuse를
  별도로 기록하고 flush한다. 최초 오버레이 선택이 안 보인 원인은 이전 로그가
  끝까지 남지 않아 확정하지 못했다. 새 로그에서 확인해야 한다.
