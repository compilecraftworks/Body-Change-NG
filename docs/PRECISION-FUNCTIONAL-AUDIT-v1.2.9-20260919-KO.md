# Body Change NG 1.2.9 — 전체 기능 정밀 재검사

검사일: 2026-09-19. 제품 기준 커밋: `747de9b06bac5a7c74525cd5bf9a554cd932e6cd`.

후속 상태: 이 문서는 수정 전 1.2.9의 검사 기록이다. 확인된 세 결함은 후속 1.3.0 작업에서 수정했으며 [수정 및 회귀 검증](RELEASE-VERIFICATION-v1.3.0-KO.md)을 참고한다. 아래의 “이번 요청”은 최초 검사 시점을 뜻한다.

## 결론

**기존 회귀 검사는 모두 통과했지만, 기능 간 연결에서 추가 수정이 필요한 3개 경로를 확인했다.** 개별 테스트 통과를 전체 기능 무결점으로 해석하면 안 된다.

1. 미로드 상태에서 복수 선택한 오버레이의 첫 복원에서 슬롯이 중복 배정된다.
2. 기본 바디에 독립적으로 적용된 의상 보정을 바디 상태 불일치로 오인하여 제거할 수 있다.
3. 스킨 미리보기 취소 작업은 RaceMenu가 열렸을 때의 플레이어 작업 차단을 우회한다.

이번 요청은 검사이므로 **제품 소스·DLL·버전·배포 ZIP·MO2·GitHub를 변경하지 않았다.** 진단용 코드와 이 보고서만 추가했다. 게임 실행, 실행 중 게임 메모리 접근, 세이브 조작도 하지 않았다.

### 확인 수준

- 아래 세 항목의 **문제 분기**는 제품 함수 본문을 그대로 추출하여 오프라인 실행했다. 엔진/VM/노드 경계는 가짜 구현이다.
- 오버레이의 같은 슬롯 선택, 기본 바디 검증의 Default 정리 예약, actor-0 작업의 RaceMenu 차단 우회는 실행으로 확인했다.
- 그 이후의 실제 화면, 목선·검은색·보라색, CTD, 실제 RaceMenu co-save는 재현한 것이 아니다. 이 항목들을 과거 제보의 확정 원인이라고 단정하지 않는다.
- 변경점만이 아니라 아래 전체 기능군의 정책 테스트와 실제 호출 연결을 대조했다. 모든 엔진 호출과 모든 모드 조합을 실행했다는 뜻은 아니다.

## 1. 미배정 복수 오버레이가 같은 슬롯으로 복원됨 — P2

관련 코드:

- `src/BodyChangeNG/RaceMenuOverlay.cpp:1103` 부근: 미로드 액터의 수동 확정은 `kNoOwnedSlot`인 선택 의도를 저장한다.
- `src/BodyChangeNG/RaceMenuOverlay.cpp:1437`: `QueueReapplySaved`가 저장 항목들을 한 작업 안에서 순회한다.
- `src/BodyChangeNG/RaceMenuOverlay.cpp:663`: `ApplyNow`는 기존 슬롯이 없으면 빈 슬롯을 탐색한다.
- `src/BodyChangeNG/RaceMenuOverlay.cpp:494`: 실제 노드 속성 쓰기는 `FinalizeNodeProperties`가 다음 틱으로 지연한다.

발생 경로:

1. 아직 3D가 로드되지 않은 NPC에게 같은 부위의 오버레이를 둘 이상 확정한다.
2. 각 선택에는 텍스처·색상이 저장되지만 아직 물리 슬롯이 없어 `ownedSlot=255`다.
3. NPC 등장 시 `QueueReapplySaved`가 여러 항목을 연속으로 `ApplyNow`에 전달한다.
4. 첫 항목이 고른 슬롯은 다음 틱까지 실제 점유되지 않는다. 복원 루프는 `reserved` 목록도 전달하지 않는다.
5. 뒤 항목들도 그 슬롯을 빈 슬롯으로 판단한다.

오프라인 관측:

| 조건 | 요청 3개의 슬롯 |
| --- | --- |
| 저장된 슬롯이 모두 미배정 | **0, 0, 0** |
| 기존 소유 슬롯이 0/1/2로 배정됨 | 0, 1, 2 |
| 체크박스 배치 미리보기처럼 예약 목록 전달 | 0, 1, 2 |

제품 finalizer는 이전/새 텍스처 소유권을 확인한다. 첫 텍스처가 점유하면 다른 텍스처의 뒤 요청은 충돌로 종료하는 경로다. 따라서 **복수 선택 중 일부만 보이는 문제**로 이어질 수 있다. 일반적인 기존 슬롯 재적용이나 체크박스 누적 미리보기 자체를 같은 결함으로 판단하지 않는다.

권장 수정 범위: 복원 작업 내부에서 선택한 슬롯을 후속 항목에 예약 전달하거나, 항목을 완료 순서로 진행한다. 외부 모드의 슬롯 소유권 검사를 제거해서 해결하면 안 된다. 항목별 실패·부족 슬롯·기존 소유 슬롯과 새 슬롯이 섞인 경우도 회귀 검사해야 한다.

## 2. 기본 바디 검증이 의상 보정을 지우는 경로 — P2

관련 코드:

- `src/BodyChangeNG/OutfitRefit.cpp:186`: 지원 계열·장비 조건이면 바디 프리셋 선택이 없어도 보정 계획을 만들 수 있다.
- `src/BodyChangeNG/RaceMenuBodyMorph.cpp:593`: 기본 프리셋 키가 없어도 절차형 보정값을 생성한다.
- `src/BodyChangeNG/RaceMenuBodyMorph.cpp:734`: 기본 바디 일치 판정에 의상 보정 키까지 포함한다.
- `src/BodyChangeNG/RaceMenuBodyMorph.cpp:759`: `QueueVerifySavedBody`가 이 불일치를 보면 전체 Default 정리를 예약한다.
- `src/BodyChangeNG/RaceMenuBodyMorph.cpp:1028`: Default 정리는 보정 키도 지운다.
- `src/BodyChangeNG/ActorRegistry.cpp:730`, `:761`: 기본 바디 완료 기록은 기존 의상 보정 signature를 무효화하지 않으며, 이후 보정 판단은 signature를 사용한다.

발생 조건은 **기본 바디 선택이 저장된 액터 + 지원 계열의 활성 의상 보정 + 이후 NiNode 갱신**이다. CBBE/3BA 또는 BHUNP/UNP에서 가능하며, 기본적으로 보정 대상이 아닌 UBE에 동일하게 일반화하지 않는다.

오프라인 검사에서 기본 바디에 아무 키도 없으면 정상으로 판정했다. `BodyChangeNGOutfit`에 해당하는 보정 키 하나만 추가하면 불일치로 바뀌고, 실제 제품 `QueueVerifySavedBody`가 Default 정리를 예약했다.

**영향:** 가슴·유두 보정이 풀릴 수 있다. 또한 정리 뒤에도 기존 보정 signature가 유지되므로, 같은 장비/설정 판단에서는 재적용을 생략할 수 있다. 보정 수식이 틀려서가 아니라 **기본 바디 복구와 의상 보정의 책임이 섞인 문제**다. 실제 이벤트 발생 빈도나 화면상 반복 양상은 인게임 측정하지 않았다.

권장 수정 범위: 기본 바디의 기준 키와 독립적인 보정 키를 구분한다. 명시적인 전체 초기화/삭제 준비는 여전히 소유 보정까지 제거해야 하므로, 기본 바디의 자동 검증만 조정하거나 해당 정리 후 정상 보정 정책을 재평가해야 한다. 보정 signature만 무작정 지워 상시 재적용시키는 우회는 피한다.

## 3. 스킨 취소의 RaceMenu 플레이어 보호 누락 — P2

관련 코드:

- `src/BodyChangeNG/UI.cpp:1632`: 미리보기 취소에 `restore` 모드를 전달한다.
- `src/BodyChangeNG/NativeSkinBackend.cpp:1426`, `:1499`: 이 복원 작업은 언로드 취소에 살아남도록 `actor=0`, 일반 채널로 예약된다.
- `src/BodyChangeNG/ActorEvents.cpp:355`: RaceMenu가 열리면 플레이어 ID의 작업을 취소한다.
- `src/BodyChangeNG/FrameTasks.cpp:20`: Pump의 RaceMenu 보호는 `job.actor == playerID`에만 적용된다.
- `src/BodyChangeNG/NativeSkinBackend.cpp:1107`, `:1267`: 실제 Apply/Clear는 ActorBase·세대 검사는 하지만 별도의 RaceMenu-open 검사는 없다.

미리보기 취소를 예약한 뒤 실행 전에 RaceMenu가 열리는 순서라면, 해당 작업은 플레이어 ID 취소와 Pump의 메뉴 보호를 모두 우회한다. 제품 Pump 재현에서도 일반 플레이어 작업은 실행되지 않았지만 actor-0 복원 역할의 작업은 실행됐다. `CancelActor(playerID)`를 먼저 호출한 대조에서도 동일했다.

**확인된 결함은 보호 경계 누락이다.** 이후 native 경로는 private form 복원/변경과 3D 갱신을 요청할 수 있다. 얼굴 쪽 rebuild 관찰에는 별도 RaceMenu 대기가 있지만, 이미 앞서 실행되는 바디 변경을 막는 것은 아니다. 실제 CTD나 스킨 손상을 재현했다고 주장하지 않는다.

권장 수정 범위: 액터 언로드에는 살아남는 복원을 유지하되, RaceMenu 중 플레이어 변경은 보류하고 닫힌 뒤 최신 세대만 복원한다. 단순히 플레이어 ID 작업으로 되돌리거나 취소 작업을 버리면 1.2.9에서 고친 미로드 복원 누락이 재발할 수 있다.

## 누수·성능 및 남은 통합 검증 경계

1. **실제 private ARMO/ARMA/TXST 수명:** 외부 제공자가 raw pointer를 보유할 수 있어 공개한 그래프 일부를 계속 보존한다. 동일 원본의 팩 전환은 재사용하지만 제공자/종족 교체 반복의 누적 가능성은 남는다. 이번 호스트 할당 0 결과로 이것까지 해결됐다고 하지 않는다. 강제 해제는 dangling pointer 회귀를 만들 수 있다.
2. **콜백 수명:** 제품 내부는 완료/포기 시 재시도와 capture를 정리하지만 VM이 보유한 callback 객체를 강제로 회수할 수는 없다. 이는 실제 엔진 관찰이 필요한 범위다.
3. **미리보기 중 자동 저장:** BCNG 확정 기록과 RaceMenu 임시 morph/overlay 등록의 co-save 타이밍은 단위 codec 검사만으로 증명되지 않는다. 실제 저장 후 재로드까지 확인하기 전에는 ‘어느 시점에서 저장해도 임시 외형이 절대 남지 않는다’고 보증하지 않는다.
4. **최악 지연:** 작업 큐의 시간/개수 예산은 있으나 개별 RaceMenu native 호출을 중간에 선점할 수 없다. 원거리 검색의 최초 form ID 수집도 한 번의 잠금 구간이므로 대형 환경의 일시 지연 가능성은 남는다. 매 프레임 전체 폼/DDs를 순회하는 구조로 바뀐 것은 아니다.
5. **ORefit 등록:** 시작 시 JSON을 자동 읽지 않고 버튼으로 등록하는 현재 정책을 확인했다. 이는 코드에 명시된 동작이므로 이번 검사에서 새 저장 결함으로 분류하지 않았다.
