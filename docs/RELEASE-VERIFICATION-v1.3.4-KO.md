# Body Change NG v1.3.4 검증 기록

## 변경 범위

- 이 문서의 초기 오버레이·배포 검증 뒤 같은 미배포 1.3.4에 모프 계산·UBE 보정·대소문자 식별 변경을 통합했다. 최종 통합 결과는 아래 마지막 절과 `MORPH-PARITY-AUDIT-2026-09-25-KO.md`를 함께 참고한다.
- 오버레이 변경은 `OverlayPolicy.h::CanClaimNode`의 해제된 라이브 텍스처 판정으로 한정했다. 이후 요청에 따라 공통 배포 헤더와 UBE 바디 프리셋 후보 필터도 수정했다.
- 정확한 `actors\character\slavetats\blank.dds`만 추가로 허용한다. 대소문자, 슬래시와 `Textures/`, `Data/Textures/` 접두사는 기존 리소스 정규화로 처리한다.
- `NodeIsFree`의 8개 등록 텍스처, 색상·투명도 차단과 1인칭/3인칭 검사, 실제 적용 직전 재확인은 유지했다. 등록 값이 남은 슬롯은 여전히 재사용하지 않는다.
- `StoredPathsMatch` 등 기존 소유권 비교에서는 SlaveTats 빈 텍스처 예외를 사용하지 않는다. 실제 문신·투명 문신·다른 폴더의 동명 텍스처를 가져오지 않는다.
- 의존성 핀, SE/AE 전용 빌드, 지원 런타임, RaceMenu v1/v2 ABI, 저장 형식, 외부 모드 기록과 설정은 변경하지 않았다.

## 근거와 회귀 검사

- 설치된 SlaveTats NG 0.8.1의 `SlaveTatsNG.ini`는 빈 슬롯 정리에 위 경로를 기본 사용한다고 명시한다.
- 설치된 SlaveTats 소스의 `clear_overlay`는 빈 텍스처를 설정한 뒤 등록된 텍스처·색상·투명도 항목을 제거한다. 이때 라이브 재질에는 빈 DDS가 남을 수 있다.
- 이전 함수로 얼굴 기본 텍스처 5칸은 0/5, 몸·손·발의 SlaveTats 빈 텍스처는 실제 슬롯이 있어도 0/0이 되는 조건을 오프라인 재현했다. 제보자의 실제 세이브를 재현했다는 뜻은 아니다.
- 새 회귀 검사는 4개 부위, 용량 0/1/3/5/127/254, 경로 정규화, 등록 항목 보존, 실제 문신, 동명 다른 파일, 서로 다른 1/3인칭 상태를 포함한다.
- 체크박스 누적 미리보기, 색상·저장 복원, 지연 작업 소유권, 런타임 레이아웃과 새 배포 후보 검사를 포함한 오프라인 실행 파일 37개가 모두 통과했다.
- `xmake build -y -j 8 -a` Release 빌드 통과. DLL 버전은 1.3.4.0이다.

## 변경 함수의 할당 검사

기존 `tests/OfflineAllocationMeter.h`를 사용하는 별도 오프라인 실행 파일에서 실제 제품 함수를 호출했다. 계측기 양성 대조군(1024바이트 할당·해제)도 통과했다.

- 6개 경로 × 등록 있음/없음 × 100,000회 = 1,200,000회 호출.
- 허용 결과 400,000개, 잔존 할당 블록 0개, 잔존 요청 바이트 0.
- 순간 추가 요청 바이트 최대 64, 해당 PC 실행 시간 84ms.
- 엔진/GPU 할당이나 인게임 전체 누수 측정이 아니다. 새로운 영구 컨테이너·콜백·폴링·파일 캐시는 없다.

## UBE 배포 제보 — 원인과 수정

두 제보 이미지를 브라우저에서 확인했다. 일반 액터 목록에는 UBE 프리셋이 있으며, UBE를 선택한 NPC 배포 체크박스 목록에는 미분류 항목 두 개만 남는다.

- `UI.cpp::BodyItems`의 일반 목록은 선택 액터의 감지된 바디 계열을 사용한다.
- 기존 배포 체크박스 목록은 설정의 배포 바디 계열을 사용하지만, 그 전에 UBE 비트가 있는 프리셋을 무조건 제외했다.
- `Distribution.cpp::CompatiblePresetPoolIds`에도 같은 UBE 제외가 있었다. 두 곳의 무조건 제외를 함께 제거했다.
- 선택 액터의 바디 계열은 배포 후보의 미리보기 호환성에도 별도로 사용한다. 따라서 이번 스크린샷의 목록 누락을 “선택 NPC가 UBE가 아니어서 의도적으로 숨김”으로 설명하면 부정확하다.
- 현재 성별별 글로벌 바디 타입 하나를 고르는 설정은 여러 바디 계열 NPC에 대한 동시 분리 배포 기능과 같지 않다. 이 기능을 확장할 경우 실제 액터 호환성, 바디·스킨 후보, 미리보기와 저장된 규칙을 함께 검증해야 한다.
- 자동 프리셋 후보는 설정 계열과 수신 액터의 실제 확인된 계열로 모두 검사한다. 적용 단계에서 거부될 잘못된 계열을 미리 선택·기록하지 않도록 한 것이다. 계열을 알 수 없는 액터의 기존 처리 및 성별 검사는 유지했다.
- 후보 전체를 `Find`로 읽어 슬라이더를 복사하던 반복 대신 기존 `CompatibleIds`를 사용한다. 액터 계열 판정은 후보 묶음당 한 번이며, 계열이 같거나 미확인이면 두 번째 필터도 생략한다.
- 스킨·후타의 기존 자동 배포 제한은 변경하지 않았다. 이 수정이 해당 기능의 UBE 자동 배포까지 확장하는 것은 아니다.

## 배포 헤더와 추가 회귀 검사

- 공통 `Draw` 헤더에서 체크박스 선택 중 또는 조건 팝업이 열린 동안 액터 드롭다운·새로고침을 안내문으로 교체했다. 바디·스킨·후타·오버레이 모두 같은 분기를 쓴다.
- 기존 취소·팝업 닫기·탭 전환·세션 초기화의 상태 변경 경로는 수정하지 않았다. 안내문은 기존 플래그를 읽기만 한다. 내부 미리보기 액터와 후보·색상·저장 상태를 새로 만들거나 지우지 않는다.
- `FittedDisabledLine`에 선택적인 폭 인자를 추가하고 오른쪽 두 버튼의 폭을 제외한 영역에 안내문을 그린다. 기본 인자는 이전 동작이며 새 폰트 크기를 만들지 않고 기존 글리프 정점만 축소한다.
- 실제 ImGui로 3개 언어 문구, 3개 창 폭, 4개 배율의 36개 배치 조합을 검사했다. 한 줄 높이·다음 버튼과의 겹침 방지·폰트 개수 보존을 확인했다. 테스트 기본 폰트의 한중 글리프는 대체 글리프이므로 실제 한중 폰트 모양의 인게임 검증은 아니다.
- 새 `DistributionPresetTests`는 제품의 `BodyItems`, `DistributionCatalogFamily`, `CompatiblePresetPoolIds`를 빌드 시 추출해 실행한다. 실제 XML 파서·프리셋 목록·계열 필터를 사용하며 액터/RaceMenu 경계만 대체한다.
- UBE·3BA·UNP·HIMBO·SAM·미분류, UBE Zeroed, 다른 계열 미리보기 차단, 누락 프리셋, null/베이스 없는 액터, 1,000회 목록 전환에서 후보 결과와 불변 목록 포인터 보존을 확인했다.

## 한계 및 배포 상태

초기 오버레이 제보자의 세이브는 확인하지 않았다. 빈 텍스처를 쓰더라도 아직 등록 값이 있거나 실제 문신이 모든 슬롯을 점유했다면 0/0은 계속 표시될 수 있다. 등록 정보를 강제로 삭제하는 우회는 넣지 않았다.

배포본은 `scripts/Package-Release.ps1`로 커밋된 소스에서 작성한다. 릴리즈 ZIP은 런타임·필수 경로 안내·기존 선택적 도구·라이선스의 11개 파일로 제한하고 PDB를 제외한다. 소스 ZIP에는 빌드에 필요한 의존성 소스와 커밋 식별자를 포함하며 각 ZIP의 파일별 SHA-256과 목록을 원본과 대조한다. 산출물은 저장소 `release` 루트에 둔다. MO2 교체와 GitHub Release 페이지 게시는 이번 배포 요청에 포함하지 않았다.

## 2026-09-25 최종 1.3.4 통합 검증

- 사용자가 아직 1.3.4를 배포하지 않았음을 확인하여 버전을 올리지 않고 기존 1.3.4의 변경 내역·소개글·ZIP에 모든 후속 작업을 합쳤다.
- 모프 기준 계산, UBE/Necoco 가산 보정 및 다른 모프 보존의 상세 수치와 출처는 별도 모프 감사 기록에 있다. 시험 중 폐기한 27개 상쇄 보정은 최종 DLL에 포함하지 않는다.
- 에셋 ID·DDS 경로의 대소문자 비구분, 게임 문자열 재사용 시 TXST 기록 판정, 즐겨찾기·색상 초안·복원·동일 스킨 서명은 기존 소유권·예약·경로 안전성 검사를 보존한다.
- `xmake build -y -j 8 -a` 통과. 오프라인 회귀 실행 파일 38개를 최종 트리에서 전부 재실행하여 통과했다. 문서 테마 검사 136개 밝음/어두움 대비 조합과 배포 작성 PowerShell 검사도 통과했다. `git diff --check` 통과.
- 최종 DLL 1.3.4.0 SHA-256: `D15C3CB71B4085848F381A57E23C3A59A6567CBA916068C3EB1C9B2A431E6C69`.
- 위 DLL은 두부팩 MO2의 설치 DLL과 해시가 동일하다. 사용자가 해당 빌드의 인게임 테스트가 정상이라고 보고했다. 테스트의 세부 시나리오 전부나 모든 지원 게임/RaceMenu 조합을 재현·검증했다는 뜻은 아니다.

- 최신 소개글은 `NEXUS-DESCRIPTION-v1.3.4-EN.bbcode`, `NEXUS-DESCRIPTION-v1.3.4-KO.html`이며 Markdown 원문과 한영 변경 내역도 함께 갱신했다. 전체 경로, 이름 기반 JSON 가이드, UBE 배포와 스킨 배포 제한 차이, UBE 체중/생략값, SFS·ORefit 보정 범위를 반영했다.
