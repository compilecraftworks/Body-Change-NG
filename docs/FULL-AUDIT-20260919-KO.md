- 이번 점검에서 제품 소스는 추가 변경하지 않았다. `tests/CatalogPerformanceProbe.cpp`에 오프라인 진단을 추가했고 이 보고서를 작성했다.

## 수정이 필요한 확인 사항

### A. 일반 전체 초기화에서 공유 NPC 베이스의 얼굴 복원이 누락될 수 있음

**우선순위: P2 / 코드 및 정책 재현 확인.** 몸의 공유 상태와 각 액터의 얼굴 상태를 같은 요청 세대로 취급하는 문제다.

근거:

- `ActorSettingsReset.cpp:52`의 `QueueAll`은 액터마다 초기화를 예약한다.
- `NativeSkinBackend.cpp:1408`의 `QueueClear`는 같은 ActorBase의 `generation`을 액터마다 증가시킨다.
- `NativeSkinBackend.cpp:1228`의 `ClearNow`는 일반 모드에서 최신 세대가 아닌 요청을 **얼굴 복원 전에** 반환한다.
- 삭제 준비 모드에서는 예외를 두어 각 액터의 얼굴을 복원하지만, 일반 전체 초기화에는 그 예외가 없다.

동일 베이스를 공유하는 로드된 액터 여러 명의 Default 요청이 모두 실행 전에 수락된 경우를 정책으로 재현했다. 2명에서는 1명, 32명에서는 1명만 `ClearNow`의 얼굴 복원 지점에 도달한다. 다른 공유 소유자의 요청이 먼저 거부되는 경우도 있어 실제 결과는 요청 순서에 영향을 받는다.

영향: 공유 몸은 기본값인데 일부 액터의 얼굴 NiOverride는 남을 수 있다. 즉시 모든 액터가 다시 정상화된다고 보장할 수 없다. 후속 로드·갱신이 복구할 가능성과 별개로 초기화 한 번의 처리가 불완전하다.

수정 방향: 베이스 단위 몸 복원과 참조 단위 얼굴 복원을 분리한다. 단순히 모든 오래된 요청을 허용하면 새 스킨 선택을 뒤집을 수 있으므로, 현재 Default 의도와 액터별 취소 조건은 유지해야 한다.

### B. NPC가 언로드된 뒤 미리보기를 취소하면 임시 바디 모프가 남을 수 있음

**우선순위: P2 / 코드 경로 확인.**

- `RaceMenuBodyMorph.cpp:291`의 `ClearPreviewNow`는 `Is3DLoaded()`가 거짓이면 미리보기 모프 키를 지우기 전에 반환한다.
- `QueueCancelPreview`는 먼저 미리보기 소유자 추적을 해제한다. 이후 정리가 위 조건으로 반환하면 재시도 대상도 사라진다.
- 셀 이탈 시 작업 취소와 `ForgetActorState`는 임시 모프 키 자체를 제거하지 않는다.
- 나중에 다시 로드돼도 저장된 BCNG 프리셋이나 적용할 규칙이 없는 액터는 프리셋 재적용을 통해 정리될 것이라고 기대할 수 없다.

재현 조건: 유효한 액터 참조는 남아 있지만 3D가 사라진 상태에서, 이미 적용된 바디 미리보기를 취소한다. 게임 일시정지를 끈 상태의 NPC 미리보기 등에서 검증할 필요가 있다.

수정 방향: 유효한 참조의 저장된 미리보기 키 삭제와, 로드된 3D의 시각 갱신 조건을 분리한다. 키를 지우려고 셀이나 액터 3D를 강제로 로드해서는 안 된다. 이 점검만으로 해당 임시 키가 실제 세이브에 어떻게 남는지까지 실증한 것은 아니다.

### C. 오버레이 색상 팝업의 취소 키가 본체 UI까지 닫음

**우선순위: P2 / 코드 경로 확인.**

- `UI.cpp:4028`에서 본체가 취소 입력을 처리하기 전 검사하는 목록에 `g_showOverlayDetails`가 빠져 있다.
- 틴트·설정·배포·의상 팝업은 검사하지만 오버레이 색상 팝업은 검사하지 않는다.
- 따라서 `UI.cpp:3061`의 오버레이 팝업 취소 처리가 실행되기 전에 본체가 입력을 소비하고 닫힌다.
- `EscapePressed`는 Esc뿐 아니라 매핑된 키보드·게임패드 Cancel도 포함한다.

수정 방향: 최상위 팝업이 먼저 취소 입력을 소비하도록 통일하고, 본체 취소 처리에서는 오버레이 색상 팝업도 제외한다. 본체 종료에 따라 미리보기 세션이 끝나는 부수 효과도 함께 회귀 검사해야 한다.

### D. 바디스킨·후타스킨·틴트 목록의 매 프레임 복사 및 화면 밖 행 처리

**우선순위: P2 / 코드 확인 및 합성 성능 측정.**

- 바디프리셋은 표시용 스냅샷과 클리퍼를 사용하고, 오버레이도 클리퍼를 사용한다.
- 바디스킨의 `SkinProfiles::Snapshot()`은 DDS 경로·종족별 레이어를 포함한 전체 값을 복사한다. 후타스킨과 틴트 목록에도 값 복사 경로가 있다.
- 해당 세 목록은 화면 밖 행도 순회하며 행을 구성한다.
- 특히 `UI.cpp:2128`에서는 스킨별 DDS 경로 집합을 매 프레임 다시 만들어 텍스처 개수를 센다.

이는 **DDS 이미지 전체를 매 프레임 읽는다는 뜻이 아니다.** 경로 문자열, 벡터, 해시 집합, 행 구성에 드는 CPU 작업이다.

실제 제품 자료형을 사용한 합성 측정의 중앙값:

| 합성 팩 수 | 스킨 목록 복사 | 복사 + 전체 경로 수 집계 | 후타 목록 복사 | 틴트 목록 복사 |
| ---: | ---: | ---: | ---: | ---: |
| 25 | 0.1184 ms | 0.3984 ms | 0.0052 ms | 0.0951 ms |
| 100 | 0.4314 ms | 1.4290 ms | 0.0177 ms | 0.3783 ms |
| 500 | 2.5133 ms | 7.6466 ms | 0.1044 ms | 1.7289 ms |
| 1,000 | 4.6802 ms | 15.3526 ms | 0.2147 ms | 3.2114 ms |

합성 카탈로그는 각 스킨에 여러 부위·종족별 레이어를 넣었고, 틴트는 팩당 15개 항목이다. 서로 다른 탭의 비용을 합산하면 안 된다. 디스크·GPU·실제 UI 전체 비용은 포함하지 않았으며, 설치 모드 수와 스킨팩 수는 동일하지 않다. 이 수치를 특정 사용자 환경의 FPS나 클릭 불가 원인으로 단정할 수 없다.

수정 방향: 새로고침 시 불변 표시 스냅샷·텍스처 개수를 생성하고, 실제 적용 시 필요한 팩만 얻는다. 세 목록에 클리퍼를 적용하되 키보드 포커스 행, 체크박스 누적 미리보기, 색상 편집을 제외시키지 않아야 한다.

### E. 삭제 준비에서 공유 베이스의 몸 갱신 요청이 중복됨

**우선순위: P2 / 코드 및 정책 재현 확인.**

- 삭제 준비에서는 각 액터의 얼굴을 빠짐없이 복원하려고 같은 베이스의 `ClearNow`를 모두 실행한다.
- 각 실행은 `RefreshLoadedActors`로 같은 베이스의 로드된 액터들을 다시 순회한다.
- `SkinRefreshTargets.h`의 중복 제거는 한 번의 호출 안에서만 동작한다.

같은 베이스의 로드된 액터 32명을 정리하는 정책 재현에서 갱신 콜백 요청은 1,024회 발생했다. **실제 `DoReset3D`가 반드시 1,024회 실행된다는 뜻은 아니다.** 얼굴 재생성 게이트가 일부를 합칠 수 있지만 순회·요청·세대 갱신 비용은 남는다. 작업 큐의 시간 예산도 실행 중인 단일 콜백을 중간에 나누지는 못한다.

수정 방향: 배치에서 몸 복원·공유 베이스 갱신은 중복 제거하고, 얼굴 복원은 참조별로 유지한다. A 항목의 누락을 막으면서 함께 해결해야 한다.

### F. 장기 플레이의 액터 기록 증가와 저장 상한 도달 시 일부 선택 누락

**우선순위: P2 / 낮은 빈도의 경계 조건, 코드 확인.**

- `Distribution.cpp:1030` 부근은 조건에 맞는 새 선택이 없어도 `SetRuleSelection`을 호출한다.
- `ActorRegistry.cpp:665`는 그때 `EnsureLocked`로 레코드를 만든다.
- 레지스트리는 셀 이탈마다 지우는 구조가 아니며, 실제 사용자 선택이 없는 기록도 장기간 누적될 수 있다.
- `SaveState`는 16,384개를 넘으면 `SnapshotAll()` 결과를 잘라 저장한다. 이 스냅샷은 `unordered_map` 순회 순서이며 수동 선택·복원 필요 기록 우선순위가 없다.

**저장 개수 제한은 이미 있으며, 제한을 초과한 파일 전체를 저장했다가 로더가 전부 버리는 구조는 아니다.** 문제는 제한 안에 남길 레코드를 임의 순서로 골라 일부 중요한 선택을 저장에서 제외할 수 있다는 점이다. 로그 경고는 있지만 사용자 선택을 보존하는 정책은 없다. 실제 사용자 세이브가 상한에 도달했다는 증거는 없다.

수정 방향: 아무 선택·복원 의도도 없는 신규 기록 생성을 줄이고, 미로딩 액터의 유효한 선택 및 Default 의도는 보존한다. 상한 처리에서도 중요한 기록을 조용히 버리지 않도록 별도 정책과 왕복 저장 테스트가 필요하다. 단순히 언로드된 액터 기록을 전부 지우는 것은 배포·저장 회귀다.

## 추가 검증이 필요한 위험 — 확정 누수·실제 장애로 단정하지 않음

### G. 얼굴 VM 호출이 응답하지 않는 경우의 복구 경로

`FaceSkinOverrides.cpp:275`의 `Batch::Call`은 `DispatchStaticCall`의 즉시 실패를 처리하지만, 호출이 수락된 후 콜백이 오지 않는 경우의 시간 제한은 없다. 이때 `running`이 유지되므로 같은 액터의 다음 얼굴 작업이 대기한다.

대부분의 정상 네이티브 얼굴 경로와는 구분해야 한다. 이 위험은 VM 대체 경로, 이전 얼굴 노드 정리, 언로드된 액터의 저장 오버라이드 복원에 관련된다. 3D 재생성 게이트에는 별도의 타임아웃이 있지만 VM 배치 타임아웃을 대신하지는 않는다.

삭제 준비의 2분 확인 제한은 완료로 오판하지 않고 `incomplete`를 표시한다는 점에서 안전하다. 다만 `running`은 해제하지 않으므로 콜백이 끝내 오지 않으면 재시도·재개도 막힐 수 있다. 세션 초기화/해당 요청 폐기 외 회복을 검증해야 한다.

권장 검증: 수락 후 콜백 누락·지연·시간 제한 후 늦은 콜백을 각각 주입한다. 단순 타임아웃 후 다음 쓰기를 시작하면 늦은 이전 쓰기와 겹칠 수 있으므로 세대·소유권과 원상 복원을 같이 설계해야 한다.

### H. 스킨 복제 폼의 실패·재생성 시 수명 관리

`NativeSkinBackend.cpp:486`의 `CloneArmorGraph`에는 ARMO/ARMA/TXST 복제 뒤 실패 반환 경로가 있고, `ApplyNow`의 소스 교체에서는 기존 인스턴스를 비우고 새 그래프를 만든다. BCNG가 해당 복제 폼들을 별도 회수하거나 실패한 빌드에서 되돌리는 경로는 확인하지 못했다.

이것을 정상 스킨 전환마다 발생하는 확정 메모리 누수로 표현하면 안 된다. 정상 경로는 그래프를 재사용하고, 폼의 엔진 소유·회수 수명 및 TNG의 외부 참조가 개입한다. 실패 반복·소스 교체 반복 시 할당 수와 생존 폼을 계측해야 한다.

수정 전 반드시 구분할 것: 아직 공개하지 않은 실패한 임시 복제물과, 이미 TNG 또는 게임이 참조할 수 있는 이전 그래프. 후자를 무조건 해제하면 use-after-free 위험이 있다. 캐시 DDS의 과거 해시 파일 보존도 메모리 누수와 다르며 기존 세이브 때문에 임의 삭제하면 안 된다.
