# Body Change NG 1.3.1 — 안전한 캐시 정리 검증

검사일: 2026-09-20. 비교 기준: 1.3.0 (`0b259c99924751f45133661b9eca20653275d371`).

## 범위와 보존 정책

- 사용자가 승인한 **DDS 경로 보존 방식**이다. 모든 세이브를 분석해 미사용 DDS를 삭제하는 기능은 아니다. 1.2.7의 고유 캐시와 예전 세이브가 참조할 수 있는 경로는 유지한다.
- 별도 `Tools\BodyChangeNGCache.exe`를 게임 종료 후 직접 실행한다. MO2를 통해 실행하지 않는다. 먼저 읽기 전용 검사 후 확인하며 기본 답은 No이다. 명령행 `--scan`은 읽기 전용, `--compact`는 명시적 변경이다.
- 내용·수정 시각이 동일한 사본만 하드링크로 합친다. 파일 크기, SHA-256, 전체 바이트를 비교하며 변경 직전 파일 ID·크기·시각을 재확인한다. 같은 캐시 내부에 모든 링크가 있는 파일만 대상으로 하여 원본 팩의 변경과 새 공유 사본을 연결하지 않는다.
- 원본 팩, 읽기 전용 파일, 작업을 막는 잠금, 외부 링크, 리파스 지점, 알 수 없는 폴더 구조는 제외한다. 허용 루트는 물리 경로 `textures\BodyChangeNG\Cache`, 하위는 기존 4개 네임스페이스와 16자리 해시 폴더이다.
- 삭제 대상은 1.3.1의 정확한 준비/링크 임시 이름에 맞는 **게임에 전달되지 않은 파일**뿐이다. 고유 DDS를 오래됐거나 현재 선택되지 않았다는 이유로 지우지 않는다.
- 공유 데이터 연결은 공개 DDS를 먼저 삭제하지 않고 임시 링크를 원자적으로 교체한다. 실패 시 기존 경로를 유지하며 자신의 임시 파일만 정리한다. 교체 뒤에도 공개 경로의 파일 ID를 확인한다.
- 도구 중복 실행을 막는다. Skyrim 실행 중에는 거부하고 작업 중에도 실행 여부를 확인해 중단한다. 게임이나 텍스처 편집기를 작업 도중 실행해서는 안 된다.
- Windows 10/11 NTFS용이다. 지원되지 않는 파일 작업은 오류로 보고하거나 제외한다. 관리자 권한이나 새 게임 훅을 요구하지 않는다.

## 런타임 변경

`RuntimeAssetCache`의 주 DDS와 동반 맵 준비만 작은 공통 함수로 연결했다. 기존 캐시를 먼저 지우는 대신 인접 임시 파일을 완성한 뒤 교체한다. 실패 시 이전 정상 DDS가 유지된다. 읽기 전용 원본은 개인 사본을 만들고 사본의 속성만 변경한다.

캐시 ID·해시·텍스처 경로·부위 선택·기존 준비 큐는 그대로다. 새 게임 스레드, 영구 액터 맵, 세이브 필드, 프레임당 디스크 검사는 추가하지 않았다. 지원 12개 SE/AE 런타임, RaceMenu ABI, 1.3.0 복원 수정, 기존 의존성 잠금은 변경하지 않았고 VR/1.7.x는 추가하지 않았다.

## 실행 검증

- 고정 xmake 3.1.0, CommonLibSSE-NG 6.7.1, 기존 의존성 잠금으로 Release 전체 빌드 성공. `EXCLUSIVE_SKYRIM_FLAT` 유지.
- `build/v1.3.1/tests/*Tests.exe` **35개 모두 통과**. 바디/UBE·스킨/후타·오버레이/틴트·배포/저장·입력/팝업·SFS/의상 보정·복원/삭제 준비·런타임 경계의 기존 검사도 다시 실행했다.
- `tools/test-addon-audits.py` **19개 통과**.
- 새 캐시 검사는 Windows 실제 파일 API를 사용한다. 게임/엔진 대신 가짜 캐시를 만든다. 검사 종료 후 임시 픽스처 제거도 확인했다.
- 읽기 전용 검사에서 변경 없음, 잘못된 루트/경로 순회 거부, 취소, 내용/시각 불일치 보존, 원본 하드링크 보존, 읽기 전용/미확인 구조 제외, 반복 실행의 멱등성을 확인했다.
- 잠긴 대상 교체 실패에서 원래 DDS 유지와 임시 파일 회수를 확인하고 잠금 해제 후 재시도 성공을 확인했다.
- 정확한 임시 파일 두 종류만 제거하고 비슷한 이름의 사용자 백업은 보존했다. 리파스 제외는 호스트가 심볼릭 링크 생성을 허용할 때 실행하는 조건부 검사다.
- 없는 원본 실패 1,000회, 준비 파일 생성 뒤 잠긴 대상 교체 실패 1,000회에서 공개 파일 바이트와 임시 파일 정리를 확인했다. 후자 반복 전후 프로세스 핸들 수 증가가 없었다.
- 한글 파일명을 포함한 **96개 파일 / 12개 내용 그룹**에서 84개 경로의 중복 저장을 합쳤다. 각 그룹의 파일 ID·내용이 일치하고 재실행에서는 추가 변경이 없었다.
- 새 캐시 검사를 MSVC `/utf-8 /fsanitize=address`로 빌드·실행하여 통과했다. 잘못된 메모리 접근 보고가 없었다. 제품 빌드와 동일하게 UTF-8 입력을 사용한다.
- 기존 AssetCatalog 검사도 새 런타임 준비 함수를 사용해 통과했다. 파일 삭제 후 재생성, 경로 격리, 동반 맵 등 기존 동작을 포함한다.
- `git diff --check` 통과.

## 실제 설치 캐시의 읽기 전용 확인

`D:\TOFU\MO2\overwrite\textures\BodyChangeNG\Cache`에 **`--scan`만** 실행했다.

| 항목 | 결과 |
| --- | ---: |
| DDS 검사 | 144개 |
| 중복 경로 | 25개 |
| 회수 가능 할당량 추정 | 188.372MiB |
| 미공개 임시 파일 | 0개 |
| 오류 | 0개 |

위 회수량은 할당 크기 기반 추정이며 파일 탐색기의 논리적 폴더 크기 감소를 뜻하지 않는다. 이미 하드링크인 파일과 고유 파일은 줄지 않을 수 있다. **설치 캐시·원본 팩·세이브·MO2는 변경하지 않았다.**

## 메모리·성능 및 한계

도구는 오프라인에서만 실행한다. 해시 읽기 버퍼는 256KiB, 바이트 비교는 64KiB 두 개로 고정하며 파일 메타데이터와 경로 목록은 검사 크기에 비례한다. DDS/준비 파일 100,000개에 도달하면 불완전 결과로 중단한다. 검사 파일 수·크기에 따라 시간이 걸릴 수 있다. 핸들/CNG 객체/임시 링크는 수명 범위가 끝날 때 정리한다.

게임 쪽 변경은 기존 준비 시점의 임시 파일/교체뿐이며 동일 캐시 재사용의 빠른 경로는 유지한다. ASan과 오프라인 핸들 검사는 전체 게임/GPU 누수 증명이 아니다. 새 인게임 실행, 모든 런타임의 렌더링 또는 예전 세이브 로드는 하지 않았다. 동시 외부 파일 편집·정리 중 강제 종료·모든 파일 시스템과 보안 프로그램의 동작을 보장하지 않는다.
