# BCNG 전체 점검 — 2026-09-12

## 결론과 검증 수준

일반 Release에서 성기 TXST와 RaceMenu 오버레이 키 보호가 빠지는 빌드 조건, 서로 다른 기능의 적용 작업을 취소하는 경로, 초기화와 늦은 오버레이 완료의 충돌을 수정했다. 불필요한 진단 코드와 그 진단만을 위한 재탐색·지연·통계도 제거했다.

- SE/AE Release 및 별도 오프라인 FormDelete 검증용 DLL 빌드 성공.
- 자동 테스트 실행 파일 21개 전부 성공. 일부는 실제 정책/상태 전이를 실행하고, 일부는 소스 구조를 검사한다. 모두 엔진 통합 테스트인 것은 아니다.
- 툴레드의 실제 BnP CBBE·UNP·남성 SOS 팩을 읽기 전용으로 검사: 96가지 종족·노인·흡혈귀 조합 성공.
- 이번 점검에서 게임을 실행하거나 세이브를 로드하지 않았다. GPU 출력, 장시간 플레이 메모리 추세, 모든 RaceMenu 배포본의 인게임 동작은 미검증이다.
- 따라서 “전체 기능에 누수·회귀가 전혀 없다”거나 “모든 버전 완전 호환”으로 판정하지 않는다.

원시 결과: [자동 테스트 및 실제 파일 검사](FULL-AUDIT-20260912-TESTS.json)

## 발견해서 수정한 문제

### 1. 일반 빌드에서 기능이 빠지는 조건

기존 일반 Release 설정은 native_addon_txst_trial과 form_delete_guard_trial이 꺼져 있었다. 성기 TXST 설치 함수는 즉시 반환했고, 오버레이 키 삭제 방지 코드도 일반 DLL에서는 제외됐다.

시험 빌드 전용 조건과 출력 디렉터리 분기를 제거하고 일반 Release에 기능을 포함했다. 다음 안전 장치는 유지했다.

- 성기 엔진 함수의 실제 런타임 버전, 코드 해시, 호출 지점 및 소유권 확인.
- RaceMenu의 잘못된 handle 축소 콜백 패턴과 실행 중 VM handle 형식 확인.
- 다른 모드가 먼저 변경한 호출 지점에는 중복 패치하지 않음.
- 정상 RaceMenu 콜백은 바꾸지 않음. 보호 패턴 불일치가 정상 공개 API 전체를 막지는 않음.

최종 DLL의 문자열 검사로 두 설치 경로가 포함되고, 기존 시험 빌드 차단 문구가 사라졌음을 확인했다. 이것만으로 실제 게임에서 훅 설치가 성공했다고 판정하지는 않는다.

### 2. 바디 선택이 다른 적용 작업까지 취소

바디 수동 선택 경로가 같은 액터의 스킨·후타·틴트·오버레이 작업까지 넓게 취소하고 일부만 다시 예약했다. 얼굴/텍스처 작업의 정상 완료를 끊을 수 있는 구조였다.

기능 간 일괄 취소와 불완전 복구 코드를 삭제했다. 같은 기능의 대기 요청만 최신 요청으로 합치고, 이미 실행 중인 네이티브 작업의 완료와 소유권은 유지한다.

회귀 시험: 활성 스킨 작업을 유지한 채 바디 요청 10,000회를 교체하고 틴트·남성 성기·오버레이 네 부위 요청이 모두 살아남는지, 최신 바디만 실행되는지, 종료 후 대기·점유가 남지 않는지 확인했다.

### 3. 오버레이 기본값·초기화·뒤늦은 완료

- 새 문양의 미리보기 후 기본값을 누를 때 이미 적용된 문양까지 정상 제거하도록 수정.
- 이미 새로운 작업이 대기/실행 중이면 저장값 재적용이 그 선택을 덮지 않도록 수정.
- 초기화 시 제거할 정확한 노드 소유권을 먼저 버리지 않도록 변경.
- 초기화 세대 번호를 추가해 오래된 적용 완료가 선택을 다시 살리지 못하게 함.
- 늦게 생성된 노드는 선택이 아닌 제거 대기 소유권으로 기록. 해당 소유권은 저장·로드도 가능.
- UI의 미확정 미리보기 상태도 초기화와 함께 폐기해 창을 닫을 때 이전 스킨/오버레이로 되돌리는 충돌 방지.
- 3D가 없을 때도 등록된 정확한 override 키를 정리할 수 있게 하고, 라이브 형상 복원은 3D가 있을 때만 실행.
- 액터가 분리될 때 미리보기 노드 소유권을 그냥 잊지 않고 세션·액터 정체성 확인 후 정리. 외부 모드가 소유한 경로나 새로 확정한 같은 노드는 건드리지 않음.

이는 사라진 정상 선택을 주기적으로 복구하는 방식이 아니다. 정상 키는 보호하고, 사용자가 초기화한 키의 삭제 책임을 완료까지 보존하는 처리다.

### 4. 수동 미리보기와 자동 배포의 충돌

바디·오버레이뿐 아니라 스킨·후타의 미확정 미리보기도 자동 배포 및 장비 재평가보다 우선하도록 연결했다. 확인/취소 후에는 하나로 합친 자동 요청이 재개된다.

미리보기 대기 때문에 뒤의 직접 선택까지 불필요하게 길게 기다리지 않도록 이 재확인 간격은 1틱으로 설정했다. 3D 생성 대기의 기존 제한과 재시도는 별개다. 작업 제출 실패 시 메타데이터를 제거해 요청이 영구 대기 중으로 남지 않게 했다.

### 5. 새로고침·UI 성능 및 작업 수명

- 바디프리셋·스킨·후타·틴트의 파일 목록 새로고침을 하나의 소유된 작업 스레드에서 수행.
- 카탈로그마다 실행/대기 하나만 허용. 연속 클릭으로 스레드나 파일 스캔을 무한 증식시키지 않음.
- 기존 목록은 읽을 수 있고, 완성된 목록만 잠금 아래 교체.
- 작업/오류 보고가 예외를 던져도 작업 스레드를 종료시키지 않음.
- 스킨 새로고침 플래그는 작업 또는 제출 실패 시 반드시 해제.
- 카탈로그 생성 후 작업자를 초기화해 종료 시 작업자가 먼저 합류하고 카탈로그가 그 뒤 해제되도록 순서 명시.
- DDS 준비 작업자에도 예외 격리 추가.
- 언어·배율 조회는 전체 Settings와 즐겨찾기/틴트 백업을 복사하지 않는 경량 getter 사용.
- 오버레이 카탈로그의 성별·바디 계열 필터 결과를 목록 개정/액터 조건/세션 기준으로 캐시.
- 즐겨찾기 조회의 반복 선형 검색 감소.
- 긴 UTF-8 경로의 말줄임을 경계 확인+이진 검색으로 변경. 한글 중간 바이트 절단 방지.
- 후타 탭 표시 여부만 볼 때 전체 애드온 레지스트리를 복사하지 않게 변경.
- 미선택 성기 액터에 네이티브 텍스처 기준값을 불필요하게 축적하지 않게 변경.

실제 프레임 시간 개선 수치는 측정하지 않았다. 디스크가 느리거나 첫 DDS 로드가 필요한 상황에서 지연이 완전히 없어지는 것은 아니다.

### 6. 진단 로그와 사용하지 않는 코드

제거한 것:

- FaceGPU/FaceSkinDiagnostics 상세 진단과 오버레이 등록 추적 모듈 및 해당 추적 전용 빌드.
- 오버레이 성공 확인 로그만을 위해 2틱 기다리던 작업.
- 스킨 변경마다 수행하던 로그 강제 flush.
- 모든 DDS를 두 번째로 순회하던 SkinCatalogAudit 진단.
- 틴트 전체 상태 덤프, 바디 TRI 진단 순회, 개별 override 삭제/성공 상세 로그.
- 프리셋 계열 통계만을 위한 추가 순회.
- 소비자가 없는 ActorWorkMetrics API와 매 작업의 atomic 카운터·시간 측정.
- 정상 DLL의 FormDelete 주기 통계. 테스트용 카운터는 별도 probe에만 남김.
- 호출자가 없는 옛 바디 전용 초기화 API, 옛 프로필 바디 대상 경로 및 그 보조 함수, 진단용 logTargets 인수.

유지한 것:

- 시작 버전/필수 연동 성공 여부와 간단한 목록 로드 요약.
- 적용 실패, DDS 실제 로드 실패, 소유권 충돌, 용량 부족, 지원되지 않는 ABI/엔진 코드의 경고·오류.
- 실제 기능에 필요한 파일 flush는 유지. 로그 flush와 혼동해 삭제하지 않음.
- 오류 원인과 무관한 전체 라이브 형상 덤프는 제거하되 소유권 충돌 경고는 유지.

이전 세션의 사용자 로그 파일은 삭제하지 않았다. 사용하지 않는 소스/진단 경로를 제거한 것이며 사용자 DDS·세이브·설정·캐시를 일괄 삭제하지 않았다.

## 메모리/누수 판정의 한계

테스트에서 작업 완료 후 큐·lease·closure 참조가 해제되는 것, 제출 실패/예외 후 다시 요청 가능한 것, 제한된 캐시가 재사용되는 것을 확인했다. 이 결과는 모든 게임 힙에 대한 누수 검사가 아니다.

특히 NativeSkinBackend의 CreateDuplicateForm 기반 ARMO/ARMA/TXST는 엔진에 등록된 폼이다. 기존 ActorBase별 그래프를 재사용하지만, provider 기준 스킨 변경 또는 부분 그래프 생성 실패 때의 엔진 소유 폼 회수는 별도 수명 검증이 필요하다. 엔진이 참조 중인 폼을 임의 delete하는 수정은 하지 않았다. 이 영역은 “누수 없음 확인 완료”로 표시할 수 없다.

FormDelete probe는 빌드만 했고 게임에 주입·설치하지 않았다. 배포 대상은 일반 BodyChangeNG.dll 하나다.

## 게임/RaceMenu 버전 구분

현재 코드의 기본 런타임 허용 표:

- SE 1.5.97
- AE 1.6.317 / 1.6.318 / 1.6.323 / 1.6.342 / 1.6.353 / 1.6.629 / 1.6.640 / 1.6.659 / 1.6.1130 / 1.6.1170 / 1.6.1179
- 1.6.678은 현재 허용 표에 없음. VR 빌드도 없음.

위 표는 모든 기능을 모든 게임에서 실제 실행했다는 뜻이 아니다.

**성기 네이티브 TXST의 설치 어댑터는 현재 1.5.97과 1.6.1170의 검증된 코드에 한정된다.** 다른 버전은 일반 로더 허용과 별개로 이 경로가 아직 사용 불가다. 미검증 코드에 임의 주소/오프셋을 적용해서 활성화하지 않았다.

RaceMenu BodyMorph v4/v5, Overlay/Override legacy v1과 public v2는 서로 다른 ABI를 구분한다. 미확인 상위 버전에는 알려진 하위 prefix를 사용하는 기존 정책을 유지하지만, 미래 버전이 prefix를 보존한다는 보증은 아니다. 없는 인터페이스나 서로 다른 ABI 조합은 거절한다.
