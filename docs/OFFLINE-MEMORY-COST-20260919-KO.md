# 수정분의 메모리 비용 — 오프라인 확인

사용자 요청에 따라 인게임 측정·계측 DLL·MO2 변경은 하지 않았다. 준비했던 인게임 프로세스 측정 스크립트도 제거했다. 배포 DLL의 SHA-256은 `1BB7318BCE76173029E2ECC40EE912C1677CC158B634EFF4215C015F216FB876`로 변경되지 않았다.

## 결론

최근 수명 수정은 큰 상주 버퍼·텍스처 캐시를 새로 추가하지 않는다. 추가 비용은 작업 중 소유권 추적용 포인터와 콜백 관리 객체가 중심이다. 확인된 실패 경로는 이전보다 할당을 더 잘 회수한다. 정상적인 팩 전환은 기존 스킨 그래프를 재사용한다.

| 수정 | 추가 비용 및 수명 |
| --- | --- |
| 얼굴 콜백 Delivery | 같은 호스트 기반 클래스와 빈 continuation으로 비교했을 때 기존 72바이트 → 248바이트, **동시 생존 콜백당 +176바이트**. 해제 뒤 잔류 0. 캡처 내용과 실제 VM 할당, 힙 관리자 오버헤드는 별도 |
| 모델 대체 텍스처 배열 | 엔진 규약의 개수 헤더 **배열당 8바이트**. 기존 배열과 새 배열이 교체 중 잠시 공존하는 것은 기존 방식도 동일 |
| GraphConstruction | 지역 객체 **48바이트**, 추적하는 폼/TXST당 포인터 8바이트와 벡터 여유 용량. 생성 완료·실패 뒤 추적용 저장소 해제. 완성 그래프의 객체를 추가로 복제하지 않음 |
| Pending 텍스처 소유자 | 생성 중 항목당 unique pointer 8바이트. 성공 시 생성 소유권을 이전하며 실패 시 회수 |
| 복원 실패 시 기존 근거 유지 | 이미 가지고 있던 그래프/경로를 유지. 실패할 때마다 새 복제물을 만드는 방식이 아님 |

앞선 카탈로그 수정은 매 UI 프레임의 전체 스킨/후타/틴트 메타데이터 복사를 불변 스냅샷 공유로 바꾼 것이므로 대량 임시 할당을 줄이는 방향이다. 새로고침 중 기존 독자가 있으면 이전 스냅샷이 잠시 남으며 마지막 독자가 놓으면 회수된다. DDS 전체를 새 상주 캐시에 담는 변경은 아니다.

## 실제 호스트 C++ 할당 계측

별도 `BodyChangeNGOfflineMemoryProbe.exe`에만 전역 C++ new/delete 계측기를 연결했다. 이 코드는 제품 DLL에 포함되지 않는다. 양성 대조로 4,096바이트/1개 할당의 잔류를 감지한 뒤 해제하면 0으로 돌아오는지 먼저 검증했다. 평상시 잔류 0만 출력하는 무효 계측기가 아님을 확인했다.

각 항목은 워밍업 3회 후 전체 시나리오 묶음을 100회 반복했다. 현재 Release/MSVC x64 환경의 **요청된 C++ 할당 바이트**를 센다. 할당자 자체의 헤더·힙 단편화·게임 엔진 힙·RaceMenu/TNG·GPU는 포함하지 않는다.

| 검사 묶음 | 신규 할당 횟수 | 기준 대비 최대 생존 바이트 | 종료 후 잔류 증가 |
| --- | ---: | ---: | ---: |
| 얼굴 콜백 | 6,700 | 624 | 0바이트 / 0개 |
| 얼굴 Finish/롤백 경계 | 600 | 24 | 0바이트 / 0개 |
| TXST 생성·실패 | 310,100 | 29,496 | 0바이트 / 0개 |
| 포인터 분리·복원 재시도 | 0 | 0 | 0바이트 / 0개 |
| 모델 배열 교체·실패 | 960,000 | 3,992 | 0바이트 / 0개 |
| 몸/원거리 그래프 생성·실패 | 1,700,000 | 1,496 | 0바이트 / 0개 |

총 2,977,400회 할당에서 검사 후 추가 잔류가 없었다. 이는 실제 제품 함수 일부를 추출하고 VM·엔진 할당·하위 생성 등을 가짜 구현으로 대체한 오프라인 결과다. 위 최대값은 **테스트 시나리오의** 임시 생존량이지 실제 NPC 한 명의 스킨 메모리량이 아니다.

특히 성공한 그래프는 제품처럼 유지되는지도 확인한 뒤 **테스트 장치가 직접 정리한다.** 따라서 잔류 0을 ‘게임에서 완성된 모든 스킨 그래프가 자동 해제된다’는 뜻으로 해석하면 안 된다.

## 별도로 남는 기존 수명 정책

TNG가 참조할 수 있는 완성된 스킨 그래프는 이번 수정 전부터 장기 유지된다. 정상 팩 전환은 재사용하지만, 종족/원본 제공자가 달라져 새 그래프를 계속 만들면 유지량이 늘 수 있다. 이는 새 콜백/배열/실패 정리 비용과 구분해야 한다. 임의로 파괴하면 외부 캐시의 해제된 포인터 접근 위험이 있다.

따라서 **이번 수정이 대량 메모리를 추가 소비하는 구조는 아니지만, 전체 게임의 누수가 0이라고 판정한 것은 아니다.** 게임 없이 확정할 수 없는 전체 엔진 잔류량을 MB 단위로 만들어 보고하지 않는다.

## 재실행

고정 xmake로 `build BodyChangeNGOfflineMemoryProbe` 후 `build/v1.2.7/trials/offline-memory/BodyChangeNGOfflineMemoryProbe.exe`를 실행한다. 제품 전용 환경변수·로그·훅·게임 파일 변경은 필요 없다.
