# 오버레이 삭제 호출 추적 시험 DLL

## 목적과 현재 판정

오버레이 등록이 사라지는 호출자를 기록하기 위한 **진단용**이다.
근본 원인을 확정하거나 오버레이 문제를 해결한 빌드가 아니다.
기존 스킨/얼굴 성공 시험의 `face_attachment_trial`을 함께 켰고 그 적용
소스는 수정하지 않았다. 오버레이의 선택/색상/소유권 판정도 그대로다.
키 재생성, 복구, 삭제 차단, 장비 변경, 다른 모드 비활성화는 하지 않는다.

## 관찰 범위

SE 1.5.97 + 툴레드의 UBE 2.0 U.0.7 SKEE에 한정한다.
SKEE SHA256:
`283EA6F0DF6234B5636D6B03445A57C90369514E61EC3B02DA07F731FCF3469B`

다음 네 진입점을 관찰한다. 기존 디스크 SHA256과 로드된 진입부 32바이트를
전부 검사한 후에만 설치한다. 미일치하면 진단만 설치하지 않으며 일반
오버레이 인터페이스 지원 정책은 변경하지 않는다.

| RVA | 관찰 동작 | 포착 범위 |
| --- | --- | --- |
| 0x89490 | 액터 노드 등록 전체 erase | FormDelete, 프리셋, 액터별 Papyrus/가상 API 등의 공통 삭제 |
| 0x91F10 | 노드 actor map clear | Revert, 전체 삭제, 인라인 Papyrus 전체 삭제 |
| 0x8A460 | 특정 노드 이름 erase | 부위 슬롯 전체 삭제 |
| 0x8A770 | 특정 노드 key/index erase | DDS·색상·투명도 개별 삭제 |

단일 가상 인터페이스 포인터만 감싸는 것이 아니라 공통 삭제 본체를 관찰한다.
다만 직접적인 메모리 훼손, 알려지지 않은 인라인 컨테이너 조작까지 모두
포착한다는 보장은 없다. `actor-erase`는 삭제 함수 호출 기록이며 실제 값이
있어서 지워졌는지는 전후 BCNG verification/ownership 로그와 함께 판단한다.

기록: 순번, monotonic tick, 스레드, 액터 FormID, 성별, 노드 이름,
key/index, 최대 24프레임의 `DLL 이름 + RVA` 호출 스택.
BCNG 자체의 SKSE FormDelete 콜백도 플레이어에 한해 원래 64비트 handle을
기록한다. 다른 플러그인의 콜백을 교체하지 않는다.

## 안전성 및 수명

- 다음 게임 시작의 PostPostLoad에서 설치. 실행 중인 게임에 원격 주입하지 않는다.
- 훅이 대체하는 명령은 정확히 5바이트 `MOV [RSP+8/10], RBX` 하나다.
  스택 포인터/비휘발 레지스터를 바꾸지 않는 leaf stub에서 그 명령을 실행하고
  원래 함수 +5로 점프한다. 원본 함수의 나머지 코드와 unwind offset을 유지한다.
- 모든 wrapper는 동일 인자로 원본 함수를 한 번 호출한다. 재시도/예외 삼키기로
  원래 함수 동작을 바꾸지 않는다. 마지막 Win32 오류 값도 기록 전후 보존한다.
- 훅 안에서는 게임 API, 저장소 조회, 파일 출력, 동적 할당, 대기를 하지 않는다.
  문자열·스택 주소를 고정 버퍼에 복사하며 Actor/Geometry/Material 소유권을 갖지 않는다.
- 256개 고정 기록 버퍼. 잠금이 사용 중이거나 가득 차면 **진단 기록만** 버린다.
  버린 수는 출력되므로 로그가 불완전한 상황을 숨기지 않는다.
- 출력은 기존 input tick에서 최대 16개씩, SKEE 잠금 밖에서 한다.
- trampoline 4 KiB는 패치된 함수와 같은 프로세스 수명이다. 재로드마다
  할당하지 않고, 다시 Install해도 같은 훅을 중복 설치하지 않는다.
- 시험 옵션 기본값은 false. 일반 빌드에는 진단 함수와 훅이 컴파일되지 않는다.

## 빌드와 검사

고정 XMake 3.1.0 / 기존 저장소 의존성 및 SE/AE exclusive flat 구성.

```
xmake f -m release --face_attachment_trial=y --overlay_registry_trace=y
xmake build --all
```

- Release 전체 빌드 성공.
- 시험 옵션을 끈 일반 Release도 빌드 성공. 진단 문자열/진입점 코드가
  포함되지 않는 것을 확인했고 작업 설정은 두 시험 옵션 모두 false로 돌렸다.
- 기존 테스트 실행 파일 18개 모두 통과.
- 실제 설치 SKEE를 독립 호스트에서 로드한 등록·교체 4,000회 유지.
- 진단 코어를 동일하게 컴파일한 probe DLL로 삭제 경로 600회 검사.
  가상 함수, Papyrus 인라인 전체 삭제, Revert 모두 기록되며 실제 원본 호출
  위치 0x8E8EF / 0x9BCBC / 0x8E7E1이 스택에서 확인됐다.
- 삭제 인자(key/index 포함), 다른 액터 값 보존, 원래 삭제 수행, 잘못된
  이미지 거부, 중복 Install 무작업 확인.
- 버퍼 초과 300회 및 4개 스레드/독립 액터의 삭제 2,000회 검사 통과.
  버려진 진단 수까지 대조했고 원본 삭제 작업은 누락되지 않았다.

이 검사는 게임 렌더링/전체 모드 조합의 인게임 검증이 아니다.

- 게임 종료를 프로세스 목록으로 재확인한 후 툴레드의
  `D:/TuLED13E/File Mod Skyrim SE/mods/Body Change NG/SKSE/Plugins/BodyChangeNG.dll`
  한 파일만 교체했고 위 SHA256과 일치함을 확인했다. 설정, 스크립트,
  다른 모드 DLL, 세이브는 교체하지 않았다. 추가 MO2 백업도 만들지 않았다.
