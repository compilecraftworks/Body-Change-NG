# Body Change NG 1.2.0 재설계

1.2.0은 `v1.2.0-rearchitecture` 브랜치에서 1.1.x와 분리해 개발한다. 이번
재설계의 우선 목표는 스킨 적용을 파일명 추측과 광역 슬롯 부작용에서
분리하고, 입력을 검증한 뒤 정확한 표면에만 적용하는 것이다.

## 핵심 모델

`SkinUvLayout`은 바디 모프 프리셋과 별개의 스킨 계약이다. 지원 값은 여성
Vanilla, CBBE, UNP, UBE, 남성 Vanilla, HIMBO, SAM, Argonian, Khajiit이다.
스킨 프로필과 인간형 액터는 각각 하나의 정확한 레이아웃으로 결정되어야
한다. 미확정 또는 서로 충돌하는 증거는 `unknown`이며 호환으로 간주하지
않는다.

적용 전에는 성별, 종족, UV 레이아웃을 순서대로 검증한다. 하나라도 맞지
않으면 DDS 쓰기를 시작하지 않는다. 이는 잘못 적용한 뒤 복구하는 방식보다
안전하며, UV가 다른 부위에 들어가 밀려 보이는 현상을 원천에서 막는다.

## 부위 라우팅 규칙

- CBBE, UNP, Vanilla, HIMBO, SAM은 현재 3D에서 확인된 정확한
  Armor+ArmorAddon+geometry에만 쓴다.
- UBE는 몸·손·발이 하나의 바디 아틀라스를 공유한다는 명시적 계약 때문에
  광역 skin-slot 경로를 사용할 수 있다.
- Argonian과 Khajiit은 전용 발 레이어가 없으면 발을 변경하지 않는다.
  인간형의 검증된 레이아웃만 발에 바디 아틀라스를 사용할 수 있다.
- 장비에 가려져 정확한 대상이 없는 부위는 다른 ArmorAddon에 대신 쓰지
  않고 다음 3D/장비 갱신 때 다시 조정한다.
- 얼굴, 성기, 질/항문 보조 메시와 꼬리는 각각 독립된 대상 선택 규칙을
  유지한다.

## 작업 조정 규칙

프레임 작업 큐의 숫자는 우선순위가 아니라 `(actor, operation)`의 최신 작업
교체 키다. 1.2.0은 이를 `WorkChannel` 타입으로 정의하고 바디 미리보기,
확정, 스킨, 후타나리 스킨, 틴트, 장비 재조정 등을 모두 서로 다른 채널로
분리했다. 기존에 같은 값 205를 사용하던 틴트와 후타나리 스킨이 서로를
취소하는 문제도 제거했다.

## 프로필 판정

알려진 표준 폴더와 이름에서 단 하나의 레이아웃이 확인되면 자동 프로필을
만든다. HIMBO/SAM처럼 같은 Bethesda 파일명을 공유해 구분할 수 없는 팩은
폴더 이름의 명시적 표식 또는 `profile.json`의 `uvLayout`이 필요하다.
모호한 자동 프로필은 카탈로그 진단을 위해 보존될 수 있지만 UI와 런타임
적용에서는 제외된다. 명시 JSON이 모호하거나 성별·종족과 충돌하면 스캔
단계에서 거부한다.

## 검증 범위

순수 단위 테스트는 레이아웃 호환성, 모호성 fail-closed, 종족별 발 레이어,
UBE 전용 광역 라우팅, 작업 채널 충돌 방지를 검사한다. 기존 자산 카탈로그
테스트는 표준/UBE/비스트/SOS/부분 스킨 스캔과 정확한 부위 분류를 계속
검증한다. 실제 Skyrim 안에서의 RaceMenu v0/v1/v2 동작은 별도의 게임 내
회귀 검증이 필요하다.
