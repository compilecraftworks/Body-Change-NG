# Body Change NG 1.2.0 재설계

1.2.0은 `v1.2.0-rearchitecture` 브랜치에서 1.1.x와 분리해 개발한다. UI와
NPC 배포 조건·우선순위·풀 편집 방식은 1.1.4를 유지하되, 내부 소유권을
바디 모프, 기본 스킨, 틴트, 남성 성기 애드온, 여성 후타나리 애드온,
의상 보정으로 분리한다. 한 기능의 선택·적용·초기화가 다른 기능의 상태나
작업을 지우지 않는 것이 최우선 불변식이다.

## 기능별 권한과 범위

| 기능 | 저장/적용 범위 | 백엔드 | 장비 이벤트 |
|---|---|---|---|
| 바디 프리셋 | 액터 레퍼런스 | RaceMenu BodyMorph | 의상 보정만 사용 |
| 기본 바디스킨 | NPC ActorBase | 네이티브 TXST → ARMA → Skin Armor | 사용하지 않음 |
| 얼굴 스킨 | NPC ActorBase | Face TXST, RSV일 때만 얼굴 브리지 | 사용하지 않음 |
| 틴트마스크 | 플레이어 | RaceMenu 틴트 배열 | 사용하지 않음 |
| 남성 SOS/TNG 성기 | 액터 레퍼런스의 슬롯 52 애드온 | RaceMenu exact override | 사용 |
| 여성 후타나리 | 액터 레퍼런스의 선택형 애드온 | RaceMenu exact override | 사용 |
| 의상 보정 | 액터 레퍼런스 | BCNG 소유 BodyMorph 키 | 사용 |

`ActorState`도 같은 경계를 따른다. Body, Skin, Futanari가 각각 독립된
선택·적용 상태를 가지며, 예를 들어 Default Skin은 바디 프리셋이나
후타나리 선택을 초기화하지 않는다. 프레임 큐 역시 기능마다 서로 다른
`WorkChannel`을 사용하므로 최신 스킨 작업이 틴트나 후타나리 작업을
취소할 수 없다.

## 스킨 레이아웃과 런타임 바디 계열

카탈로그의 `SkinLayout`과 액터의 `BodyFamily`는 별도 계약이다. 일반 인간형
스킨팩은 CBBE/3BA·UNP/BHUNP·바닐라/HIMBO/SAM을 파일명·폴더명으로 다시
분류하지 않고 모두 `Legacy`로 등록한다. 명백한 `!UBE/Body`, `!UBE/Head`
구조만 `UBE`다. 스킨팩 메타데이터 JSON은 읽지 않으며, 자동 ID인
`auto:<상대 폴더>:<성별>`도 변하지 않는다.

호환성은 적용 시 액터의 `BodyFamily`와 결합한다. CBBE/3BA·UNP/BHUNP·일반
여성 바디는 Legacy를 허용하고 UBE는 UBE만 허용한다. 네이티브 재질 라우팅에
필요한 구체 `SkinUvLayout`은 이 시점에만 파생한다. 3BA의
`femalebody_etc_v2_1`과 BHUNP의 `BakaUNP/VaginalAnalCanal2`는 분류 근거가
아니라 독립된 선택적 질·항문 자산이며, 실제 설치 그래프에서 일치하는 정확한
TXST/지오메트리 역할에만 들어간다. 남성의 구체적인 바닐라/HIMBO/SAM 경로도
적용 시점의 런타임 BodyFamily에서만 파생한다. 아르고니안·카짓은 바디 계열
분류가 아니라 별도의 종족 경계로 유지한다.

## 네이티브 기본 스킨 그래프

일반 BodySkin은 더 이상 현재 입은 의상이나 로드된 지오메트리를 칠하지
않는다. 적용 순서는 다음과 같다.

1. 액터가 현재 사용하는 Skin Armor를 원본 공급자 그래프로 잡는다.
2. ARMO, 실제 적용되는 모든 ARMA, 기본 TXST와 texture-swap 목록의 TXST를
   동적 폼으로 깊게 복제한다.
3. 복제 TXST의 0~7번 채널은 우선 원본 그대로 보존한다.
4. 선택 프로필이 선언한 부위·채널만 정확한 TXST 역할에 덮어쓴다.
5. 복제 Skin Armor와 far skin, 필요한 경우 Face TXST를 ActorBase에 연결한다.
6. 같은 ActorBase를 쓰는 현재 로드 레퍼런스의 3D를 한 번 갱신한다.

이후 알몸 바디, 손, 발이 다시 생성되거나 의상을 갈아입어도 Skyrim이
ActorBase의 현재 Skin Armor를 원본으로 사용한다. BCNG는 기본 스킨을 위해
장갑·신발·의상 착탈을 추적하거나 매번 NIF를 재도색하지 않는다.

Default Skin은 BCNG가 아직 소유하고 있는 포인터만 원래 공급자 그래프로
되돌린다. 그 사이 다른 모드가 포인터를 바꿨다면 임의로 덮어쓰지 않는다.
RSV 경로가 새 공급자로 확인되면 기존 BCNG 얼굴/far-skin 클론을 먼저
안전하게 분리한 뒤 현재 RSV 그래프를 새 원본으로 다시 복제한다. RSV가
아닌 외부 포인터 충돌은 실패 폐쇄한다.

각 포인터의 소유 여부도 독립적이다. 얼굴 레이어만 있는 프로필은 Face TXST만
연결하고 몸/far-skin 복제본을 연결하지 않는다. 반대로 몸 전용 프로필은 얼굴
TXST를 소유하지 않는다. BCNG가 사용하지 않던 몸·far-skin·얼굴 공급자가 바뀐
경우에는 다음 관련 프로필을 적용하기 전에 현재 값을 새 원본으로 다시 잡는다.

## 부분 스킨팩 규칙

모든 DDS가 존재해야 하는 것은 아니다. "요청한 역할이 그래프에 존재"는
프로필이 실제로 제공한 부위에 대해서만 정확한 TXST 대상이 있어야 한다는
뜻이다.

- 몸 diffuse만 있는 프로필은 몸 TXST만 요구한다.
- 손이나 발 파일이 없으면 해당 역할을 요구하지 않고 원본/RSV TXST를 유지한다.
- diffuse, normal, subsurface, detail, specular 중 빠진 채널은 복제 전에
  보존한 원본 값을 유지한다.
- 선언한 손 DDS를 몸에, 몸 DDS를 손에 대신 넣는 폴백은 없다.
- 선언한 부위가 있는데 정확한 TXST 역할을 찾지 못하면 전체 적용을
  중단한다. 일부만 잘못 적용한 상태로 성공 처리하지 않는다.

CBBE 3BA의 `femalebody_etc_v2_1`과 BHUNP의
`BakaUNP/VaginalAnalCanal2`는 일반 몸과 별도의 질·항문 보조 아틀라스
역할이며 Legacy/UBE 분류를 좁히지 않는다. UBE는 슬롯 53과 UBE UV 계약이 확인된 경우에만 몸·손·발 공유
아틀라스로 처리한다. 실제 UBE 2.0 기본 그래프는 `NakedTorso`가
`0x00800174`(슬롯 53 포함), `NakedHands`가 슬롯 33, `NakedFeet`가 슬롯
37이고, 세 NIF가 모두 `!UBE\Body\femalebody_1_{d,n,sk}`를 사용한다.
몸 NIF에는 질·항문 지오메트리도 포함돼 같은 몸 아틀라스를 사용한다.

UBE 기본 세 ARMA에는 바닐라와 달리 `NAM1` TXST가 없다. 따라서 현재
Skin Armor가 확인된 정식 `!UBE\Body`, `!UBE\Hands`, `!UBE\Feet` naked
모델을 사용하고 선택 프로필에 몸 아틀라스 DDS가 실제로 있을 때에만 BCNG가
복제한 ARMA에 전용 TXST를 생성하고 위 세 기본 채널을 원본값으로 넣는다.
얼굴 전용 UBE 프로필은 이 합성을 하지 않는다. 선택팩이 제공한 채널만 그 복제 TXST에서
바뀐다. 이미 TXST/스왑 목록을 제공하는 UBE 호환 그래프는 그것을 그대로
복제하고, 알 수 없는 커스텀 UBE naked 경로에는 기본 경로를 추측하지 않고
실패 폐쇄한다. Argonian/Khajiit은 전용 발 파일이 없을 때 몸 DDS를 발로
복사하지 않는다.

## 의상 안의 피부

BCNG는 의상 NIF 자체를 기본 바디로 오인해 수정하지 않는다. 정상적인
Skyrim skin-texture 계약을 따르는 의상의 피부 셰이더는 Biped의 현재 naked
Skin Armor가 공급한 Skin Texture를 사용한다. 실제 UBE 변환 의상들도 별도
`meshes\!UBE\...` ARMA/NIF를 사용하고, 노출 피부에는 위 UBE 몸 아틀라스
경로를 넣는다. 따라서 BCNG는 ActorBase의 복제 Skin Armor 그래프만
연결하고 의상 착탈을 추적하지 않는다.

반대로 의상 제작자가 노출 피부를 Skin Tint가 아닌 별도 재질과 고정 경로로
완전히 독립시킨 경우, 그것은 실제 바디 스킨이 아니라 의상 소유 표면이다.
이 경우에는 해당 의상 패치가 필요하며 BCNG가 장비를 추적해 임의로
덮어쓰지 않는다. 이 경계는 SFS, SVS, Skyrim Outfit System 같은
외형/가상 의상 모드와의 소유권 충돌을 피하기 위한 의도된 규칙이다.

## 얼굴, 틴트, RSV

얼굴 diffuse/normal/subsurface/specular/detail은 몸 TXST에 섞지 않고 Face
TXST 복제로 처리한다. RaceMenu 틴트마스크와 색·투명도는 플레이어 전용
틴트 배열 기능이며 기본 스킨과 별도 상태·채널을 사용한다.

RSV가 NPC base의 Skin을 배포한 상태라면 BCNG는 그 RSV Skin Armor를
원본으로 복제하므로 Default에서 RSV가 다시 나타난다. RSV의 직렬화된 얼굴
NiOverride 키는 삭제하거나 소유하지 않는다. 선택 스킨에 얼굴 레이어가
있고 RSV 얼굴 키가 실제로 확인된 액터만, RSV의 지연 NiNode 갱신 뒤 150ms
병합을 한 번 수행한다. 각 채널의 현재 키가 RSV 경로인지 다시 확인하고
그 채널을 비영구 live 값으로만 덧칠하므로, 빈 채널이나 다른 모드 채널에
BCNG 영구 키를 만들지 않는다. 일반 기본 스킨은 NiNode 이벤트를 소비하지 않는다.
UBE 2.0 자체가 요구하는 RSV 플레이어 제외/`PLAYER VANILLA` 구성은 BCNG가
대신 수정하지 않는다. UBE와 RSV가 호환되게 구성된 뒤 공급되는 유효한
TXST 그래프에 대해서만 위 재기반 규칙을 적용한다.

## 남성 성기와 여성 후타나리

남성 HIMBO/SAM의 기본 몸에는 성기 메시가 없을 수 있지만, 선택한 일반
남성 BodySkin의 `malegenitals_*` 변형은 현재 SOS/TNG 슬롯 52 애드온에
연결한다. 프로필에 남성 성기 DDS가 없으면 이전 BCNG 소유 성기 키를
명시적으로 제거한다.

여성 후타나리는 CBBE 3BA/BHUNP/UBE 공통으로 기본 여성 스킨의 질·항문
아틀라스와 다른 선택형 외부 애드온이다. SOS/TNG가 탈착·토글을 관리하고
SOS/ERF/TRX 등이 실제 성기 지오메트리 계열을 제공한다. Futanari 탭의
선택은 애드온이 잠시 없어도 유지되며, 다시 장착되었을 때 그 애드온에만
재적용된다. 일반 BodySkin의 적용·Default·마이그레이션 정리는 여성 슬롯
52를 건드리지 않는다.

## NPC 배포 범위

1.1.4의 조건 종류, 첫 일치 규칙, 우선순위, body/skin 제외, 풀 편집과 JSON
스키마는 바꾸지 않는다. 다만 적용 단위의 차이는 해시 선택에 반영한다.

- BodyMorph는 레퍼런스 단위이므로 같은 NPC base의 서로 다른 레퍼런스도
  각자의 바디 프리셋을 가질 수 있다.
- 네이티브 스킨은 ActorBase 단위이므로 같은 base를 공유하는 모든
  레퍼런스가 하나의 스킨을 공유한다. 스킨 풀 해시는 레퍼런스 FormID를
  제외해 항상 같은 항목을 고른다. 1.1.x 코세이브에 서로 다르게 남은
  참조별 자동 스킨 결과도 유지하지 않고 이 공통 해시로 한 번 수렴시킨다.
- 같은 ActorBase에 서로 다른 수동 스킨을 요구하면 어느 한쪽을 조용히
  덮지 않고 `sharedActorBaseConflict`로 실패 폐쇄한다.
- 활성 스킨이 없는 Default 상태에서는 다음 레퍼런스로 소유권을 넘길 수
  있다. 같은 활성 프로필은 공유하지만, 비소유 레퍼런스가 다른 프로필이나
  강제 Default로 활성 그래프를 바꾸려는 요청은 거부한다.

기본 샘플 8개도 보호된 레코드가 아니라 수정·이동·삭제 가능한 일반 규칙이다.
샘플과 아직 이름을 직접 고치지 않은 생성 규칙만 선택적 `nameKey`를 가지며,
이 값으로 한국어·영어·중국어 표시를 바꾼다. 사용자가 이름을 편집하면 키를
해제해 그 문자열을 그대로 보존한다. 새 규칙 ID는 현재 전체 규칙과 충돌하지
않게 발급한다. 첫 일치 의미를 자동으로 재정렬하지는 않으며, 앞선 같은 성별
전체-NPC 규칙에 가려진 행은 편집기에서 즉시 경고한다.

배포 규칙과 설정 저장은 `.new` 파일 쓰기·flush·재파싱이 모두 성공한 뒤에만
기존 파일을 원자 교체한다. 자동 바디 또는 스킨 접수가 거절되면 로그에 액터,
ActorBase, 규칙/수동 소스, 선택 ID와 사유를 남긴다. 접수 성공과 실제 완료는
구분하며 코세이브 완료 서명은 BodyMorph 또는 네이티브 TXST 연결이 끝난 뒤에만
갱신한다.

바디모프 완료를 기다린 뒤 스킨을 다시 칠하던 1.1.x 배포 지연은 없다.
두 기능은 각자의 작업 채널에서 독립 적용되며, RaceMenu가 3D를 다시 만들어도
ActorBase의 네이티브 Skin Armor 공급 관계는 그대로 유지된다.

레퍼런스마다 서로 다른 네이티브 스킨이 반드시 필요하다면 NPC base 자체를
복제·교체해야 하며, 이는 FormID와 조건 소비자 호환성을 깨뜨리므로 1.2.0의
안전 범위에 포함하지 않는다.

## 버전 경계

빌드는 SE/AE 전용 `EXCLUSIVE_SKYRIM_FLAT`이며 VR 대상이나 VR 분기를
생성하지 않는다. 전체 기능 지원 런타임은 SE 1.5.97과 AE 1.6.317, 318,
323, 342, 353, 629, 640, 659, 678, 1130, 1170, 1179이다. 렌더러 훅,
입력 훅, PlayerTint 멤버 오프셋은 각 경계를 별도 표로 판정한다. 1.7.x를
포함해 표에 없는 버전은 부분 기능만 임의로 실행하지 않고 전체 실패 폐쇄한다.

RaceMenu BodyMorph ABI v4/v5와 Override ABI v0/v1/v2를 명시적으로 구분한다.
v0/v1의 외부 성기·RSV 얼굴·1.1.x 정리는 Papyrus 문자열 경로를 사용하고,
검증된 v2만 네이티브 인터페이스를 사용한다. 미래 ABI나 목록에 없는 Skyrim
버전은 가장 가까운 버전으로 추측하지 않는다.

## 1.1.4 업그레이드 정리

1.1.4 코세이브 형식은 그대로 읽는다. 해당 액터가 처음 1.2 스킨 적용 또는
Default를 받을 때, 이전 버전이 기록한 BCNG 캐시 경로의 body/hand/foot/tail/
face NiOverride 키만 소유권을 확인해 한 번 제거한다. RSV와 다른 모드의
키, 남성 성기, 여성 후타나리는 이 정리에서 제외한다. 따라서 과거 BCNG
키가 새 네이티브 TXST 위에 다시 나타나거나 Default 뒤 되살아나는 것을
막으면서 다른 모드의 레이어는 보존한다.

## UI와 검증

탭, 팝업, 클릭/더블클릭, 게임패드 조작, 즐겨찾기, 배포 편집 화면은
1.1.4와 동일하다. 바뀐 것은 백엔드 오류 문구와 TXST 소유권 설명뿐이다.

회귀 테스트는 UV fail-closed, 부분팩 역할 요구, CBBE/BHUNP 보조 아틀라스,
UBE 슬롯 53, RSV 재기반과 외부 소유권 거부, 기능별 이벤트/작업 채널,
ActorState 독립성, NPC base/레퍼런스 배포 범위, 런타임/ABI 경계를 검사한다.
Release DLL과 모든 테스트를 통과한 뒤에도 실제 Skyrim에서 CBBE 3BA,
BHUNP, UBE, RSV, SOS/TNG, ERF/TRX 및 대표 의상 조합의 게임 내 검증은
별도의 릴리스 게이트로 남긴다.
