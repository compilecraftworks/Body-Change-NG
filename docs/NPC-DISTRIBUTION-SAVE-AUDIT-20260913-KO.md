# NPC 배포·저장 점검 및 후타 이벤트 보완

## 범위와 증거

2026-09-13 현재 작업 트리 기준. 사용자 요청으로 점검 후 아래 두 문제를 수정했다.
기존 다른 작업의 변경은 보존했다. 아래 두 문제의 점검·수정 단계에서는 게임 실행,
메모리 쓰기, 사용자 세이브·설정·배포 JSON 수정, MO2 DLL 교체를 하지 않았다.

점검 초반 읽은 액터 16개 기록은 사용자가 업데이트 전 자료라고 확인했다.
따라서 해당 로그와 기존 세이브는 **최신 빌드의 배포·저장·로드 정상/실패를
판정하는 근거에서 제외한다.** 현재 빌드로 새로 저장한 후 다시 로드하는 인게임
검증은 아직 하지 않았다.

## 수정 1: 후타 등록·애드온 전환 뒤 후타 배포만 재평가

기존 `ActorEvents.cpp`의 장착·NiNode 재생성 이벤트는
`QueueReapplyCurrentFutanari()`로 이미 저장된 ID만 복구했다.
초기 NPC 배포 이후 SOS/TNG 등록이 끝나면 저장된 후타 ID가 없어 아무 일도 하지
않았고, ERF/TRX 전환 시 이전 종류의 ID가 호환성 검사에서 막혀도 새 후보를
선택하지 않았다. 미등록 상태로 처음 이벤트가 들어온 액터의 필터도 너무 일렀다.

수정:

- `Distribution::RefreshFutanariSelection()`에서 후타 규칙만 재평가한다.
- 초기 배포와 이벤트 재평가는 동일한 `ChooseFutanariRule()`을 사용한다.
- 설치된 여성 애드온이 있으면 이전 BCNG 선택이 없는 여성도 장착·NiNode 이벤트
  확인 대상으로 허용한다. 실제 후보 선택은 계속 SOS/TNG 등록·유형 일치를 요구한다.
- 등록 유형은 일치하는 규칙이 있을 때만, 한 번의 평가에서 최대 한 번 조회한다.
- 바디·일반 스킨·오버레이 재선택, 매 프레임 전 NPC 검색, 타이머/백그라운드 스레드,
  새 장기 보관 컨테이너는 추가하지 않았다.
- 플레이어는 자동 배포 제외. 수동 후타 선택 및 수동 기본값은 변경하지 않는다.
- UI 미리보기 중 자동 재적용을 막고, 기존 이벤트 병합·세대 취소를 유지한다.
- UBE 자동 배포 제외 정책은 기존 요청대로 유지하며, UBE 수동 변경은 건드리지 않는다.

함께 발견한 같은 경로의 결함: 적용 완료 판정에 애드온 형태만 들어가므로, 같은
애드온에서 배포 스킨 ID만 바뀌면 재적용이 생략될 수 있었다.
`FutanariSelectionSignature()`에 애드온 대상, 스킨 ID, DDS 내용 해시를 함께
포함해 이를 해결했다. 성공한 실제 적용 때만 완료 서명을 기록하며, 동일 값으로
돌아오는 재생성 이벤트는 다시 TXST를 적용하지 않는다. 수동 기본 복원은 별도
기존 서명을 유지한다.

## 수정 2: 전체 NPC 제외 옵션의 적용 범위

`UI.cpp`는 커스텀 팔로워·노인 제외 체크박스를 전체 NPC에서만 표시했지만,
`Distribution.cpp::MatchesTarget()`은 모든 대상 종류에 이 값을 적용했다.
따라서 이름·개별 NPC·플러그인·팩션 등으로 직접 지정해도 숨은 체크 값 때문에
배포가 거부될 수 있었다.

`MatchesDistributionScopeFilters()`와 실제 호출부를 전체 NPC 조건에 한정했다.
전체 NPC의 기본 제외는 그대로이고, 다른 대상을 명시하면 그 대상 조건으로
판정한다. 기존 JSON 구조·체크 값은 바꾸지 않아 전체 NPC로 돌아왔을 때 사용자가
설정한 체크 상태가 유지된다. 바디·스킨·후타·오버레이 공통 조건 평가에 적용된다.

## 저장 경로 점검

- 배포 조건: `Data\SKSE\Plugins\BodyChangeNGdistribution.json`.
  임시 `.new` 파일 쓰기·검증 후 교체한다. 즉시 배포는 저장 성공 후에만 활성
  규칙을 교체한다. 다음 실행 배포는 저장된 규칙만 교체한다. 팝업 닫기는 저장하지 않는다.
- 액터 선택: SKSE co-save의 ASTR v6. 바디·스킨의 수동 여부, 후타 ID·수동/기본값,
  부위별 오버레이 ID·경로·슬롯·색상·수동 여부를 보존한다.
- 후타 자동 선택도 같은 v6 인코더/디코더를 사용한다. 이번 수정은 저장 버전이나
  바이너리 필드를 변경하지 않았다.
- 로드 시 실행 중 적용 증거는 무효화하고 재검증한다. 세이브/분리 전의 지연 작업은
  기존 session generation/lease로 차단한다.

## 실행한 테스트

고정 xmake 3.1.0, 프로젝트의 SE/AE 전용 설정으로 릴리즈 빌드 성공.
전체 테스트 실행 파일 24종 통과.

- 대상 종류 11 × 옵션 4 × NPC 특성 4 = 176가지 제외 범위 조합.
- 실제 후타 선택 갱신 함수 + ASTR v6 왕복: 초기 미등록, 등록 뒤 자동 선택,
  ERF→TRX 선택 변경, 일시적 후보 없음, 수동 스킨/기본값 보존, 다른 기능 보존.
- 동일 애드온의 스킨 변경 및 DDS 갱신이 완료 서명을 무효화하는지 검사.
- 같은 서명 반복 1,000회에서 재적용 불필요 확인.
- 기존 1,000개 NiNode 요청의 큐 병합과 로드 경계 취소 검사.
- 실제 이벤트→후타 전용 평가 연결, 미등록 액터의 이벤트 허용,
  수동/미리보기 보호에 대한 소스 연결 검사.

이 테스트들은 엔진 독립 정책·직렬화·큐 및 소스 연결 검증이다. 실제 SOS/TNG
등록 이벤트, 렌더링, 게임 저장 콜백 순서를 인게임 재현했다는 뜻이 아니다.

## 별도 미해결: 오버레이 미리보기 중 저장

후속 배포 준비에서는 바디프리셋·바디스킨·후타스킨의 NPC 배포 체크박스 목록에도
마지막 행 미리보기를 연결했다. 체크·키보드/게임패드 확정은 배포 후보만 바꾸며
수동 액터 선택은 저장하지 않는다. 기존 미리보기/복원 경로를 공유하고, 원본 선택은
카탈로그별 하나만 보관한다. 3개 카탈로그 각각 1,000회 전환의 원본 유지와 액터
경계, 취소·조건 팝업 진입·탭 변경·닫기 연결을 검사했다. Release 재빌드와 24종
테스트를 다시 통과한 DLL을 두 MO2에 교체했으며 사용자 설정·배포 JSON 해시는
교체 전후 같았다. 게임 렌더링 검증은 여전히 별도이며 아래 위험은 미해결이다.

이번 두 수정과 별개로, 미리보기 중 자동저장이 발생하면 임시 오버레이가
RaceMenu 쪽 저장 데이터에 남을 수 있는 경로를 발견했다. 아직 인게임 재현하지
않았으며 이번 변경으로 해결했다고 주장하지 않는다.

BCNG의 ASTR 선택 배열에는 미리보기를 넣지 않지만,
`RaceMenuOverlay.cpp::FinalizeNodeProperties()`는 미리보기에도
`AddNodeOverride`로 DDS/색상/알파를 RaceMenu 저장소에 등록한다.
RaceMenu는 그 노드 저장소를 자체 저장 콜백에서 직렬화한다.
BCNG는 미리보기 소유권을 실행 중 메모리에만 보관하므로, 미리보기 상태에서
저장한 파일을 나중에 로드할 때 이를 BCNG 임시 노드로 회수할 정보가 빠질 수 있다.
이는 다음 공식 소스와 BCNG의 호출 경로를 결합한 **코드상 위험 판단**이다.
[RaceMenu 저장 콜백](https://github.com/expired6978/SKSE64Plugins/blob/9ebcb733e17be695f994cd2e9cc383043446bc02/skee64/main.cpp#L342),
[노드 저장소 직렬화](https://github.com/expired6978/SKSE64Plugins/blob/9ebcb733e17be695f994cd2e9cc383043446bc02/skee64/OverrideInterface.cpp#L2164).

따라서 최신 빌드 인게임 검증은 닫기 후 명시 저장·로드와 미리보기 중 자동저장을
구분해야 한다. 새 등록 NPC와 ERF/TRX 전환도 셀 이동 없이 확인해야 한다.
