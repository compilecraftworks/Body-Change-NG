# BCNG 제보 점검 및 개발 수정 — 2026-10-08

2026-10-17 갱신: 아래 개발 변경은 1.3.7 릴리즈에 포함한다. 본문은 10월 8일 조사 당시의 기록이며, 최종 배포 검사는 [1.3.7 검증 기록](RELEASE-VERIFICATION-v1.3.7-KO.md)을 따른다.

기준 배포: 1.3.6 / main `3fe5f6414dcd13ff140a549bdabe721fe05a385e`.
아래 체형 편집·오버레이 표시·스킨 복구 변경은 **개발 소스 변경**이며 기존 GitHub 1.3.6 릴리즈와 ZIP에는 포함되지 않는다. 이번 작업에서는 버전 숫자, MO2 설치본, 게임 설정, 공개 릴리즈를 갱신하지 않았다.

## UBE 로드·클릭 체형 누적: 특정 SE 원인 확인, AE 제보 원인 미확정

1.3.5에는 UBE SE 동봉 특정 RaceMenu DLL(Skyrim 1.5.97)의 ExtraData 정렬/검색 불일치에 대한 호환 수정이 실제 포함되어 있다. 정렬은 이름 포인터의 하위 32비트만 비교하지만 검색은 64비트 전체를 비교하여 기존 SHAPEDATA를 찾지 못했고, 이미 변형된 geometry에서 두 번째 baseline을 만들어 모프를 중첩하는 반례를 확인했다. 이 수정은 확인한 DLL 해시와 코드에만 적용되며 AE DLL에는 적용하지 않는다. [SE 진단 기록](UBE-SE-MORPH-BASELINE-AUDIT-20260928.md)을 따른다.

1.3.6에는 SE/AE 공통 공개 API로 모프 갱신을 액터 작업 안에서 완료하고, 로드/RaceMenu 복원 때 살아 있는 확정값을 보존하는 변경이 포함되어 있다. 지원 런타임과 BodyMorph v4/v5의 오프라인 검사를 통과했으나 **AE 제보자의 누적 현상 자체를 재현하거나 실제 원인을 확정한 것은 아니다**. 따라서 상태는 “특정 SE 결함 수정 배포, SE/AE 공통 갱신·복원 개선 배포, AE 제보 재현·해결 확인 미완료”로 구분한다. [1.3.6 검증 한계](RELEASE-VERIFICATION-v1.3.6-KO.md)를 따른다.

## RaceMenu 체형 미세 조정: 개발 수정

1.3.5의 메뉴 종료 재확정은 편집값을 XML 프리셋으로 덮을 수 있었다. 1.3.6은 살아 있는 BCNG 모프 키를 보존하지만, BCNG 키 `BodyChangeNG`와 CBBE 슬라이더의 `RaceMenuMorphsCBBE.esp`는 여전히 별개였다. 따라서 슬라이더의 0 표시와 실제 몸의 프리셋 모양은 동시에 발생할 수 있다.

메뉴를 열 때 이미 적용된 플레이어 프리셋 값과 기존 슬라이더 기여분을 편집 키에 표시한다. BCNG의 기존 기여분은 소유한 보정 키로 상쇄한다. 닫을 때 편집 결과에서 기존 슬라이더 기여분을 빼 BCNG 키에 반영하고, 원래 슬라이더 키를 복원한다. 임신 등 다른 공급자의 키는 수정하지 않는다. 옷 보정은 체형에 섞지 않고 기존 OutfitRefit 정책으로 다시 계산한다.

RaceSex Menu 이벤트를 사용하므로 콘솔 showracemenu와 같은 메뉴를 사용하는 Face Sculptor가 동일 경로에 들어간다. 실제 Face Sculptor 모드/인게임 입력은 여기서 실행하지 않았다.

슬라이더 키는 설치된 CBBE 3BA PEX의 `MORPH_KEY.get`와 `GetBodyMorph` 명령을 끝까지 해석하여 확인했다. HIMBO PSC의 Get/Set 호출, UBE PEX의 `MORPH_KEY.get`도 확인했다. 검증한 키는 CBBE, HIMBO, UBE 세 가지다. 알 수 없는 계열·혼합 계열·UNP/SAM의 키는 추측하지 않는다.

SKEE의 실제 합산 방식은 공통 공개 API로 검사한다. 기본 `iBodyMorphMode=0` 합산에서만 편집 연결을 시작한다. 평균/최댓값 공급자는 변경하지 않고 로그에 필요한 설정을 알린다. 설치 INI를 자동 변경하지 않는다. [공식 SKEE 구현](https://github.com/expired6978/SKSE64Plugins/blob/master/skee64/BodyMorphInterface.cpp)은 모드별 계산과 0 모프 키의 저장 구조를 보여준다.

### 저장·복구·수명

- 프리셋 값과 기존 슬라이더 값은 SKEE의 같은 액터 레코드에 소유한 baseline/offset 키로 보관한다. BCNG/SKEE 저장 콜백 순서와 관계없이 편집 중 스냅샷을 복구할 수 있다.
- 편집창이 열린 상태의 저장은 편집을 종료하지 않는다. 이미 닫혔으면 지연 복원 전에 저장되더라도 소유권을 정리한다.
- 복구 키에는 검증한 슬라이더 키 종류의 0 마커가 있다. Zeroed Sliders의 빈 프리셋과 카탈로그가 아직 없는 상황도 복구할 수 있다. 새 코세이브 레코드나 기존 스키마 변경은 없다.
- Reset으로 사라진 이름과 명시적 0을 BCNG에 반영한다. 수정한 Zeroed Sliders에 BCNG 키가 생긴 것을 잘못된 상태로 판단해 프리셋을 덮지 않는다.
- 새 프리셋의 명시적 확정은 새 프리셋으로 교체한다. Default/전체 초기화/제거 시 임시 기여분을 먼저 정리하고 소유한 키를 제거한다.
- 런타임 편집 세션은 플레이어 하나의 actor handle·세션 세대·값 스냅샷만 보유한다. geometry/material/provider 포인터를 비동기 보관하지 않는다. 종료·새 세계 로드 시 스냅샷을 해제한다. 새 프레임 폴링/파일 캐시/백그라운드 작업은 추가하지 않았다.

## 오버레이 0/0: 기존 슬롯 수정 확인 및 진단 표시 개선

1.3.4에는 SlaveTats/SlaveTats NG가 해제한 정확한 `actors/character/slavetats/blank.dds`만 빈 슬롯으로 인식하는 수정이 이미 있다. 현재 소스에도 유지되고 Face/Body/Hands/Feet, 두 카메라 뷰, 경로 대소문자·구분자를 검사한다. 실제 등록된 texture/tint/alpha 키가 남은 슬롯은 다른 모드 소유이므로 가져오지 않는다. 설치된 SlaveTats PSC의 해제 함수에서도 blank 쓰기 다음 diffuse/tint/alpha 등록 제거를 확인했다.

`0/0`만으로 위 버그의 재발을 확정할 수 없다. 대상 3D 미로드, 인터페이스 미연결, 해당 부위 설정 0/오버레이 비활성, 다른 모드가 모든 슬롯 점유한 경우를 구분해야 한다. UI는 대상 로딩·RaceMenu 미연결·슬롯 비활성·다른 모드 전체 점유를 각기 표시한다. 한·영·중 상태별 툴팁에서 대상 로딩 대기, 게임 버전에 맞는 RaceMenu/SKSE 플러그인 확인, 부위별 슬롯 활성화와 재시작, 해당 모드에서 예약 슬롯 해제를 안내한다. 가용 용량에는 이미 BCNG가 사용 중인 슬롯도 포함한다는 설명과 점유/전체 수를 표시하며 긴 문구는 화면 폭 안에서 줄바꿈한다. 인터페이스 미연결 화면에도 안내를 직접 표시한다. 실제 슬롯 증설이나 다른 모드의 오버레이 삭제는 하지 않는다.

## 커스텀 동료의 몸·손·발 보라색: 확인 누락 및 복구 결함 개발 수정

공개 1.3.6 소스는 몸 material의 실제 필수 리소스가 사라져도 같은 폼/프로필을 성공 상태로 취급할 수 있었다. 제보자 로그 없이 실제 production 함수의 반례를 실행하고, 세션 빠른 경로·같은 프로필 적용·NiNodeUpdate 이후에 현재 몸 리소스를 확인하도록 수정했다.

BCNG가 소유한 private ARMA/TXST의 diffuse/normal 리소스 및 renderer 포인터 누락, 이전 BCNG 캐시 경로만 검사한다. 정상 네이티브 갱신을 실패한 선택당 최대 두 번 재시도하고, 오래된 작업·외부 shader/TXST 혼합·다른 스킨 소유권·제거 모드는 복구 쓰기를 막는다. 부위 부재로 실패 횟수가 초기화되지 않으며 성공/셀 이탈/세션 리셋에서 복구 상태를 해제한다.

새 실제 함수 검사 100,271개와 50,000회 반복, 전체 50개 오프라인 회귀 실행 파일이 통과했다. 특정 동료가 최초로 텍스처 로딩에 실패한 제보자 환경까지 재현했다고 주장하지 않는다. 기존 asset/리플레이서 추적과 현재 변경/검증의 자세한 내용은 [보라색 동료 스킨 조사](PURPLE-FOLLOWER-SKIN-INVESTIGATION-20261008-KO.md)에 정리했다.

## 검증 범위

- 고정된 XMake 3.1.0, CommonLibSSE-NG v11.0.0 `94faaed0c60eddd8347767f2d4d29a97c93bde8c`, MSVC 14.51.36231, SE/AE exclusive flat 구성. 의존성의 버전·커밋은 변경하지 않았다. VR 없음.
- 몸 리소스 복구 변경 당시 Release 전체 빌드와 전체 50/50개 오프라인 회귀 실행 파일을 통과했다. 편집 함수 검사 60,101개, 재개방 60,000회 뒤 추적 할당 블록/바이트 증가 없음도 확인했다. 2026-10-09 상태별 오버레이 안내 개선 후에는 Release DLL을 다시 빌드하고 OverlayPolicy/CodePattern 검사 두 개를 재실행해 통과했다. 이번 문구 변경의 인게임 화면 검증은 수행하지 않았다.
- 개발 DLL SHA-256: `8F709B4662203CF0909FEE12435344DB4549BF797B2B853A3A2CEFE09017D891`. 이 DLL의 버전 리소스는 기존 1.3.6이며 공개 1.3.6 ZIP의 DLL은 교체하지 않았다.
- 실제 production begin/finish/mode-preflight 함수로 CBBE/HIMBO/UBE 각각 20,000회 재개방을 검사한다. 수정·0·삭제·음수·100% 초과·대소문자·외부 키·옷 보정·중복 열기·detach·새 세션·비유한 값·두 저장 순서·빈 프리셋 복구를 포함한다. 반복 종료 뒤 추적한 allocation 블록/바이트 증가도 검사한다.
- BodyMorph v4/v5의 독립 공개 ABI 공급자 두 가지에 실제 production 선언을 연결한다. 새 합산 조회/모프 이름 삭제 호출도 12개 지원 런타임 입장 테이블 × 두 ABI × 1,000회 반복한다.
- 전체 결과는 `build/report-fixes-test-results.json`, 빌드 기록은 `build/report-fixes-build.log`에 둔다. 숫자 비교 테스트 실행 파일 하나에 Windows 이미지 손상 오류가 발생하여 해당 타깃을 재빌드했고 재실행으로 검증했다. 이것을 게임 DLL 오류나 테스트 통과로 간주하지 않았다.

오프라인 검사는 실제 게임 렌더링, 제보자 환경 재현, 모든 RaceMenu 설치 버전의 실게임 보증을 대신하지 않는다.
