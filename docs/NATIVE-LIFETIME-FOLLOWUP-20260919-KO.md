### 확인한 계약

- ARMA/TXST/FLST의 Copy 슬롯은 두 실행 버전 모두 기본 no-op 함수였다. BCNG의 명시적 구성요소 복사를 유지해야 한다.
- AE Duplicate 경로는 폼 종류로 팩토리를 찾아 생성한 뒤 Copy를 호출한다. 호출자에게 반환된 복제물의 작업 실패를 엔진이 자동으로 아는 경로가 아니다.
- TESForm 소멸 경로는 폼 레지스트리 및 관련 관리자 정리를 수행한다. 이것이 외부 모드의 임의 raw pointer 캐시를 무효화한다는 의미는 아니다.
- ARMO/FLST의 참조 배열 정리와 ARMA의 모델 정리는 그 저장소를 해제한다. 해당 그래프의 모든 참조 대상 폼까지 일괄 소유·삭제하는 계약으로 취급하지 않는다.
- 모델 대체 텍스처 배열은 엔트리 포인터 **앞 8바이트**의 개수를 읽고, 개수 × `0x18` 엔트리를 파괴한 뒤 **앞 8바이트를 포함한 할당 시작 주소**를 해제한다. SE/AE 모두 동일했으며 고정 CommonLib의 `RE::SimpleArray` 계약과도 일치한다.

## 확인된 문제와 수정

### 1. 응답 없이 해제된 얼굴 콜백

VM이 수락 후 콜백을 버리거나 SKSE 전달 작업이 폐기되면 C++ 배치는 해제돼도 요청의 `running`이 남을 수 있었다.

공유 Delivery 객체가 실제 응답 전달 또는 포기를 한 번만 확정하도록 했다. 마지막 소유자가 응답 없이 해제할 때 기존 프레임 작업 큐로 `Finish(false)`를 전달한다. VM 스레드/소멸자에서 액터를 직접 변경하지 않는다. 부분 적용은 기존 롤백을 통하고, 이전 세션·활성 세대는 새 요청을 해제하지 않는다. 즉시 호출 거부는 포기 경로를 해제하여 중복 종료하지 않는다. 이전 노드의 읽기·제거는 지원되는 기존 네이티브 접근을 재사용한다.

VM이 콜백을 계속 소유한 채 응답하지 않는 경우에는 강제 타임아웃을 넣지 않았다. 수락된 Papyrus 쓰기를 실제로 취소하지 못한 상태에서 다음 스킨 쓰기를 시작하면 늦은 응답과 충돌하기 때문이다. 삭제 준비 역시 이를 성공으로 표시하지 않는다.

### 2. 모델 대체 텍스처 배열의 잘못된 할당·해제

기존 `SetModelAlternateTextures`는 plain `calloc<Entry>`로 헤더 없는 배열을 만들고, 엔진 Copy가 만든 배열도 엔트리 시작 주소를 `free`에 전달했다. 엔진의 배열 규약과 맞지 않는 직접적인 메모리 오류였다. 이는 UBE에만 한정되지 않는다. 해당 대체 텍스처 경로를 사용하는 모델이 대상이다.

`NativeModelArray.h`로 엔진 힙의 개수 헤더를 포함해 생성·해제한다. 실제 생성 완료한 엔트리 개수만 헤더에 기록한다. 중복 형상 대상 때문에 예상 용량이 실제 개수보다 크더라도 미생성 엔트리를 파괴하지 않는다. 새 배열 완성 전에는 기존 모델을 변경하지 않는다. 생성 중 할당 실패와 예외에서도 새 배열을 정리한다.

이 메모리 오류가 제보자의 검은 깜빡임·반보라색 스킨의 유일한 원인이었다고 확정하지 않는다. 사용자의 세이브가 손상됐다는 증거도 아니다.

### 3. 생성 실패 시 폼/텍스처 정리

- TXST는 기존 애드온 공급 경로와 동일하게 팩토리의 초기 참조 하나를 인수한다. decal 할당·채널 준비·경로 쓰기 실패 시 `DecRefCount`로 정리한다. 정상 반환 뒤에는 그래프 생성 트랜잭션으로 넘긴다.
- 모델 대체 배열을 만들기 전의 개별 TXST도 Pending 객체가 생성 참조를 보유한다. 배열 생성 실패 시 연결되지 않은 TXST가 남지 않는다.
- `BuildInstance`는 몸과 원거리 스킨을 하나의 `GraphConstruction` 범위로 만든다. 독립 저장소가 확인된 ARMO/ARMA와 새 FLST, TXST 생성 참조를 추적한다. 실패하면 참조하는 폼들을 먼저 해제하고 TXST 생성 참조를 나중에 해제한다. 몸 성공 후 원거리 실패도 같은 범위에 포함한다.
- 비정상 Copy가 원본 저장소와 공유되거나 검증을 통과하지 못한 복제물은 무작정 소멸시키지 않는다. 이 비정상 제공자/레이아웃 경로의 잔류까지 모두 회수한다고 주장하지 않는다.
- 전체 생성 성공 시 기존 장기 유지 그래프에 소유권을 넘긴다. 세션 초기화·스킨 변경에서 이 폼을 자동 파괴하는 정책은 추가하지 않았다.

### 4. 이전 그래프의 복원 근거 보존

원본이 변경돼 새 그래프로 교체할 때, 기존 private DDS 경로 복원이 하나라도 실패하면 기존 인스턴스와 경로 근거를 남겨 재시도할 수 있게 했다. 원본 제공자의 포인터는 덮어쓰지 않고, 몸/원거리 모든 복원 경로를 시도한다.

## TNG의 외부 참조와 남는 경계

보관된 TNG 공개 소스 `db688f2d408553d6125e110067ac56673a484e8e`의 `Core::GetSkinWithAddonForRg`는 원본 스킨 포인터를 키로 만든 스킨을 캐시하고, `ogSkinMap`에 생성 스킨 → 원본 포인터를 저장한다. 생성 스킨은 원본의 ARMA를 참조할 수 있다. 원본 포인터를 ActorBase에서 분리했다고 해서 TNG가 더 이상 사용하지 않는다는 뜻은 아니다.

따라서 완료된 과거 그래프의 강제 해제는 하지 않는다. 정상 팩 전환은 기존 그래프를 재사용하고 Default/세션 초기화는 private DDS를 원복한다. 실제 원본 교체가 반복되면 장기 유지 그래프는 증가할 수 있다. 이는 이번 생성 실패 정리와 구분되는 남은 수명 정책이다. 외부 모드 캐시 무효화 계약이나 안전한 재사용 검증 없이 ‘완전 회수’를 약속하지 않는다.

공개 소스와 사용자가 제공한 TNG 4.2.6 바이너리가 완전히 같은 커밋이라고 단정하지 않는다. 두부·툴레드는 SOS 환경이므로 이번 확인으로 TNG 크기 변경의 실제 렌더 결과를 검증한 것은 아니다.
