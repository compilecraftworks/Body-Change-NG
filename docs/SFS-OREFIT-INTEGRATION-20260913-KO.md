# SFS 최종 표시 의상 기반 ORefit 연결 — 2026-09-13

## 적용 규칙

- API 없음/미지원 또는 `NotManaged`: 기존 `GetWornArmor` 32·46·56 검사와
  실제 인벤토리 전체 착용 슬롯의 강제 적용 규칙을 유지한다.
- `Ready`: 반환된 표시 ARMO만 평가한다. 실제 장비는 해당 실제 장비의
  이름/FormID/플러그인, 등록 외형은 해당 등록 ARMO의 정보를 사용한다.
  등록 외형의 ID를 숨겨진 실제 장비의 ID로 치환하지 않는다.
- `Ready` 빈 배열: 강제/제외 규칙에 있는 숨겨진 장비도 후보가 아니다.
  BCNG 의상 보정 레이어를 해제하여 가슴·유두 보정을 함께 제거한다.
- `NotReady`: 이전 판단을 실제 장비로 대체하지 않고 변경 알림을 기다린다.
  잘못된 ABI/스레드/헤더도 알몸 또는 `NotManaged`로 오인하지 않는다.
- 슬롯 판정은 `declaredSlots`가 아니라 `visibleSlots`를 사용한다. 강제
  적용은 반환된 모든 슬롯의 의상에 적용한다. 전용 프리셋의 우선순위는
  기존 32 → 46 → 56을 유지한다. 같은 우선순위의 복수 등록 의상은 원형
  FormID 오름차순으로 고정한다. SFS 배열 정렬을 표시 우선순위로 해석하지 않는다.
- 알려진 동적 원형은 해당 표시 ARMO 자체의 원형이다. 원형 불명은 현재
  ARMO 이름/ID만 사용하고 소속 플러그인을 추측하지 않는다. 하나의 불명
  항목 때문에 나머지 유효한 표시 의상까지 거절하지 않는다.
- 제외 이름/FormID/플러그인, 강제 이름/FormID, 여성/남성 전용 프리셋
  매핑 모두 같은 표시 후보 집합에 적용한다. 기존 강제 적용의 제외 우선
  정책도 유지한다. 기본 `-Refit` 후보와 절차적 보정의 허용 여부 역시
  이 최종 판단을 따른다. `-Refit`은 BodySlide 프리셋 접미사이지 의상 태그가 아니다.
- 기존 UBE 보정 제한 및 유두 보정 옵션은 변경하지 않는다.

## 실행·수명

1. PostPostLoad에서 이미 로드된 SFSCore의 API v1 및 정확한 sender
   `Skyrim Fitting System`의 알림 등록을 확인한다. DataLoaded에서 재시도한다.
   LoadLibrary, 내부 함수 오프셋, SFS 상태 쓰기를 사용하지 않는다.
2. 게임 작업 밖의 평가 요청은 BCNG의 액터별 latest-wins 채널로 이동한다.
   API 질의는 FrameTasks의 SKSE 게임 작업 안에서만 실행한다.
3. 버퍼 크기 변경은 최대 세 번 다시 질의한다. 헤더/항목을 같은 질의에서
   받으며 부분 배열을 사용하지 않는다. 256개는 보관 버퍼 축소 기준이지
   허용 의상 수 제한이 아니다.
4. SFS 알림에서 모프를 직접 변경하지 않는다. epoch/revision/scene/status를
   복사해 중복 알림을 제거하고 해당 액터만 재평가한다. SceneChanged만으로
   이미 적용된 모프 signature를 무효화하지 않는다. 신규 등록 노드의 기존
   모프 반영은 SFS/RaceMenu의 기존 경로가 담당한다.
5. 보정 작업 실행 직전에 같은 epoch/revision/scene/status인지 다시 확인한다.
   대기 중 숨김/표시가 바뀌면 이전 작업은 버리고 최신 상태를 재평가한다.
   A 적용 → B 대기 → A 복귀도 기존 B 작업의 generation을 취소한다.
6. 바디 미리보기 중에는 보정 변경을 보류하며 미리보기 정리 때 재평가한다.
   분리/삭제/세이브 전환 때 액터별 메타데이터를 해제한다. 엔진 포인터,
   텍스처, 3D 노드, borrowed payload를 비동기 캐시에 보관하지 않는다.
7. SFS epoch 알림은 이전에 요청한 액터만 재등록한다. 매 프레임 전체 NPC
   검사나 반복 질의를 하지 않는다. 최초 스레드 초기화 전(epoch 0)만 최대
   8회 제한 재시도를 허용한다. 이후 준비 대기는 SFS의 알림으로 재개한다.

## 점검

`BodyChangeNGRenderedOutfitTests`는 실제 consumer cpp를 가짜 게임/작업
경계로 컴파일한다. API 부재, 상태 분기, 용량 변화, 동적 원형, 실제 장비와
등록 외형의 규칙 분리, 둘 다 숨김, 모든 슬롯 강제 적용, 슬롯 우선순위,
대기 중 버전 변경, 스레드 제한, 중복 알림 1,000회 병합, 미리보기, epoch,
분리/삭제 정리, 초기 재시도 종료를 검사한다.

Release 빌드 및 기존 테스트를 포함한 23개 실행 파일 통과. 이 검사는
인게임 검증 또는 모든 SFS/RaceMenu 조합의 실측 결과가 아니다. SFS 측에서
현재 ABI v1 및 originalFormID 의미가 동일함을 재확인했으며, `Ready`가
모든 병렬 3D 부착 완료 fence가 아니라는 점도 확인했다.

현재 두 MO2의 SFSCore는 1.6.4.0이다. 이 버전은 새 API를 제공하지 않으므로
SFS 쪽 새 DLL이 배포되기 전에는 BCNG가 기존 실제 장비 기준으로 동작한다.
이 작업에서 SFS DLL이나 MO2 설치본은 변경하지 않았다.
