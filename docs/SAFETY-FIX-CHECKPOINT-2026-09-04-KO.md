# 안전성 수정 체크포인트 — 2026-09-04

이 문서는 전체 수정 완료 보고서가 아니다. 자동 안전 검토에서 차단된 실행 구조 변경은 미적용 상태다.

위 문장은 이 체크포인트 당시의 상태다. 이후 사용자 추가 승인으로 진행한 수정·검증·한계는 [후속 안전성 작업 기록](LIFECYCLE-SAFETY-FOLLOWUP-2026-09-04-KO.md)을 참조한다.

## 기준 및 적용 범위

- 기준 커밋: `8aefeba953e990eb16a1a80ec2d7290728a6c5ad`.
- 작업 브랜치: `compilecraftworks/lifecycle-safety`.
- 기존 작업 트리는 깨끗한 상태에서 시작했다.
- xmake 3.1.0, CommonLibSSE-NG 6.7.1 및 기존 의존성 잠금을 유지했다.
- DLL 버전은 1.1.0을 유지한다. MO2 복사, 릴리즈 ZIP 재생성, GitHub 푸시는 하지 않았다.

## 적용한 수정

1. 바디 확정과 기본 바디 복원의 미리보기 취소를 해당 액터로 제한했다. 다른 NPC의 자동 확정이 UI 액터의 미리보기를 취소하지 않는다. 명시적 UI 종료의 전역 미리보기 취소는 유지한다.
2. 바디 확정 예약 시 의상 보정 완료 서명을 무효화한다. 같은 프리셋 재적용도 의상 보정 키를 지우므로 다시 보정할 수 있어야 한다.
3. 현재 바디 재적용 경로에 의상 보정 재요청을 연결했다. 기존 호출자가 중복 요청해도 의상 작업 세대 검사로 오래된 작업은 실제 모프 쓰기 전에 폐기된다.
4. 기본 의상 보정 목표 계산을 BCNG 단일 키가 아니라 의상 보정 키를 비운 뒤의 전체 모프 합성값 기준으로 맞췄다. 다른 모드의 키 자체를 삭제하지 않는다. 수학 검증은 합산 방식 기준이다.
5. 절차적 의상 보정과 의상 보정 삭제에도 독립적인 최신 작업 번호 검사를 추가했다.
6. RaceMenu Override v1 스킨 배치에 ActorHandle, 액터/VM 동일성, 세이브 세션, 작업 세대, 성별을 기록했다. 중간 조회 콜백과 최종 완료 콜백에서 다시 확인한다.
7. 중간 VM 조회 결과는 SKSE 게임 작업으로 넘긴 후 검사한다. 실제 후속 콜백을 실행하는 동안 소유권 있는 액터 참조를 유지한다.
8. VM 콜백 호출과 콜백 폐기/소멸이 중복되어도 배치 완료 카운터는 한 번만 감소하도록 공용 CompleteOnce 검사를 적용했다.

스킨 DDS 부위/채널 라우팅, 부분 팩 규칙, UBE/3BA/UNP/SOS/종족별 매핑, 틴트 적용, 카메라, UI 배치, 배포 규칙 형식은 변경하지 않았다.

## 검증

- Release DLL 빌드 성공. 전체 재빌드 시 CommonLibSSE-NG Trampoline의 기존 미사용 매개변수 경고가 있었고, 최종 수정 파일 재빌드/링크는 성공했다.
- 테스트 11종 빌드 및 실행 성공: ActorState, AsyncWorkGuard, AssetCatalog, BodyFamily, Hotkey, OutfitRefitRules, PathMigration, PresetCatalog, RaceMenuPresetMigration, RuntimeLayout, SkinOverrideOwnership.
- 신규 테스트는 다른 액터 미리보기 보호, 동일 액터/전역 취소 유지, 16개 동시 완료 시 단일 완료, 폐기된 콜백 중복 완료 방지, 외부 모프 4종 × 의상 목표 3종 계산을 검사한다.
- 파일을 사용하는 기존 테스트는 새로 만든 전용 임시 디렉터리 아래에서만 실행했다.
- `git diff --check` 통과. LF/CRLF 변환 안내만 있었다.
- 최종 DLL SHA256: `7CC928008C6D4C412E05DC6B58015DA12DA1F05DB48D677C7338B46C0A0D4702`.

인게임 CTD 재현, OverlayFix의 외부 작업 완료, 실제 프레임 시간, RaceMenu 재진입의 인게임 검증은 수행하지 않았다. 테스트 통과는 이 항목들의 성공을 보장하지 않는다.

## 차단되어 적용하지 않은 부분

자동 승인 검토가 다음 묶음 변경을 거부했다. 다른 도구나 경로로 우회 적용하지 않았다.

- 기존 입력 훅에 연결하는 실제 프레임 작업 큐, 처리 예산, 액터별 진행 중 상태, 공통 로드 장벽. 실제 프레임 경계와 기존 큐 통합 검증이 부족하여 입력/CTD/배포 회귀 위험을 사유로 거부되었다.
- 프리셋 내용 지문 및 조회 최적화, 의상 조회 최적화를 함께 적용하는 변경. 핵심 경로 동시 변경과 조기 반환의 영향 우려를 사유로 거부되었다. 제안된 조기 반환은 강제 의상 유무를 확인하는 보조 함수에만 넣으려던 것이지만, 거부 이후 해당 패치는 적용하지 않았다.

따라서 다음 문제는 남아 있다:

1. 같은 SKSE FIFO 재예약을 실제 프레임 대기로 취급하는 초기 배포/의상/RaceMenu 복원 경로.
2. 3D가 아직 없는 액터 대기의 재시작/수명 제한.
3. 모든 자동 진입점에 걸친 로드 시작 차단과 세션 취소.
4. 액터별 스킨 비동기 처리와 바디/의상 작업의 진행 중 중복 방지. 이미 VM 또는 외부 플러그인에 전달한 쓰기 작업은 이번 가드만으로 취소할 수 없다.
5. 같은 ID의 XML/DDS 내용 변경 후 완료 서명 무효화.
6. 전체 목록 복사/불필요한 인벤토리 조회 감소와 실제 적용 시간을 포함하는 성능 측정.
7. OverlayFix의 실제 버전과 실행 경로에 맞춘 호환 처리. 고정 프레임 대기나 루트 포인터 안정만으로 외부 작업 완료를 확정하면 안 된다.

다음 단계는 사용자 추가 승인 후 실행 구조를 독립 테스트로 먼저 검증하고, 작은 통합 단계마다 빌드/테스트하는 것이다. 이번 체크포인트를 전체 수정 또는 OverlayFix CTD 해결로 소개해서는 안 된다.
