# 얼굴 캐시·재생성 경로 검증 — 2026-09-10

## 결론

**얼굴을 다시 생성하는 native 경로는 확인했다. 그러나 ActorBase FTST만 바꾼 뒤
재생성하면 선택한 얼굴 Diffuse까지 바뀐다는 가설은 여전히 성립하지 않는다.**

기존의 “QueueNiNodeUpdate는 몸만 갱신하고 얼굴은 재생성하지 않는다”는 설명은
정정한다. 실제 SE 엔진 함수는 Head 플래그도 설정한다. 지금 남은 핵심은 갱신
함수가 없다는 문제가 아니라, 생성 과정의 텍스처 공급 경로와 공유 캐시 격리다.

## 이번 검증의 범위

- 사용자가 툴레드를 메인 메뉴까지 실행한 상태에서 코드만 읽었다. PID 26612.
- SE 1.5.97.0, EXE SHA-256:
  `693E5A51EA2680119A68620BCF5080E81745549872B5D06BBD3F51131B67ABAB`.
- 프로세스 권한은 `0x410` — 조회와 읽기만. 게임 함수 호출, 메모리 쓰기, 후킹,
  세이브 로드/저장, DLL 교체, 공개 릴리즈 갱신 없음.
- `tools/audit-native-face-code.py --cache-refresh`로 36개 코드 범위를 확보했다.
  그중 20 KiB NPC 영역과 작은 leaf 영역은 함수 하나가 아닌 명시적 코드 창이다.
- 산출물은 `build/audits/face-cache-refresh/`에 분리했다. 이전 캡처는 보존했다.
  게임 코드 캡처는 Git/배포/공개 소스 ZIP에 포함하지 않는다.
- 아래 모든 RVA와 Address Library ID는 **SE 1.5.97 전용**이다. AE에 재사용 금지.

## 1. QueueNiNodeUpdate → 얼굴 재생성 연결

SE 공식 SKSE 커밋 `63912619bdad6ec7762a37f09734c79def81e9f2`의
`CURRENT_RELEASE_RUNTIME`은 1.5.97이다. 해당 소스를 실행 코드와 대조했다.

1. Papyrus `Actor.QueueNiNodeUpdate()`는 native `0x693110`에 `false`를 전달한다.
   CommonLib의 같은 함수 이름은 `Actor::DoReset3D`, SE ID 39181이다.
2. 이 함수의 비지연 분기는 `0x69327E`에서 `0x17` 플래그를 준비하고,
   `0x69328A`에서 AIProcess flag setter `0x67E3B0`를 호출한다.
3. setter는 middleHigh의 `update3DModel` 바이트에 해당 비트를 OR한다.
   `0x17 = Model(0x01) | Skin(0x02) | Head(0x04) | Scale(0x10)`.
   **Face(0x08)는 없지만 Head가 있으므로 아래 얼굴 분기의 조건을 만족한다.**
4. `0x693299`는 설치 상태에서 이미 detour된 호출이다. 공식 SKSE의
   `UpdateEquipment_Enter = 0x693110 + 0x189`와 일치하며, 공개 wrapper는
   원래 `UpdateEquipment`를 실행한 다음 NiNodeUpdate 이벤트를 보낸다.
5. 그 원래 함수는 `0x650DF0`, CommonLib `AIProcess::Update3DModel_Impl`,
   SE ID 38404와 같다. `0x650F57`의 `flags & 0x0C`가 Head/Face 분기를 연다.
6. Head 비트가 있으면 `0x650FD0` → `0x361AE0`로 기존 얼굴 항목을 정리한다.
7. `0x650FFB` → `GetHeadModel(0x363DE0)`,
   `0x65100E` → 얼굴 부착 함수 `0x363F20`을 호출한다. 실제 액터 인자를 유지한다.
8. 마지막에는 update flags를 정리하는 함수 `0x67E3F0`도 호출한다.

이것은 **native 코드의 조건부 실행 경로 검증**이다. 3D/AIProcess 부재나 지연
분기도 있으므로 모든 Papyrus 요청이 즉시 이 분기를 실행했다고 의미하지 않는다.
이번에는 액터가 로드된 세이브에서 호출 횟수나 실행 완료 시점을 측정하지 않았다.
설치된 detour의 모든 런타임 동작을 동적 추적한 것도 아니다.

## 2. 기존 얼굴 때문에 생성을 생략하는 항목의 수명

이전 조사에서 `0x364FF0`에 TESNPC 키를 찾으면 얼굴 생성을 건너뛰는 분기가
있었다. 이번에는 Head reset이 그 항목을 제거하는 경로를 확인했다.

- `0x361AE0`은 같은 TESNPC 키와 같은 map(`RVA 0x1DD6320`)을 사용한다.
- `0x361B36` → `0x369730`(SE ID 24292)은 해당 항목의 얼굴 참조를 꺼낸 뒤,
  bucket 연결을 끊거나 다음 항목으로 옮기며 저장 참조를 해제한다.
- 다시 만든 얼굴은 기존에 확인한 `0x363F20`의 부착/등록 경로로 들어간다.

따라서 이 항목을 “한 번 있으면 영원히 얼굴 재생성을 막는 캐시”로 볼 수 없다.
또한 이것은 **NPC별 기존 얼굴 항목 정리**이지 모델 DB 전체 삭제가 아니다.
키가 실제 Actor reference가 아닌 TESNPC이므로 같은 베이스를 공유하는 액터의
동시 동작까지 격리된다는 결론으로 확대하지 않는다.

## 3. 생성된 얼굴의 모델 DB 저장 — 추정에서 확인으로

이전에 미확인이었던 `0xD2F440`(SE ID 74043)과 하위 함수를 읽었다.

- `0xD2F440`은 경로로 ID를 구성하고 같은 모델 DB의 엔트리 처리 함수
  `0xD312B0`(ID 74090)에 얼굴 NiPointer와 엔트리 출력 인자를 넘긴다.
- `0xD312B0`은 엔트리를 얻고, 여러 상태 분기에서 전달된 얼굴 노드의 참조를
  증가시켜 **엔트리 `data +0x28`에 그 포인터 자체를 저장**한다.
  예: `0xD3132C` → `0xD31339` → `0xD3133D`.
- 다른 상태 분기의 `0xD314E0`(ID 74092)도 같은 포인터 저장을 수행한다.
  `0xD314F4`에서 참조 증가, `0xD314F8`에서 엔트리 저장이다.
- 이 저장 단계는 입력 얼굴/재질/TextureSet을 새로 deep-copy하지 않는다.
  교체되는 기존 노드는 참조 카운트를 감소시키고 필요하면 파괴한다.

이제 **얼굴 생성 결과를 모델 캐시에 보관하는 실제 경로가 있다**고 말할 수 있다.
따라서 원래 캐시 키로 등록될 얼굴을 복제 도중 BCNG 스킨으로 바꾸면, 액터만의
임시 결과라고 가정할 수 없다. 이는 BCNG가 현재 캐시를 오염시켰다는 진단이
아니라, 앞으로 구현할 생성 단계 어댑터가 피해야 할 검증된 공유 경계다.

서로 다른 세 종류의 상태를 혼동하면 안 된다.

| 상태 | 키/소유 단위 | 이번 확인 |
|---|---|---|
| BCNG native 선택 그래프 | 현재 코드에서는 ActorBase FormID | 같은 베이스의 서로 다른 프로필은 충돌로 거절 |
| 엔진의 기존 얼굴 항목 | TESNPC | Head 갱신 경로에서 제거되고 다시 등록됨 |
| 모델 DB의 얼굴 모델 | 경로에서 얻은 리소스 ID | 생성 얼굴 포인터를 참조 유지하며 보관 |

두 번째 상태를 무효화해도 세 번째 원본 모델 캐시가 액터별로 바뀌는 것은 아니다.

## 4. 원래 요구한 방식에 대한 판정

검증된 것:

- 플레이어/NPC의 실제 액터 인자를 유지하는 얼굴 재생성 경로가 있다.
- 현재 사용 중인 QueueNiNodeUpdate의 native 경로에도 Head 갱신이 들어 있다.
- 기존 얼굴 항목 생략 분기를 풀고 재생성하는 native 절차가 있다.
- 캐시 모델·재질·TextureSet은 단순 복제만으로 독립 소유가 보장되지 않는다.

아직 입증하지 못한 것:

- 재생성 과정에서 BCNG 선택 FTST가 Face Diffuse의 초기 입력으로 사용되는 연결.
  기존 생성 분기는 HeadPart TXST, 사전제작 분기는 FaceGen 모델을 사용한다.
- 원본 NIF/HeadPart/모델 DB를 수정하지 않으며, 사후 live DDS 교체 없이 양쪽
  생성 분기와 캐시 재사용을 모두 처리하는 완성된 액터별 텍스처 공급 어댑터.
- 실제 A→B→기본값, 두 액터 격리, 저장/로드 및 SE/AE 전체 런타임 동작.

그러므로 **갱신 함수를 또 추가하거나 Face 플래그만 더 켜는 것을 얼굴 스킨
해결책으로 채택할 근거는 없다.** 기존 경로에 이미 Head 재생성 요청이 있다.
단순 FTST 교체 가설과 향후 생성 입력을 바꾸는 엔진 확장은 구별해야 한다.
이 검증만으로 후자의 안전한 구현이 완성됐다고 보고하지 않는다.

## 검증 산출물과 변경 범위

- 이번 추가 direct CALL 10개를 원시 opcode/상대 목적지로 재검산, 모두 일치.
- 플래그 mask/OR, Head 분기, 얼굴 map 제거, DB 노드 포인터 저장을 디스어셈블리와
  분리된 바이트 검사로 대조했다.
- 조사 도구 문법 검사와 문서/도구 whitespace 검사 통과.
- 예외 테이블에 없는 ID 74092를 일반 함수로 요청했을 때 검사가 중단됐다.
  해당 직접 호출 대상만 명시적인 128바이트 코드 창으로 읽었으며, 그 안에 있는
  다음 함수들의 바이트를 ID 74092의 본문으로 해석하지 않았다.
- 플러그인 소스/DLL/모드 설치/세이브 변경 없음. 게임 기능을 바꾼 작업이 아니므로
  Release 빌드/기능 회귀 테스트는 실행하지 않았다.
