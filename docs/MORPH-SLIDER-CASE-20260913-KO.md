# 1.2.1 슬라이더 대소문자 점검 — 2026-09-13

## 범위와 결론

제보의 인게임 테스트 버전은 **1.2.0**이다. 현재 1.2.1의 OBody/OClothe 키 정리,
모프 보존 옵션, NPC 배포 성별·대상 선택, 커스텀 팔로워·노인 제외, 후타 즐겨찾기를
유지한 채 대소문자 충돌만 점검했다. 비교 기준 커밋은
`f4b4b5bb0f2d1de52547c6065b226fbd42d9c71e`이다.

1.2.1에는 예전 `CollectCompatibleSliderNames`/전체 프리셋 0 값 합집합과
확정 시 전체 모프 합계를 상쇄하는 코드가 이미 없다. 이 코드를 되살리거나
1.2.0의 제보 경로가 그대로 남았다고 판정하지 않았다.

현재 코드에도 별도로 남은 문제는 다음과 같다.

- XML의 `Breasts` small과 `breasts` big을 두 슬라이더로 나눠 읽었다.
- 저장된 이름과 선택 XML의 이름이 다르면 미리보기의 기존 값 차감·0 값 병합이
  서로 다른 키로 계산될 수 있었다. 실제 모프 이름은 하나이므로 마지막 쓰기에
  따라 값이 상쇄되거나 기존 값 위에 과하게 더해질 수 있다.
- XML의 소문자 이름과 기본 의상 보정의 표준 이름도 별개로 합성되었다.
- UNP 역방향 기본 슬라이더의 인식이 영문 대소문자에 좌우되었다.

외부 근거: RaceMenu의 [고정 커밋 StringTable.h](https://github.com/expired6978/SKSE64Plugins/blob/9ebcb733e17be695f994cd2e9cc383043446bc02/skee64/StringTable.h)는
`SKEEFixedString` 이름을 소문자 해시와 `_stricmp` 비교로 다룬다.

## 변경

- `SliderName.h`: ASCII 대소문자를 무시하는 동일성/해시와 모프 값 맵.
  문자열 자체는 소문자로 다시 쓰지 않고 첫 표기를 유지한다. 비ASCII 바이트는
  변경하지 않는다. 프리셋 ID나 모프 소유 키의 비교 정책은 바꾸지 않는다.
- `PresetCatalog.cpp`: small/big을 같은 슬라이더로 병합한다. 같은 끝값이
  반복되면 기존 정책처럼 XML에서 마지막 값이 우선한다. UNP 인식도 동일한 비교를 쓴다.
- `RaceMenuBodyMorph.cpp`와 `BodyMorphKeys.h`: 선택 값·미리보기 기준 값·의상 보정
  값의 맵을 같은 정책으로 통일한다.
- XML 파일 수정, 수치 제한, 세이브 형식 변경, 추가 전체 모프 초기화, 전체 프리셋
  합집합 생성, 새 주기 검사나 스레드는 없다.

## 검증과 배포

수정 전 코드에서 새 XML 병합 테스트와 대소문자 미리보기 테스트의 실패를 각각
확인한 다음 수정했다. 수정 후 Release DLL 빌드와 자동 테스트 실행 파일 24종이
모두 통과했다. 모프 키 테스트는 4,509개 조건을 확인한다.

포함: Breasts/breasts, Waist/waist, HipBone/Hipbone, XML 양 끝값 순서 반전,
다른 프리셋의 0 값 격리, +120/-150, UNP 반전/비반전, 지정 의상 보정,
가슴·유두 기본 보정, 보존 ON/OFF, 각 방향의 128회 반복 미리보기·취소,
OBody/OClothe 제거와 다른 키 보존. 회귀 테스트는 실제 게임의 렌더나 장시간 누수를
검증하는 것은 아니다. 인게임 재확인은 아직 필요하다.

MO2의 TuLED·TAKEALOOK 양쪽에 반영했고 설치 DLL 해시를 확인했다.
설정·규칙 JSON은 복사 전후 해시가 동일하고 팩과 세이브는 건드리지 않았다.
교체 전 파일은 `build/mo2-backup-v1.2.1-slider-case-20260913`에 보관했다.
