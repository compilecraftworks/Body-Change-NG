# v1.3.3 배포 JSON 작성 기능 검증

검증일: 2026-09-24. 패키지 게시나 인게임 검증을 뜻하지 않습니다.

## 변경 범위

- 배포 JSON 읽기에만 고정된 nlohmann/json의 주석 지원 옵션을 사용합니다. 정규식으로 주석을 지우지 않습니다.
- 기존 schema 7, 규칙 판정·순서·호환 조건, 원자적 파일 교체, SE/AE 런타임과 RaceMenu 계약, 의존성은 유지합니다.
- 기본 파일에는 활성 규칙이 없으며 예제 19개는 모두 주석입니다. 필드 19개와 scope 0~10 전체를 한영으로 설명합니다.
- 주석은 1.3.3 이상 DLL에서만 읽습니다. 인게임 저장은 실제 규칙을 맨 위에 쓰고 기존 주석 토큰을 아래에 보존합니다. 문자열 안의 기호를 주석으로 오인하거나 예시를 활성화하지 않습니다. 필드 옆 주석도 아래로 이동합니다. `settings.json` 등 다른 입력에는 주석 지원을 추가하지 않았습니다.

## 완료한 검사

- Release DLL 빌드 성공, 파일 버전 `1.3.3.0` 확인. SE/AE 전용 설정과 기존 도구·의존성 고정 유지.
- 기존 회귀 실행 파일 35개를 현재 버전 경로에 빌드하고 실행하여 전부 통과. 입력, 카탈로그, 바디/UBE, 스킨/후타, 오버레이, 미리보기 복원, 배포 수명, 저장·초기화, 비동기 큐와 실패 경로를 포함합니다.
- 실제 배포 읽기 함수를 이용해 일반 JSON, 줄/블록 주석, UTF-8 BOM, 파일 끝 주석, 문자열 안의 주석 기호·이스케이프를 검사했습니다. 잘못된 끝 쉼표, 닫히지 않은 주석, 두 번째 루트 객체와 JSON에 없는 16진 숫자 표기는 거부합니다.
- 템플릿의 예제 19개가 파싱되고 모든 scope를 포함하는지, 저장 필드 19개의 주석 설명이 있는지, 예제의 필드명·형식·ID가 유효한지 검사했습니다. 첫 예제 객체를 맨 위 rules에 복사하면 정확히 해당 규칙 하나만 활성화됩니다.
- 기본 종족/뱀파이어 종족·팩션·키워드·클래스·전투스타일 39개의 EditorID/종류/로컬 숫자를 두부와 Steam의 Skyrim.esm에 읽기 전용으로 대조했습니다. `tools/verify-distribution-reference.py`로 재검증할 수 있습니다. 이는 해당 NPC의 최종 모드 덮어쓰기까지 같다는 뜻은 아닙니다.
- 바디 후보 3개, 스킨 후보 2개, 후타 후보 3개, 몸 오버레이 후보 2개와 개별 색상이 예제에서 유지되는지 검사했습니다. 여러 후보는 동시 적용이나 기능 간 짝짓기가 아니라 각 기능의 후보 풀임을 안내합니다.
- 별도 완성 파일 예제에서 노드 여성 대상의 독립된 바디·스킨 규칙 2개와 각 후보 2개를 검사했습니다. 기존 파일 밑에서 주석만 풀면 안 되며 새 편집본 또는 기존 rules에 복사하도록 안내합니다.
- 실제 저장 함수의 88개 scope/성별/기능 조합에서 플러그인+로컬 ID, 후보와 오버레이 색상을 보존했습니다. 대상 읽기·교체 잠금, 임시 파일 생성 실패, 닫히지 않은 주석은 원본을 유지한 채 저장에 실패합니다. 성공 시 실제 데이터가 위에, 기존 주석 토큰이 아래에 남습니다.
- 전체 주석 가이드·19개 예시 보존, 25회 반복 저장 시 파일 바이트 동일, 추가 사용자 메모 보존, 활성 규칙 전체 삭제 후 주석 유지, 주석 없는 파일 호환을 검사했습니다. 새 가이드를 자동 주입하거나 이미 삭제된 주석을 복구하지 않습니다.
- 오프라인 ID 도구에서 XML 상대경로·이름·엔티티·중복·Refit 제외, 읽기 전용 동작, 경로 경계, DTD·잘못된 XML 거부, 오버레이 해시·경로 정규화·부위 차이를 검사했습니다.
- 한글 소개글·현재 체인지로그의 밝은/어두운 CSS 팔레트에서 글자·배경 68개 조합이 4.5:1 이상의 대비를 갖는지 `tests/DocumentationThemeTests.ps1`로 확인했습니다. 본문은 고정 흰색 대신 브라우저의 `CanvasText`를 사용합니다. 브라우저 확장 기능의 강제 색상 변환까지 검증한 것은 아닙니다.
- 패키지에 들어갈 파일 11개의 허용 목록과 PDB 제외를 대조했습니다. 기본 파일이 활성 규칙 0개로 읽히며 `release/BodyChangeNGdistribution.json`과 패키지 템플릿의 SHA-256이 같습니다. ZIP 생성 시 `scripts/Package-Release.ps1`이 파일별 SHA-256과 소스 리비전을 검증합니다.

## 설명과 코드 대조

- 개별 NPC는 RefID가 아닌 원본 플러그인+로컬 BaseID입니다. 플러그인 조건은 리텍 덮어쓰기 파일이 아니라 원본을 뜻합니다.
- 전체 NPC의 팔로워·노인 포함 옵션은 다른 scope에 숨은 제외 조건으로 적용되지 않습니다. 팔로워·노인 판정 기준도 주석에 설명했습니다.
- 하나의 규칙은 성별과 scope 하나를 사용합니다. 임의의 여러 조건 AND 조합은 지원하지 않습니다.
- 후보 하나는 고정 지정, 여럿은 호환 후보 선택입니다. 다른 로드 순서에서도 대상 식별은 유지되지만 복수 후보 선택 결과까지 같다고 보장하지 않습니다.
- 수동 선택 우선순위, 기능별 첫 호환 규칙, 자동 배포의 기존 UBE 제한, 부위당 오버레이 하나, 저장된 선택과 규칙 삭제의 차이를 명시했습니다.
- `enabled: false`가 현재 비활성화 수단이 아니라는 점을 명시했습니다. 규칙을 주석 처리하거나 별도 파일로 옮겨 제외할 때 쉼표도 조정하도록 안내합니다.

## 검증 한계

실제 게임은 실행하지 않았고 설치된 모드·JSON·세이브를 변경하지 않았습니다. 전체 엔진 누수나 모든 모드팩의 적용을 보장하는 검사는 아닙니다. 주석 처리는 파일 로드·저장 시점에만 수행되며 게임 중 반복 검사나 영구 캐시를 추가하지 않습니다.

ID 도구는 현재 PowerShell에서 검사했습니다. Windows PowerShell 5.1 직접 실행은 PC 실행 정책에 의해 차단되어 완료하지 못했으며 정책을 변경하거나 우회하지 않았습니다. 도구 없이 JSON을 수동 작성하는 방법도 제공합니다.
